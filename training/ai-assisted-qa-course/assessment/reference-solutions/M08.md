# M08 模範成果物と判断根拠

> publicなqa-training-storeに置く通常Markdownです。学習用配布からの除外は秘密保持ではありません。文面一致ではなく意味・出典・判断・証拠を評価します。

## 成果物の標準例

Working treeは作業中の変更、stageは次commitへ入れる選択、commitはローカル履歴、branchは変更系列である。statusとunstaged/staged diffを分け、対象外・Secret・生成物を除いて必要なpathだけstageする。PRでは仕様・コード・テスト・対象SHA・実行結果・未確認事項を対応付ける。AIレビューの各指摘は仕様・diff・再現手順と照合し、好みだけの指摘や不要な抽象化は採用しない。.gitignoreは未追跡ファイル候補を除外するが、追跡済みファイルを自動untrackしない。

## 一時Gitリポジトリでの校正例

distribution contractは専用の一時Gitリポジトリで、M08の提出対象を`workspace/M08/review-candidate.md`と`workspace/M08/submission.md`に限定して選ぶ。`git status --short --ignored --untracked-files=all`では、これら2ファイルと`out-of-scope.txt`を未追跡として確認し、`workspace/M08/local-only-run.log`はignore済みとして別に表示する。2つの提出対象だけをstageすると、`git diff --cached --name-only`はその2 pathに一致し、`git diff --cached --check`は成功する。さらに`out-of-scope.txt`をstageへ混ぜたケースは対象path一覧が許可した2 pathと不一致になるため、commit前に停止する。これは合成fixtureの契約テストであり、実際の学習者repositoryのcommitや受講者の操作を検証したものではない。

## 評価時に確認する観点

1. working tree/stage/commit/branchを区別する
2. 必要な変更だけstageしSecretと生成物を除く
3. 仕様・コード・テスト・SHAの対応をレビューする
4. AI指摘を根拠と影響で採否する

## P01〜P06：Git差分とレビュー判断の参照例

採点は学習者本人のGit差分、stage、commitと実行済みRunに基づきます。ここに記載する判断を読んだだけではGit操作を完了したことになりません。

### P01：2つの変更を区別する

`workspace/M08/review-candidate.md`に未確認Case・Runの記載を追記し、別の`workspace/M08/private-note.md`には架空の無害なマーカーだけを保存します。`git status --short --untracked-files=all`と`git diff`で対象の変更・未追跡ファイルを区別します。未追跡ファイルの本文は通常の`git diff`だけでは確認できない点にも注意します。実Secretは投入しません。

### P02：必要なpathだけstageする

`git add -- workspace/M08/review-candidate.md`後に`git diff --cached --name-only`でstageしたパスを確認します。`git diff --cached --check`の成功は差分の空白等の問題を検査した結果であり、Secretや仕様の正しさを保証するものではありません。`private-note.md`がstage・commitに含まれないことを、実際のstage一覧で確認します。

### P03：対象外ファイルをstageしたら停止する

架空の事例で`workspace/M08/private-note.md`がstage済み一覧に混入していた場合、commitを止めて追加されたpathと差分を確認します。必要なpathのみstageから戻し、他者の追跡済み変更や作業内容を無断で削除しません。復旧後のstage一覧と取り扱い判断を示します。実Secret・個人情報を使って危険な検証はしません。

### P04：2回目のcommitの範囲を検証する

想定したファイルだけstageされた後に2回目のcommitを作り、`git log -2 --oneline`と`git show --stat HEAD`で直前のcommitと対象SHAを確認します。`git status --short --untracked-files=all`にprivate-note等が残っていればworking treeをcleanと報告しません。commit済み差分と未追跡ファイルを混同しないことを評価します。

### P05：AIレビューの採否

提案A「Run未実行でもCI成功と書く」は実行証拠の捏造になるため棄却します。提案B「仕様IDと実際のRun IDを説明に対応付ける」は、対象Runの存在とSHA・実行状態を確認できる場合に採用します。提案Cの「重複がない1箇所にFactoryと3ファイル分割を追加」は現在の根拠では棄却します。一方、同じ処理の複数箇所での重複と実際の変更負荷が確認できれば、その根拠に基づいて抽象化を再検討できます。いずれも本人の差分・テスト結果を見ずにPASSとしません。

### P06：単独commitとPR差分を区別する

2回目のcommit**単独**をレビューするときは、対象commitの親との差分、仕様/Case、変更ファイル、対象spec、SHA、実行・未実行を対応付けます。GitHub PRの差分は通常`base→head`の比較であり、1回目のcommitも含み得ます。単独commitの草稿をPR全差分だと説明せず、M09へ引き継ぐ成果物、依存、未検証事項を明記します。
