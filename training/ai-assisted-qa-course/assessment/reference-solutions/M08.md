# M08 模範成果物と判断根拠

> publicなqa-training-storeに置く通常Markdownです。学習用配布からの除外は秘密保持ではありません。文面一致ではなく意味・出典・判断・証拠を評価します。

## 成果物の標準例

Working treeは作業中の変更、stageは次commitへ入れる選択、commitはローカル履歴、branchは変更系列である。statusとunstaged/staged diffを分け、対象外・Secret・生成物を除いて必要なpathだけstageする。PRでは仕様・コード・テスト・対象SHA・実行結果・未確認事項を対応付ける。AIレビューの各指摘は仕様・diff・再現手順と照合し、好みだけの指摘や不要な抽象化は採用しない。.gitignoreは未追跡ファイル候補を除外するが、追跡済みファイルを自動untrackしない。

## 一時Gitリポジトリでの校正例

distribution contractは専用の一時Gitリポジトリで、M08の提出対象を`workspace/M08/review-candidate.md`と`workspace/M08/submission.md`に限定して選ぶ。`git status --short --ignored --untracked-files=all`では、これら2ファイルと`out-of-scope.txt`を未追跡として確認し、`workspace/M08/local-only-run.log`はignore済みとして別に表示する。2つの提出対象だけをstageすると、`git diff --cached --name-only`はその2 pathに一致し、`git diff --cached --check`は成功する。さらに`out-of-scope.txt`をstageへ混ぜたケースは対象path一覧が許可した2 pathと不一致になるため、commit前に停止する。これは合成fixtureの契約テストであり、実際の学習者repositoryのcommitや受講者の操作を検証したものではない。

## 評価時に確認する観点

1. working tree/stage/commit/branchを区別する
2. 必要な変更だけstageしSecretと生成物を除く
3. 仕様・コード・テスト・SHAの対応をレビューする
4. AI指摘を根拠と影響で採否する
