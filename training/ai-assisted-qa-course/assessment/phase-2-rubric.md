# Phase 2 公開評価基準（M05〜M07）

この基準は能力と開発用実行証拠を分けて記録します。テストが一度成功したことだけでは、本人が原因や期待結果を理解したと判断しません。

## 到達水準

| 判定 | 公開定義 |
|---|---|
| 0：対象判断を示せない | 回答や関連証拠を評価できるが、必須の判断を示せない。未実行は`not_run`、入力不足は`ungradable`、環境障害は`blocked`としてLevelと分ける。 |
| 1：支援あり | 手順を支援されると進められるが、説明・独立性・根拠が不足。 |
| 2：独立して説明 | 条件の異なる課題でコード、仕様、実行結果を本人が結び付ける。 |
| BLOCKED | Browser、Reset、権限などが使えず、習熟判定できない。 |

## 目標別の公開証拠

| 目標 | 確認する証拠 | 到達しない例 |
|---|---|---|
| M05-01 | Node.js→pnpm→TypeScript→Playwrightのコードを説明し一箇所修正する | コードを読まず完成例を実行する |
| M05-02 | Locator/Action/Assertionを役割ごとに説明する | 操作と確認を混同する |
| M05-03 | 表示と業務期待を分け、不変条件を確認する | 画面が見えたことだけを成功条件にする |
| M05-04 | 型・構文・実行・Assertion・待機の失敗を分類する | 固定Timeoutで症状を隠す |
| M05-05 | testDir、8082、通常8081、6080、出力先を設定から確認する | 異なる環境のPortを取り違える |
| M06-01 | 固定3 Caseを仕様・specへ結び、別Caseから新規specを構成してReset・操作・業務Assertionと単独実行・再実行を示す。本人のPhase 1 Caseがあれば条件・期待結果の対応と差を示す | 固定3 Caseの補完だけで新規構成を認定する、入力元が不明、fallbackだけでPhase 1能力を認定する |
| M06-02 | Reset/Context後の独立実行を複数回示す | 前のテストの状態に依存する |

| M06-05 | PASS/FAIL/未実行/環境障害を区別する | timeoutを成功やテスト不良と即断する |

| M07-02 | Trace/Screenshot/log/Runの由来と限界 | 別Runの証拠を混ぜる |

| M07-05 | 重複する操作をPage Objectへ、testごとのResetを標準fixtureへ移し、変更前後の別Runと維持したAssertionを示す。不要な例では不採用理由を示す | 採否の説明だけで実装・別Runを省く、将来拡張だけを理由に一律抽象化する |

## Phase 2修了の読み方

M06の実行証拠は専用のPlaywright経路で採取し、意味上のCase妥当性は別に評価します。本人のPhase 1成果物があれば固定3 Caseとの対応を確認します。本人成果物がない場合も公開fallbackでM06を独立評価できますが、fallbackの成功でM03/M04またはPhase 1を修了扱いにしません。M07のbefore/afterは別Runとして残します。M07で`course:assess`を起動するとM05〜M07の全15目標を、校正済みOpenCode AI候補とNode.jsの決定論的検証で評価します。実受講者による学習効果の試行は実装完了後の別工程です。
