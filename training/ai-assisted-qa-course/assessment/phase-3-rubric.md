# Phase 3 公開評価基準（M08〜M10、選択制）

Phase 3は受講者の選択制ですが、カリキュラムの教材・課題・評価基準の実装範囲からは除外しません。ここでは公開可能な証拠の形式を定義します。模範・採点用テスト・完成状態データはpublicな`qa-training-store`の`assessment/`配下に別ファイルで保存し、このルーブリック本文や学習者配布物には含めません。配布除外は秘密保持ではありません。Secretは評価資料に含めません。

## 到達水準

| 判定 | 公開定義 |
|---|---|
| 0：対象判断を示せない | 回答や証拠を評価できるが、必須の判断を示せない。証拠不足は`ungradable`、未実行は`not_run`、環境障害は`blocked`として区別する。 |
| 1：支援あり | 手順に沿えるが、変更範囲・権限・SHAの説明ができない。 |
| 2：独立して説明 | 条件の異なるPR/Runで、安全な差分、最小権限、実行結果、未確認事項を説明できる。 |
| BLOCKED | GitHub、組織Runner、権限などの未指定条件で実行できず、能力判定できない。 |

## 目標別の公開証拠

| 目標 | 確認する証拠 | 到達しない例 |
|---|---|---|
| M08-01 | working tree・stage・commit・branchの状態を説明する | ローカル差分とremote履歴を混同する |
| M08-02 | diffと`.gitignore`を確認し、`git check-ignore`でローカルログの規則を説明して、必要な対象だけをstage/commitする | Secretや生成物を確認せず含める、または`.gitignore`が追跡済みファイルを外すと思い込む |
| M08-03 | PRで仕様・コード・テストの対応を追う | 根拠なしの承認をする |
| M08-04 | AIレビューの誤り・過剰設計をdiffと根拠で判断する | AIの指摘を無条件採用する |
| M09-01 | workflow/trigger/job/runner/step/build/testを説明する | YAMLを読まず起動成功だけを見る |
| M09-02 | Run/Check/Artifactをhead SHAへ結ぶ | 別SHAの古いArtifactを使う |
| M09-03 | 失敗stepに対応するlogを選ぶ | 全失敗をテスト不良と断定する |
| M09-04 | 非公開repoの利用枠、trigger、対象とRun数を確認し、費用と未検証期間からゲートを選ぶ | 料金や無料枠を推測する |
| M09-05 | permissions、Secret、他CIの分離を判断し、制約変更時に見直す | 不要なwrite権限やSecretを加える |
| M10-01 | Phase 2成果物とPR範囲を確認する | 変更対象が特定できない |
| M10-02 | 費用・権限を確認し、専用workflowを手動有効化して対象specの実Runと条件変更への判断を示す | 未実行の案だけで達成とする、全suite/権限/Stepが無根拠に広い |
| M10-03 | 完全SHA、Run、Check、Artifactを同一実行で示す | SHAが一致しない成功報告を使う |
| M10-04 | CI環境・テスト・製品の仮説を調査し、変更条件で停止・再実行・不要trigger停止を判断する | timeout延長だけで完了扱いにする |
| M10-05 | AI提案の採否、確認範囲、未確認事項を報告する | 未実施や失敗を伏せてPASSとする |

## Phase 3修了の読み方

実装完了にはPhase 3の公開教材、課題、無効化workflow見本、評価基準、自動契約検証を含みます。M10の`course:assess`はM08〜M10の全14目標について、実PR HEAD、Run/Check/Artifact、証拠と版を決定論的に確認したうえで、別セッションの校正済みOpenCode AI候補をNode.jsが集計します。評価担当者による採点は要求しません。実受講者の学習効果試行と運用開始判断は別工程です。
