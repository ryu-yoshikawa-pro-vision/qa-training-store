# 講師向け資料

> **運営支援のみの契約（PR 4A）:** 本資料はリポジトリの運用上必要な運営・講師向けの支援資料です。受講者向けの学習内容、セルフチェック、リカバリー手順、修了要件、評価基準、模範解答の正本として扱うものではありません。

本資料は、公開リポジトリにおける運営および講師向けの参考資料です。機密情報、本番環境のシークレット、トークン、非公開テスト、受講者ごとの個別判定結果などを記載してはなりません。また、受講者向けの標準ナビゲーションに修了へのエントリポイントとして追加せず、環境構築やトラブル時の支援が必要な場合にのみ参照します。

## 公開資料（Public Reference）

受講者が公開されている正式な仕様書や最新のADR、現行ワークフロー、演習用バリデータ（Training validator）へ適切にたどり着けるよう支援します。学習内容や自己評価は、受講者向けの各必須レッスンおよび[習熟度評価基準](02_competency-rubric.md)を参照するものとし、本資料に解答や回答例を追記することはありません。

## 想定する契約（Expected Contract）

- 期待される製品仕様・動作の正本は、[`docs/spec/README.md`](../../spec/README.md)および正式な機能仕様書です。
- `docs/spec/features/*.md`、現行のADR、実行可能なソースコードそれぞれの役割を混同せず、変更されうる設定値や実装内容を本資料へ二重管理（複製）しないようにします。
- Web演習環境（Training Web）のエントリポイントは `playwright.training.config.ts` 内の `training-chromium` / `training-mobile-chromium` であり、ネイティブ演習（Training Native）の起点は `training/maestro/baseline/` です。環境支援にあたっては、現行リポジトリに含まれるスクリプトやワークフローを最優先で利用します。
- 本番用のWebテスト（`e2e/web/`）やネイティブテスト（`maestro/`）に受講者用のテストを混入させず、演習用（Training）の変更範囲とは明確に分離します。
- 現時点での動作保証範囲は「AndroidはビルドおよびランタイムE2Eテストまで」「iOSはビルド確認のみ（Build-only）」であることを運用上の前提とします。iOSシミュレータやMaestroでのランタイム実行結果が未確認であるにもかかわらず、テスト成功と記録してはなりません。
- 演習用の配布リポジトリ（Training Copy）では、実行対象ワークフローを `training-ci.yml` と `training-native-ci.yml` の2件のみに絞り、`permissions: contents: read` であること、シークレットが不要であること、デプロイ処理を含まないことといったセキュリティ境界を確実に確認します。

## 代替案（Alternative Design）

受講者の開発環境や教材の配布方法の違いをサポートする場合、以下の代替手段を許容します。ただし、受講者の修了判定基準を公式の正本以外に移してはなりません。

- GitHubのFork、または運営側が用意したGit管理下の演習用リポジトリ（Training Copy）のいずれかを利用する。どちらの場合も、本番用ワークフローと演習用ワークフローを確実に分離します。
- Windowsローカル環境のAndroid実機、またはGitHub-hostedランナー上のAndroidエミュレータを、所定のランブックおよびワークフローに沿って利用する。これら以外の非公式なネイティブ実行基盤を独自に追加しないようにします。
- Web環境におけるブラウザ種類、ベースURL（Base URL）、`dist` 配布方式、Node.jsやpnpmのバージョン差については、既存スクリプトの活用と環境確認の手順によって吸収します。
- iOSについてはビルド成果物の生成確認（Build-only）の支援にとどめ、ランタイム動作まで別途保証したものとして扱わないようにします。

## 避けるべき例（Anti-pattern）

- 演習のサポート環境に本番用シークレット、OIDC設定、書き込み権限付きトークン、本番環境設定、デプロイ処理を持ち込むこと。
- `e2e/web/` や `maestro/`、正式なワークフローへ、演習用の受講者テストや教材向けの変更を混入させること。
- `training/maestro/**` 配下の変更によって、ネイティブCIが意図せずスキップされてしまう状態を放置すること。
- 意図的な失敗演習（Intentional Failure）を通常のベースラインに混入させたり、失敗時のログや記録を削除・隠蔽したりすること。
- 現行のワークフローや仕様書、ADRに定義されている値を本資料独自の内容で上書きし、第3のSSOT（信頼できる唯一の情報源）を作り出してしまうこと。
- iOSの実機・シミュレータ検証が未実施であるにもかかわらず、「iOS Runtime PASS（実行成功）」と記録すること。
- 本資料から受講者に対して、完成版コードや非公開の模範解答、個別の修了判定結果を直接提供すること。

## 運営支援の手引き

### 環境・ツールチェーン

- Webのベースラインが起動しない場合は、`PLAYWRIGHT_BASE_URL` の設定、`dist` のビルド状態、ポート番号、ブラウザのインストール状況、Node.jsやpnpmのバージョンを確認します。
- ネイティブのツールチェーンが正常に動作しない場合は、既存の診断コマンド（Doctor）、Android SDK、JDK、Gradle、生成されたAPK、Maestroのバージョン、および対象ワークフローのログを確認します。
- Android実機を使用する場合は、USBデバッグ（`USB debugging`）の有効化、`adb devices -l` による認識、`RequirePhysicalDevice` や `-DeviceSerial` の指定、端末のロック解除状態（`unlocked`）、アプリの起動準備（Ready状態）を確認します。具体的な設定値や最新手順については、現行のランブックを参照してください。
- iOS環境については、macOS、Xcode、CocoaPodsの導入状況、ビルド時メタデータ、本番環境混入防止ガード（Production guard）、および `.app` 成果物の有無を確認します。シミュレータへのインストール、起動、Maestro実行が未保証であるという現在の境界は変更しません。

### Training Copyの準備

演習用の配布リポジトリ（Training Copy）を運営側で準備する場合は、既存の以下のスクリプトと検証境界に従って作業します。

```bash
pnpm run training:copy:prepare -- --source-sha <full-sha> --target <disposable-folder>
pnpm run training:copy:validate -- --root <disposable-folder>
```

実行対象ワークフローの許可リスト（allowlist）、起点となるコミットハッシュ（Source SHA）、本番用ワークフローからの分離、`permissions: contents: read` の権限設定、シークレットやデプロイ処理が含まれていないことを支援担当者側で確認します。受講者に対して、環境プロビジョニングや許可リストの独自作成を修了要件として課さないようにしてください。

### アカウント・権限

- GitHub Actionsが有効化されているか、対象のForkリポジトリまたは演習用コピーへプッシュできる権限があるか、プルリクエストのベースブランチが意図したブランチに向いているかを確認します。
- もしシークレットの登録が必要になった場合は、演習用ワークフローに安易に追加するのではなく、本番用ワークフローとの分離方針や演習環境自体の設計に立ち戻って見直します。
- 本体リポジトリへの直接プッシュ権限、第三者によるレビュー、外部サービスの有料利用枠（Quota）などを、受講者が満たすべき前提条件として暗黙に要求しないようにします。

### インフラ・成果物

- テスト失敗時には、根本原因となる最初の異常、それによって引き起こされた二次的な派生エラー、そしてログ、スクリーンショット、トレースファイル、JUnitレポートなどの記録をそれぞれ区別して保存・確認します。
- 演習用の意図的な失敗（Expected Failure）が誤ってベースラインに混入していないか、成果物（アーティファクト）のアップロード／ダウンロードが正常に行われたか、ワークフローのジョブ結果が予期せずスキップ（Skip）されていないかを確認します。
- 演習用のMaestroベースラインは環境が正しく整っているかを確かめるための出発点にすぎず、受講者自身が作成すべき成果物や、カリキュラムC08／ネイティブCIの修了要件を満たした証跡の代わりにはなりません。

## トラブルシューティングの確認項目

| 症状 | 支援時に最初に確認すること | 支援分類 |
| --- | --- | --- |
| Webベースラインが起動しない | `PLAYWRIGHT_BASE_URL`、`dist`、ポート番号、ブラウザのインストール状況 | 環境 / ツールチェーン |
| リセット後に別のデータが残る | 現在のシナリオ／テストコントロール（Test Control）のSSOT、localStorage / IndexedDBの状態 | テストデータ / シード支援 |
| ロケーター（Locator）が見つからない | アプリの表示状態、安定したテスト用ID（Stable Test ID）、待機対象の要素、ブラウザログ | UI / 同期支援 |
| 想定される失敗（Expected Failure）がパスしてしまう | 失敗演習用テストとベースラインの配置場所、ワークフローの実行対象 | テスト実行支援 |
| GitHub Native CIのAVDが起動しない | API 34イメージ、ABI、KVM、シリアル番号、有限のタイムアウト設定 | 環境 / ツールチェーン |
| Maestroが起動しない | APKのビルド種別（Build kind）、テストコントロールの待受状態（listening）、Maestroのバージョン | ハーネス / ツールチェーン |
| 演習用コピー（Training Copy）にワークフローが多すぎる | `training:copy:prepare` の実行状況と有効な許可リスト（active allowlist） | 信頼境界 |
| iOSのテストを実行できない | 現在の保証範囲がビルド確認（Build-only）にとどまることの再確認、ビルド成果物とログの確認 | 現行の保証範囲に関する支援 |

## 初学者の観察

初学者の受講者が作業でつまずいた場合は、安易に解答やヒントを提示する前に、環境、アカウント、権限、端末、演習用コピー、インフラ、ツールチェーンのいずれにボトルネックがあるのかを切り分けます。環境側に問題がない場合は、受講者向けの必須ドキュメントの説明不足として整理し、README、セルフチェック（Self-check）、リカバリー手順（Recovery）、バリデータの各正本側を改善・参照するように誘導します。本資料内に個別の回答や判定結果、指摘一覧（ファインディング台帳）を追記することは避けてください。
