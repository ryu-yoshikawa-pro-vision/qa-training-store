# 習熟度評価基準

この文書は、テスト自動化カリキュラムにおける評価の正本です。単に演習のテスト本数をこなしたか、あるいは手順をなぞり終えたかだけで合否を判定するのではなく、正式な仕様に基づいて判断理由を導き出し、実行可能な成果物を通して論理的に説明できるかを評価します。

## 評価の前提

- 期待される製品の振る舞いは、[`docs/spec/README.md`](../../spec/README.md)に記載された正式な仕様、および各機能のビジネスルール（BR）や受入基準（AC）に基づいて判断します。
- アプリケーション実装、既存テストコード、README、各種実行結果は、あくまで実装・リグレッション・補助資料・観測結果の記録にすぎず、正式な仕様の正本としては扱いません。
- シードシナリオID、ルート、UIテストID、ビルド値などは、仕様書が指定する実行可能な正本ソースを参照して確認します。
- `br_ids` や `ac_ids` など、複数のIDを記録する場合はセミコロン（`;`）区切りとします。
- iOSランタイム上でのテスト実行は修了条件に含めません。現在の保証範囲は「Android = ビルド + ランタイムE2E」「iOS = ビルドのみ」です。

## レベル定義

| レベル | 定義 | 成果物・確認記録の例 |
| --- | --- | --- |
| レベル0 | 説明や実践ができない、または正本や保証範囲の認識を誤っている | 仕様と実装を区別して説明できない |
| レベル1 | サンプル、ヒント、詳細な手順書を参照しながら実施できる | 例題のコードをなぞり、状態リセットとアサーションを実行できる |
| レベル2 | 自力で実施でき、その判断理由と成果物・確認記録を論理的に説明できる | ワークブック、テストコード、成果物、失敗分類の内容が一貫している |
| レベル3 | 複数のアプローチやトレードオフを比較検討し、改善案を主体的に提案できる | コスト、リスク、テストの不安定さ、プラットフォーム保証を踏まえた代替案を比較できる |

レベル3は共通課程の必須要件ではなく、対象範囲を絞り込んだレベル2を超える発展課題として位置づけます。なお、講師による支援の有無はレベル定義の必須条件としません。

## Part 1修了基準

Part 1の共通課程修了要件は、C01〜C07およびC09〜C10において、対象範囲を限定したレベル2を達成することです。各習熟項目の詳細な評価基準と最低限必要な成果物は、前述の「習熟度一覧」を参照してください。なお、C08、Android実機環境、およびモバイルアプリ自動化に関する成果物は、共通課程の修了条件には含めません。

環境構築やテストハーネスの健全性を確認するための「初期状態でのテスト通過」は、受講者自身の習熟度を示す成果物とはみなされません。モバイルアプリ自動化を選択課程として履修する場合のC08の成果物要件については、習熟度一覧の該当項目を参照してください（外部リポジトリ等への提出は必須ではありません）。

## Part 2修了基準

Part 2（最終共通課程）の修了要件は、C01〜C07およびC09〜C12において、対象範囲を限定したレベル2を達成することです。各習熟項目の評価詳細と最低限必要な成果物は、前述の「習熟度一覧」に準拠します。

C12の共通課程における評価範囲は、対象範囲を絞り込んだWeb CIのトリガー、品質ゲート、成果物、および失敗時の記録設計に限定されます。ネイティブ環境、マルチプラットフォーム対応、プレビュー／本番配信パイプライン、演習用リポジトリの運用詳細、Androidベースライン、配信コミットハッシュなどは共通課程の修了条件には重ねて要求しません。また、C08は共通課程の修了条件に含まれず、レベル3相当の比較検討や改善提案も共通課程の必須範囲外となります。

## 採点表

| 観点 | レベル1 | レベル2 | レベル3 |
| --- | --- | --- | --- |
| 正本（仕様の理解） | 仕様の参照先を特定できる | ビジネスルール（BR）／受入基準（AC）と、実際の観測結果を明確に切り分けられる | 仕様の曖昧さや不明点を課題として抽出し、代替案を比較検討できる |
| リスクと設計 | 指示された設計技法を適用できる | リスク分析に基づいてテスト条件や適切なテスト層を導き出せる | コスト、網羅性、保守性のトレードオフを踏まえた設計案を提案できる |
| 自動化実装 | 手順書に沿ってテストを実装・実行できる | 再現性のあるテストコードと実行記録を自力で作成できる | テストスイートの削減・分割や、実行トリガーの最適化を提案できる |
| 失敗分析 | エラー内容を正確に報告できる | 失敗分類に基づいて原因の切り分けと境界を論理的に説明できる | 再発防止策を設計し、品質ゲートへの反映を主導できる |
| デリバリー（CI/CD） | CI関連の基本用語を説明できる | 対象範囲を限定したWeb CIのトリガー、品質ゲート、成果物、失敗時記録を説明できる | 特定のコミットハッシュ、成果物管理、CIランナーコストを踏まえた導入案を比較検討できる |

※実装したテストの本数は演習量として記録しますが、それ単体での合否判定基準とはしません。
