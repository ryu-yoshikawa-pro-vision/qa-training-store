# M00：学習環境とAIの安全な利用

> **AIチューター**：CodespacesでM00をロードした後に `pnpm course:tutor M00 --model provider/model-id` を実行できます。利用条件を確認して起動し、質問にはToken・API key・個人情報を含めないでください。チューターはM00の公開資料と本人の成果物を読み取り専用で使い、正式評価やファイル変更は行いません。

## このモジュールで学ぶこと

ここではブラウザ版VS Codeでファイルを読み、保存し、学習用フォルダーだけを扱います。ターミナルやプログラミング経験は前提にしません。案内された `pnpm course:load M00` をコピーして実行し、失敗時には表示されたエラーを確認します。ロード成功は環境準備の確認であり、技能修了の証拠ではありません。

## Codespaceを用意し、画面を確認する

管理者から案内された個人用学習リポジトリを使います。Templateから始める場合は、Template repositoryの **Use this template → Create a new repository** で個人アカウントのPrivate repositoryを作り、その新しいrepositoryからCodespaceを作成します。Template画面から直接作る未公開Codespaceはマシン種別を選べないため、この課程の2-core確認には使いません。

1. 学習リポジトリで **Code → Codespaces** を開き、Codespaceを作成します。設定画面が出たら案内されたdev containerを選びます。
2. 作成画面の支払者表示を読み、正しい利用者・組織が支払うことを確認します。選択肢に **2-core** があることを確認して選びます。2-coreがない、支払者が想定と違う、利用枠・費用を確認できない場合は続行せず、管理者へ確認します。より大きいマシンを代用しません。
3. ブラウザー版VS Codeが開いたら、左端のExplorer、中央のEditor、下部のTerminalとPortsを探します。画面の横幅やVS Codeの版によってパネル位置が違う場合は、メニューの **View** からExplorer・Terminal・Portsを開きます。
4. Terminalで `pwd` を実行し、現在位置を確認してから教材の `pnpm course:load M00` を実行します。`workspace/M00/`に提出物が配置されたことと、表示されたエラーの有無を確認します。

Codespaceはブラウザータブを閉じても停止しません。終了時は[Codespaces一覧](https://github.com/codespaces)で対象のメニューから **Stop codespace** を選びます。実行中だけでなく停止後の保存領域も利用条件を確認します。6080を含むポートの公開範囲はPortsで確認し、課題で必要とされないPublic共有をしません。画面名・利用枠は変わるため、作成時は受講開始ガイドのGitHub公式手順も参照します。

## 画面とファイルの基本

VS Codeのエクスプローラーはファイル一覧、エディターは開いたファイル、ターミナルはコマンドの入力と結果、Portsは実行中サービスの転送状態を表示します。保存前後でファイルの変更印や差分を確認します。`pwd` は現在位置、`ls` はその場所の一覧、`cd workspace/M00` は作業場所を移す例です。相対パスは現在位置を起点に解釈されるため、作業場所が違えば同じコマンドも結果が変わります。

初回ロードではコマンドを暗記しなくて構いません。教材を開いた後に、ターミナルの現在位置、ロードされたファイル、エラーの有無を確認します。学習者が編集したファイルを再ロードが置き換える場合は続行せず、差分を保全して管理者に相談します。

### 一つのファイルを作って保存する

1. 左端のエクスプローラーで`workspace`を開き、`M00`を選びます。見つからなければロード結果と現在開いているフォルダーを確認します。
2. `M00`に新しいファイルを作り、名前を`practice.md`にします。本文に「今日はファイルを保存しました。」と書き、保存します。ファイルのタブに未保存を示す印が残っていないか確認します。
3. いったん別ファイルへ移ってから`practice.md`を開き直し、書いた文が残っていることを確かめます。`submission.md`にはファイル名と確認結果を記録します。保存できなければ、書込み先が`workspace/M00/`か、表示されたエラーと権限を確認します。
4. ターミナルで`pwd`と`ls`を実行します。`pwd`の出力がリポジトリ直下なら`ls workspace/M00`で今のファイルを確認できます。別の場所にいる場合は出力を読み、現在位置に合う相対パスを考えます。見つからないからと同じコマンドを繰り返さず、まず位置を確認します。

次は別条件で、同じフォルダーに`notes.md`を自分で作り、保存・開き直し・ファイル名の確認を行います。最初の文を写すことではなく、保存先と結果を説明する練習です。

## エージェント、Skill、権限

チャットは会話で提案します。エージェントは許可された範囲でファイルを読み、編集やコマンド実行を行えるため、依頼の範囲と許可を先に確認します。Skillは手順と補助ファイルをまとめたものです。`SKILL.md`だけでなく、参照資料や呼び出されるPython helperがある場合は、それらが同じrevisionにそろっているかを確認します。Skill名が表示されたことやAIの自己申告だけでは実行証拠になりません。

同期済みの学習環境で、リポジトリ直下から`ls .agents/skills`を実行すると、配布されたSkillの一覧を確認できます。M00で使う`qa-workflow`を例に、`cat .agents/skills/qa-workflow/SKILL.md`で入口と実行契約を読み、`references/guidance.md`と`Resources`に挙げられたhelperが存在するか確認します。見つからない場合は別のSkillを推測して実行せず、教材の同期結果と作業場所を確認します。ファイルを読むことと、そのSkillや補助スクリプトを実行することは別です。実行前に入力・出力・変更範囲を読み、許可されない操作は行いません。

安全確認のためにSkillを試すときは、提出用の公開サンプルだけを対象にした読取り専用の依頼をします。まずSkillの契約を読み、依頼文で対象ファイルを限定し、ファイル変更・コマンド実行・外部送信・他Skillへのdispatchを禁止します。出力をSkill本文と参照資料に照らし、対象範囲外を読んでいないか、ファイルを変更していないか確認します。実行できない、Skillが見つからない、または安全範囲を確認できない場合はそこで止め、未実行またはBLOCKEDと記録します。

無料モデルの設定が案内されている場合はその設定を保ちます。APIキー、認証キャッシュ、個人情報を教材・依頼文・共有ログへ貼り付けません。ポート6080はPrivate/noVNC用途であり、不要な公開設定をしません。利用条件や無料枠が不明なら、実技を開始せず管理者へ確認します。

## 依頼の作り方

依頼には、(1)目的、(2)読むべき正式資料、(3)変更してよい場所、(4)成果物、(5)完了の確認方法を含めます。例：「この練習用ファイルを読み、`workspace/M00/`だけを変更し、変更前後の差分と実行結果を示してください。外部通信、削除、他フォルダーの変更はしないでください。仕様にない点は質問事項として残してください。」AIの提案を採る前に、対象ファイルと差分を確認します。

## 演習と提出

1. `workspace/M00/practice.md`を作成して一文を保存し、別ファイルへ移ってから開き直します。続けて`notes.md`を作成し、保存先と結果を自分で確かめます。
2. 手本の短い依頼として「`workspace/M00/submission.md`だけを読み、書かれている項目を3点以内で要約してください。ファイル編集、コマンド、外部通信は禁止です」をエージェントへ渡します。応答と提出物を比べ、意図しない差分がないことをVS Codeで確認します。
3. `qa-workflow` Skillの入口と参照資料を読んだ後、「`workspace/M00/submission.md`だけを読み、必要なQA開始Skillと根拠を説明してください。ファイル変更・コマンド実行・外部通信・他Skillのdispatchは禁止です。不足情報があれば停止してください」と依頼します。実際に返ったSkill名・根拠・不足情報をSkill本文と照合し、呼び出し時に使ったSkillの配布revisionとともに記録します。実行できない、範囲外へ進む、または答えを確かめられない場合は停止し、未実行/BLOCKEDとします。
4. 自分で条件を変えた依頼を作り、目的・参照先・範囲・成果物・確認方法を含めます。
5. 作業ファイルを残したまま`pnpm course:load M00`を再実行します。loaderの結果を読み、`practice.md`と`notes.md`が保全されたことを開き直して確認します。競合や予想外の上書きが表示されたら、強制上書きをせず作業を止めます。
6. Secretを求める提案やフォルダー外の編集を拒否し、理由と安全な代替を記録します。Codespace停止方法と課金・無料枠表示も確認し、利用条件が不明なら管理者に質問します。

提出は `workspace/M00/submission.md` です。Skill実行の記録には、秘匿情報を除いた依頼文、返答の必要部分、Skill revision、実行した範囲、確認したファイル差分を記録します。APIキー、個人情報、会話全体は提出しません。評価では保存できたことに加え、現在位置、Skillの実行契約、許可範囲、危険な提案をどう照合したかを本人が説明できることを見ます。
