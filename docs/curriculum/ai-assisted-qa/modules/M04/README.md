# M04：設計レビューと自動化対象選定

> **AIチューター**：CodespacesでM04をロードした後に `pnpm course:tutor M04 --model provider/model-id` を実行できます。利用条件を確認して起動し、質問にはToken・API key・個人情報を含めないでください。チューターはM04の公開資料と本人の成果物を読み取り専用で使い、正式評価やファイル変更は行いません。

## このモジュールで学ぶこと

M03のCaseを仕様に照らしてレビューし、何をどのテスト層で確認するか、自動化するかを決めます。AI案に誤りを探すためだけに誤りを作るのではなく、正しい案は根拠を確認して採用し、欠落・重複・未根拠の期待結果は修正または未決として残します。

## Caseレビューの順番

1. Caseの仕様IDとBR/ACが正式仕様にあるか確認する。
2. Role、State、Data、前提、操作、期待結果がつながっているか確認する。
3. RiskからCondition、Caseまで追跡し、重複・未検証の高リスク条件を探す。
4. 期待結果が適切な層で観測できるか、別条件で実行可能か確認する。
5. 仕様の矛盾、データ不足、実装と仕様の差を、正解へ埋めず質問事項として分ける。

### 完成例：上限超過のAI案をレビューする

AI案が「上限3、現在数量2の商品に2個追加すると、数量を3に補正する」と書いたとします。`BR-CART-001`と`AC-CART-001`は上限超過を拒否し、変更前の数量を維持すると定めます。この案は期待結果を「拒否し数量2のまま」に修正します。上限3の根拠となる在庫・購入上限と、現在数量2をどう準備するかもCaseの前提に残します。

修正後に、同じRole・SKU・開始数量・操作・期待結果を持つ承認済みCaseがあれば、新規の自動テストを重複して増やす前に両者の追跡関係を比較します。一方、開始数量や検証したい不変条件が異なるだけで重複と決めてはいけません。実際の画面が数量3を示した場合は観測として記録し、仕様を画面に合わせて書き換えず差異を調査します。

練習では公開候補を読み、この完成例と異なる条件で、正しい案は根拠付きで採用し、誤案は修正します。仕様に答えがない場合は修正案を想像せず、質問と保留した期待結果を引き継ぎます。

### 訂正後のCaseと既存Caseを照合する

期待結果の誤りを仕様に基づいて訂正したら、候補をそのまま新しい実行対象へ加える前に、承認済みCaseとRole、State、Data、操作、期待結果、仕様根拠を比較します。同じ条件と検証責務なら、正規Caseを一件残し、重複側から参照されているCoverageやIDを正規Caseへ移します。誤った期待結果の修正は必要でも、同じ検証の自動化を二重に追加する理由にはなりません。

## テスト層と自動化判断

画面表示そのものを確認したい場合はComponent/Web E2E、データ永続化と複数部品の連携を確認したい場合はIntegration等が候補です。テスト層は一番大きいものを選ぶのではなく、期待結果を観測できる範囲と境界を越えるリスクに合わせます。

自動化候補は再実行頻度、失敗時の影響、条件の安定性、準備・保守費用を並べます。頻度が低く条件が急変する探索は後回しにする、仕様が未確定な対象は自動化しない、なども理由があれば妥当です。Automate / Later / Do not automate のいずれも候補になります。

## 仕様未決と観測結果を分ける

仕様が答えていないことと、実行して観測した結果は別の記録です。再現時に数量が拒否されたという事実だけでは、仕様上も拒否が正しいとは決まりません。BR/ACに根拠がなければ期待結果を作らず、仕様の確認事項として残します。正式仕様が期待結果を定めている場合は、その期待と観測を比較し、差があれば製品・テスト・環境のどこに原因があるかを調べます。

## Phase 1総合演習

`workspace/M04/`の初見条件を使い、既存の完成例を転記せず分析・設計を行います。提出物には仕様根拠、Risk、検証責務、Case、期待結果、テスト層、自動化採否、未決事項を含めます。評価時には提出にない小さな条件変更について本人が根拠と見直し範囲を説明します。質問への新しい回答をAIに生成させず、既存資料は参照できます。

## 評価と引継ぎ

Phase 1の公開ルーブリックは [`assessment/phase-1-rubric.md`](../../../../../training/ai-assisted-qa-course/assessment/phase-1-rubric.md) です。仕様・Risk・Caseの追跡、AI案の採否、未決の扱いを判定します。模範回答、採点用テスト、完成状態データはpublicな`qa-training-store`内の通常ファイルです。学習用Template/同期/ロード/Web Buildへの配布除外は秘密保持ではありません。本人が `pnpm course:assess M04 --model provider/model-id` を起動し、根拠のある条件変更への回答を提出します。校正済みAIの候補とNode.jsによる証拠・版の検証を合わせて判定し、人間の採点承認は要求しません。結果と再評価履歴は本人の `workspace/.course-assessments/P1/attempts/` に保存します。必要な証拠や校正がない場合は修了にしません。

## 確認と復習

[M04の確認クイズ](../../quizzes/M04.json)を回答後、誤答したレビュー観点を順番に再確認します。提出物の記述が正しくても、未提示条件への本人判断が成立しない場合はPhase 1修了にしません。
