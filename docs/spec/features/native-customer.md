# ネイティブ顧客機能

## 目的・対象範囲

ネイティブ顧客機能がWeb版と共有するプロダクトの振る舞いを、SQLite、ネイティブキーバリューストア、およびネイティブシェルによって提供するための契約を定義します。ネイティブ管理者機能、ゲスト購入、およびiOS実機環境（物理端末の実行環境）は対象外です。

## 業務ルール

### BR-NATIVE-001 — ネイティブ顧客機能は共有アプリケーション契約に従う

ログイン、アカウント、カート、購入手続き、決済、注文、レビューの定義や役割、状態、エラー、スナップショットをWeb版と共有し、ネイティブ専用に簡略化した業務ルールは作成しません。

### BR-NATIVE-002 — ネイティブ実行環境と本番機能を分離する

自動テスト環境および開発環境のみがテスト操作機能、テストハーネス、自動化ブリッジを保持し、本番ビルドではこれらを公開・インポートしません。ネイティブSQLiteにおけるデータ更新では、排他トランザクションと外部キー制約チェックを遵守します。

## UI・振る舞い契約

Androidは標準のネイティブ実行環境の対象であり、Maestroによるユーザー操作、状態の観測、実行ログの記録、個別の指摘事項への連携を行います。iOSは独立したビルドおよびビルド時の保護機能や成果物を検証対象とし、シミュレーター環境やMaestroによる検証は正式な品質ゲートとはしません。

## 受入条件

### 判定条件

#### AC-NATIVE-001 — Web共有契約をネイティブで維持する

関連業務ルール: `BR-NATIVE-001`

ネイティブ顧客機能における購入、注文、レビューの処理、および役割、状態、エラーの定義が共有アプリケーション契約と一致しており、管理者権限が混入しないこと。

#### AC-NATIVE-002 — 自動化環境と本番環境を隔離する

関連業務ルール: `BR-NATIVE-002`

自動テスト用ビルドからテスト操作機能やハーネスにアクセス可能であり、本番用バンドルにはテスト用マーカー、モジュール、画面、サービスが一切存在しないこと。また、Android実行環境とiOSのビルド検証のみの保証範囲が混同されないこと。
