# 仕様変更の手順

この文書は、仕様を保守・変更する担当者向けの手順書です。機能の仕様を学習する受講者は、まず [`README.md`](./README.md) の「学習者向けの読み始め」から対象機能を確認してください。受講にあたって本変更手順を前提とする必要はありません。

## 通常の機能変更

```text
変更要求
  ↓
正式仕様
  ↓
BR / AC
  ↓
リスク分析 / テスト設計
  ↓
実装
  ↓
決定論的自動テスト
  ↓
リスクベースのAgentic QA / 手動QA
  ↓
レビュー / マージ
```

ユーザー向け新規機能、UI/UX・レスポンシブ・アクセシビリティの変更、ロールや権限の変更、状態や状態遷移の変更、エラー処理や境界値の変更、および高リスクなリグレッションは、Agentic QAの対象候補となります。一方で、低リスクな内部限定の変更や、既存のリグレッションテストで十分担保できる変更については、対象候補から除外できます。ただし、除外したことを「テスト実施済み」の代替とみなすことはできません。

## 既存仕様への違反

実装が既存の正式な仕様に違反している場合、仕様側を実装に合わせて変更してはなりません。不具合の修正、リグレッションテストの更新、必要に応じた有効な既知の乖離の削除を行い、仕様書の修正は誤記の訂正や説明の補足のみにとどめます。

## 仕様変更

期待される挙動を変更する場合は、正式仕様 → BR/AC → リスク・テスト設計 → 実装を同一の変更単位で同期させます。緊急の修正対応であっても、マージ前に必ず同期を完了させます。

## 既知の乖離と未解決事項

既知の乖離として管理するのは、現在有効なもの（Active）のみに限定します。実装の修正とリグレッションテストの追加が完了した段階で、該当エントリを削除します。未解決事項は、プロダクトの意思決定が完了した段階で正式仕様、BR/AC、テストへと反映します。未確定の間は、検出事項を不具合として確定させません。

## レビューとCI

BR/ACや直接参照している正式仕様ファイルが変更された場合、それを参照しているChallengeの影響サマリーを生成します。生成されるHTMLはMarkdownから再生成するものとし、HTMLを直接編集してはなりません。また、AI Agentic QAは初期導入時点では必須のCIゲートには設定しません。

影響サマリーは次のCLIコマンドで生成し、CI上では既存の Style Quality Job の Review Summary へ出力します。

```text
pnpm run summarize:spec-impact
```
