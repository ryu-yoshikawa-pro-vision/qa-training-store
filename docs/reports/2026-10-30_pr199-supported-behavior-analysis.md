# Scenario Shop 全サポート機能の分類・基本分析

## 対象と算出方法

調査基準は`qa-training-store`の固定HEAD `def631991591c7bfd004a9aadaec6274fb86ec51` の正式仕様です。分母は画面カタログと`docs/spec/product-scope.md`、11件の主機能仕様、ロール/状態/UX契約を突合した**仕様上の検証責務**です。画面数または仕様ファイル数をそのまま機能数として扱いません。

出典付きの分析台帳は`training/ai-assisted-qa-course/coverage/supported-behaviors.json`です。各操作・状態・BR/AC等についてsource path/line、platform、Role、State、Data、Action、Expected、主要Risk、検証責務、Condition、Case選定方針と理由を保存します。

| 分類 | 台帳件数 |
| --- | ---: |
| 画面の操作・業務動作（38画面の73機能記述を分割） | 172 |
| 通常以外のUI状態・期待結果 | 20 |
| BR/ACの独立した業務規則・受入条件 | 46 |
| 認可・アカウント状態・会員ランク | 8 |
| 許可状態遷移・シナリオ制御 | 12 |
| UI・アクセシビリティ共通契約 | 4 |
| 正式サポート範囲・Platform・対象外 | 9 |
| **計** | **271** |

**台帳の仕様記述に対する分類率は271/271（100%）、基本分析済み率は271/271（100%）**です。新たな正式画面・機能・非default UI状態・BR/ACが追加または削除された場合、`scripts/training/validate-supported-behaviors.mjs`が仕様の独立抽出と台帳照合で欠落・不一致を拒否します。ロール・状態遷移・UI・正式スコープは必須IDと出典行で照合します。

## 分母の境界と実施レベル

- Webデスクトップ・モバイルWebは正式対象。管理操作は1024px以上。権限外・未検出画面およびレスポンシブとアクセシビリティも分析する。
- Androidはネイティブの顧客機能を対象とし、共有業務契約とネイティブSQLite/ランタイム差・本番ビルドのテストハーネス除外を確認する。iOSは**ビルド限定の保証範囲**であり、iOSランタイムE2Eを必須にしない。
- ゲストチェックアウト、Native管理、外部決済・配送、返品/返金/キャンセル等は正式対象外として明示し、サポート対象から勝手に削除する目的で対象外分類を使わない。
- 既存の仕様・画面にある表記違い・Android/Webの同一業務動作は同じ動作として扱い、表示条件の異なる非default状態は別に検証する。必要なCase深度とWeb E2E化はRiskによって判断し、**全Case自動化率100%は要求しない**。
- 実装/Seedの網羅的なコード経路検証、業務動作の実Run PASS、受講者の習熟認定はこの台帳の成功率へ加算しない。

## 追跡と検証

```bash
node scripts/training/validate-supported-behaviors.mjs
pnpm run validate:ai-assisted-qa
```

欠落した操作、BR/AC、状態、Role/UX契約、重複ID、出典改訂、Risk/Condition/検証責務/Case方針の欠落を拒否する契約テストも追加する。単なるID数・ファイル数だけで合格させない。

この台帳は**正式仕様ベースの分類・基本分析**です。全実装ファイルとソースコードを独立に一巡して「仕様に現れない実装動作がゼロ」と断定したものではありません。正式仕様とコード・Seedの差異が判明した場合は、仕様を勝手に書き換えず、対応する分析行を更新してから判定します。Template・2-core Codespaces・実OpenCodeモデルの技術受入も本台帳とは別の残タスクです。
