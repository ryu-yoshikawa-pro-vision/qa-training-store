# Curriculum self-study review checklist

この文書は、Curriculumを受講者視点で継続的に見直すための再利用可能な確認観点です。Learner Required pathやspecializationの成果物、個別レビューの結果を保存する場所ではありません。

## Review basis

レビュー時は、Master Plan §5.10のコース開始時対象受講者像と、対象経路で明示されたLearner Requiredの前段知識だけを使います。Common Coreの不足をNative specialization、Extension、Reference、経験者の暗黙知で補完しません。specializationの確認では、明示されたCommon prerequisiteと同一specialization内の前段Lessonだけを前提にします。

## Reusable checklist

| 観点 | 確認内容 |
| --- | --- |
| Lesson / Exercise | 対象がLearner Requiredまたは選択したspecializationの教材・演習として明確であるか |
| 開始条件 | Learnerが開始でき、必要な環境受領条件と正規の前提Lesson / completionが分かるか |
| 学習内容の自己完結 | 教材外の口頭説明や非公開の答え合わせなしに、説明と判断へ進めるか |
| Common Core独立性 | specialization / Extension / Referenceを未受講でもCommon Coreを進行・完了できるか |
| 分岐 / 復帰 | specializationのskip先、選択時のbranch、完了後のrejoin pointが一意か |
| 学習目標と説明 | 何を理解・説明・作成するかが本文の説明へつながっているか |
| 演習内容 | 何を作る、実行する、比較する、記録するかが明確か |
| 成果物とEvidence | exerciseの成果物、実行結果、差分など、completionに必要な根拠が特定できるか |
| 自己確認 | 参照リンクを開くだけでなく、回答・成果物の充足をLearner自身で判断できるか |
| Recovery | 学習内容の未達とEnvironment / Toolchain障害を切り分け、次に確認する場所が分かるか |
| 完了条件 | どこまでできれば当該Lesson / exerciseが完了か判断できるか |
| 次の行動 | 次に読むLesson、skip、branch、rejoin、または追加exerciseが分かるか |
| 環境値への到達 | Test Clock、Seed Data、学習用住所、Test Controlなどを重複コピーせず、既存SSOTへ到達できるか |
| 観測の分類 | 仕様・Expected Behavior違反、仕様違反とは確定しないUX上の懸念、改善提案、未確定（Evidence / 再現条件不足）を混同しないか |
| Security成立条件 | 入力、保存、escape表示、HTML解釈、JavaScript実行 / executable sink到達を区別できるか |
| Evidenceと報告 | 報告本文の対象画面・操作・事象がScreenshot / Video / Trace等と一致し、Evidence不足時に断定しないか |
| 用語と識別子 | 一般説明は日本語中心で、Tool / API / path / command / ID grammarを壊さず、表記が一貫しているか |
| Instructor support境界 | Instructor Referenceが環境・権限・端末・Training Copy・Toolchain支援に限定され、学習判断を代行していないか |
| 問題発見時の扱い | 観点を具体的な教材改善指示へ変換し、個別Finding、備考、未検証理由、レビュー履歴、補足Evidenceをこの文書へ記録しないか |

## Boundary reminders

- Training baseline / stock flow / Repository-required assetの存在を、learner-authored exerciseやcompletion Evidenceと混同しない。
- Common completionへNative環境、Physical Android、Maestro、Native CI、full deliveryを暗黙に追加しない。
- Product behavior、Seed / Test Clock / Test Control、Normative Specificationの意味を、教材レビューの都合で変更しない。
- この文書自体へYes / No、コメント、Finding、備考、未検証理由、Evidence、reviewer、実施日、PASS履歴、進捗を記録する欄を追加しない。
