# UI詳細仕様

ページ構造は `page_patterns.md`、表示文言は `ui_content_dictionary.md` を正本とします。

## 1. 共通状態

すべてのデータ画面において、必要な範囲で「ローディング（Loading）」「空状態（Empty）」「成功（Success）」「バリデーションエラー（Validation Error）」「操作エラー（Operation Error）」「競合（Conflict）」「未検出（Not Found）」「アクセス拒否（Forbidden）」の状態を定義します。画面ごとに不要な状態を一律で増やすことはしません。

- ヘッダーに小さなテストモードバッジを表示する。
- 実取引を行わない旨および実在の個人情報入力禁止の注意文は、ログイン、サインアップ、カート、注文手続き（チェックアウト）の各画面で目立つお知らせ（Notice）として再掲する。
- 重要な処理結果は、トースト通知だけでなく画面内にも履歴や情報として残す。
- 送信処理中はボタンを非活性（disabled）またはローディング表示にし、二重操作を防ぐ。
- UI表示は日本語辞書を参照し、`payment_failed` などの内部エラーコードや識別子をそのまま画面へ露出させない。

## 2. ホーム（Home）

- ヒーローエリア、主要カテゴリー、新着商品、セール商品、会員ランク案内を表示する。
- ヒーローエリアのプライマリアクション（主要ボタン）を押下した際は、全商品一覧画面へ遷移する。
- カテゴリーは最大6件、商品セクションはそれぞれ最大8件まで表示する。
- セール対象商品が0件の場合は、空のセクション自体を表示しない。
- 商品カードには、画像、ブランド名、商品名、価格、セール/会員価格の表示、評価、在庫状況を表示する。

## 3. 商品一覧・検索・カテゴリー

- 検索結果タイトル、検索結果件数、検索フォーム、カテゴリー、ブランド、価格帯、在庫状況、セール有無、最低評価、ソート、ページネーションを表示する。
- 適用済みの絞り込み条件はチップ（Chip）形式で表示し、条件ごとの個別解除と全条件の一括解除を提供する。
- デスクトップ表示ではフィルターサイドバーで条件を即時反映し、モバイル表示ではボトムシート内で選択してまとめて適用する。
- 各フィルターの候補項目には、該当する商品件数を表示する。
- 検索結果が0件の場合は、検索ワードの変更提案、フィルターの解除ボタン、全商品一覧や主要カテゴリーへの導線リンクを表示する。
- 商品詳細画面から一覧画面へ戻った際は、設定していた絞り込み条件、ページ番号、スクロール位置を復元する。
- 検索サジェスト（入力候補）には商品、カテゴリー、ブランドを合わせて最大8件表示する。商品選択時は `/products/[productId]`、カテゴリー選択時は `/categories/[categoryId]`、ブランド選択時は `/search?brand=[brandId]` へ遷移し、候補を選択せずにEnterキーを押した場合は `/search?q=...` へ遷移する。Request Sequence IDまたはAbortControllerを用いて常に最新の入力に対する検索結果のみを表示し、画面（ルート）を離脱した際はサジェスト結果を破棄する。

## 4. 商品詳細

- パンくずリスト、ブランド名、商品名、評価リンク、ギャラリー、商品説明、バリエーション選択、通常価格、会員価格、在庫状況、送料条件、数量選択、カート追加ボタン、レビュー分布・一覧を表示する。
- ギャラリーはサムネイル一覧、メイン画像、拡大ダイアログを備える。
- セール価格が適用される場合は通常価格に取り消し線を表示し、割引率をテキストで併記する。
- 会員価格が適用される場合は、適用対象のランク名と割引額を表示する。
- バリエーションの選択UIは、選択肢が12件以下の場合はボタン形式、13件以上の場合はセレクトボックス（ドロップダウン）形式とする。
- 在庫数が0の場合は「在庫切れ」と表示して選択不能にするか、またはカート追加CTAボタンを非活性（disabled）にし、在庫数が1〜5の場合は「残りN点」と低在庫の警告表示を行う。
- モバイル表示では、価格、在庫状況、カート追加ボタンを画面下部の固定バー（Sticky Bar）に常時表示する。
- レビュー一覧は、新着順、評価が高い順、評価が低い順で並べ替え（ソート）できる。

## 5. ログイン・サインアップ・アカウント

### ログイン

- メールアドレス入力欄、パスワード入力欄、ログインボタン、テスト用固定アカウントの案内を表示する。
- アカウント停止（suspended）および退会済み（withdrawn）のアカウントは、一般的な認証失敗エラーと明確に区別してエラーメッセージを表示する。
- ログイン成功後、ゲスト状態でカートに入れていた商品の統合結果メッセージを表示する。
- チェックアウト（注文手続き）画面からログイン画面へ遷移してきた場合は、ログインが必要な理由と手続きへの復帰導線を表示する。

### サインアップ（新規会員登録）

- メールアドレス入力欄、パスワード入力欄、パスワード確認欄、表示名入力欄、学習用システムとしての利用上の注意確認を表示する。
- 静的な利用規約・プライバシーポリシーへのリンクを表示するが、規約バージョンごとの同意履歴データは保持しない。

### プロフィール・配送先住所

- プロフィール画面には表示名と電話番号を表示する。取得したDTOに含まれる `actionVersion` を画面裏で非表示のまま保持し、更新リクエスト送信時にパラメータとして渡す。
- 住所管理画面では、住所一覧、新規追加、編集、削除、デフォルト住所への変更機能を提供する。登録上限は最大5件とする。デフォルト住所を削除した後に他の住所が残っている場合は、登録日時（createdAt）昇順・ID（id）昇順で先頭となる住所を自動的に新たなデフォルト住所へ繰り上げる。
- 郵便番号検索は、入力値が学習用の住所辞書に完全一致した場合にのみ住所候補を提示する。自動補完による確定は行わず、ユーザー自身で確認・確定させる。

## 6. カート

- カート明細ごとに、商品画像、商品名、バリエーション、単価、数量、在庫状況、小計、削除ボタンを表示する。数量変更時に在庫上限を超えた指定がされた場合は、変更を保存せず元の数量を維持する。
- カート投入後に商品価格の改定があった場合は、旧価格と新価格を並べて表示し、価格変更の確認ボタンを設ける。
- 購入不可となった商品明細には、購入できない理由と明細の削除ボタンを表示する。
- 注文サマリー欄には、商品小計、会員割引額、送料、合計金額、送料無料ラインまでの不足額を表示する。
- デスクトップ表示では注文サマリーを画面内に固定（Sticky）表示し、モバイル表示では商品明細一覧の直下に配置したうえで、必要に応じて画面下部固定のCTAボタン（購入手続きへ）を表示する。

## 7. 注文手続き（チェックアウト）

### 配送先

- 登録済み住所からの選択と、新規住所入力の双方に対応する。
- 入力フォームは1列レイアウトとする。各項目の必須・任意の別、および電話番号の利用目的を明示する。
- 建物名入力欄は任意の折りたたみセクションとし、すでに入力されている場合は展開状態を維持する。
- 選択または入力された配送先情報は、注文スナップショットとして保存する。

### 支払方法

- 決済テスト用コードとして、`TEST-SUCCESS`、`TEST-DECLINED`、`TEST-INSUFFICIENT`、`TEST-AUTH-FAILED` をラジオボタンで選択できるようにする。
- 実際のクレジットカード番号などを入力しないよう、注意文を明記する。

### 注文確認

- 注文商品、配送先、会員ランク、各種割引、送料、合計金額、模擬取引（テスト環境）に関する注意事項を表示する。
- カートのバージョン、商品価格、在庫状況をバックエンドと再照合・検証する。画面裏で `checkoutActionVersion` を非表示のまま保持し、注文確定リクエスト送信時にパラメータとして渡す。
- 注文確定ボタンの文言は「注文を確定する（¥x,xxx）」とし、二重送信を防ぐため一度だけ実行可能とする。
- デスクトップ表示では右側にサマリーを固定（Sticky）表示し、モバイル表示では折りたたみ可能なサマリーを配置する。

### 処理中

- 発行された注文番号と「支払いを処理しています」という進行状況メッセージを表示する。
- 画面離脱を防止する警告ダイアログを表示するが、ブラウザ終了やアプリ再起動が発生した場合でも、注文詳細画面から同一の決済試行（Attempt）を再開できるようにする。
- 処理中画面には、キャンセルボタンや再試行ボタンを配置しない。

### 結果

- 注文成功時: 注文番号、支払合計金額、配送先概要、注文詳細へのリンク、商品一覧へのリンクを表示する。
- 注文失敗時: エラー種別、在庫の引き落としは発生していない旨、および注文詳細画面から再度支払いをやり直せる案内を表示する。

## 8. 注文一覧・詳細

### 顧客向け

- 一覧: 代表商品画像、注文番号、注文日時、合計金額、注文状態、詳細リンクを表示する。注文状態による絞り込みフィルターと、新しい順の並べ替え（ソート）を提供する。
- 詳細: 「現在の状態」「次に行われること」「利用者ができること」、注文時のスナップショット情報、決済試行履歴（Payment Attempt）、タイムライン、配送情報（Shipment）を表示する。
- 注文状態が `payment_failed`（決済失敗）の場合にのみ再支払いボタンを表示し、注文詳細から取得した `orderActionVersion` を再決済リクエストに渡す。
- `processing?orderId=...` へのアクセス時は、注文の所有権、注文ステータスが `pending_payment` であること、および最新の決済試行が `processing` であることを検証した上で状態確認または再開処理を行い、再支払いボタンは表示しない。
- 配送完了（`delivered`）となった対象商品（eligible Item）に対して、レビュー投稿へのCTAリンクを表示する。

### 管理者向け

- 注文番号、注文日時、顧客のメールアドレス・表示名、商品スナップショット、金額の内訳、配送先スナップショット、決済情報、配送情報、ステータス変更タイムラインを表示する。
- 注文状態 `paid`（入金確認済み）: 「発送準備を開始」ボタンを表示する。各ステータス変更時には注文詳細の `orderActionVersion` を使用し、処理成功後はレスポンスDTOの新しいバージョンへ更新する。
- 注文状態 `preparing`（発送準備中）: 配送会社および追跡番号の入力欄と、「発送する」ボタンを表示する。
- 注文状態 `shipped`（発送済み）: 「配送完了にする」ボタンを表示する。
- その他のステータスでは、現在の状態に応じて操作ができない理由を表示する。

## 9. レビュー

- 配送完了（`delivered`）となった対象明細にのみ、レビュー投稿リンクを表示する。
- 投稿フォームは、評価1〜5のラジオボタングループ、任意のタイトル入力欄、最大1,000文字の必須本文入力欄で構成する。既存のレビューが存在する場合は評価・タイトル・本文を初期値として表示し、取得済みのバージョン情報を用いて更新処理を行う。
- 管理者向けレビュー一覧では、公開（published）/非公開（hidden）/削除（deleted）のフィルターを用意し、非公開化および再公開の操作を提供する。なお、フェーズ1（Phase 1）では状態変更の理由入力は求めず、状態変更履歴の `reasonText` には null を設定する。
- 商品詳細画面には、レビューの平均評価、総件数、1〜5の星別評価分布、並べ替え（ソート）、ページネーションを表示する。平均評価は、DBに保存されている未丸めの数値を四捨五入して小数第1位まで表示する。

## 10. 管理画面シェル・オーバービュー（Admin Shell & Overview）

- サイドナビゲーション、パンくずリスト、ページヘッダー、メインコンテンツ表示領域のレイアウト構造を共通化する。
- オーバービュー画面には、発送準備待ち件数、低在庫SKU件数、非公開レビュー件数、最近の注文一覧、クイックアクションを表示する。低在庫SKU件数の集計では、有効（active）なSKUのうち在庫数が1〜5の品目のみをカウントし、在庫0の品目は含めない。
- 売上金額、コンバージョン率、前年対比、グラフ（チャート）等の高度な集計要素は表示しない。

## 11. 管理者向け一覧画面共通

- タイトル、プライマリアクション、検索、フィルター、ソート、適用中フィルター表示、データテーブル、ページネーションを表示する。
- 絞り込みフィルターの適用結果として0件になった場合と、マスターデータ自体が0件である場合とで、エンプティ状態（Empty State）の表示メッセージを明確に分ける。
- 商品一覧の在庫フィルターでは、商品に紐づく有効（active）な全SKUの合計在庫数をもとに商品単位で判定し、合計0を「在庫切れ」、1〜5を「低在庫」、1以上を「在庫あり」とする。SKU単位の詳細な在庫数は在庫管理一覧画面で確認する構成とする。
- 一括操作（Bulk Action）は、商品一覧における「公開/非公開の切り替え」、レビュー一覧における「非公開/再公開の切り替え」に限定して提供する。
- 一括操作の実行結果は、成功件数・失敗件数および対象データへのリンクを画面内に表示する。

## 12. 管理者向け詳細・編集画面

### 商品管理

- メイン領域: 基本情報、商品説明、バリエーション/SKU設定、価格、在庫参照リンク、GitHub管理の画像アセット関連付けを表示する。既存SKUの在庫数は誤操作防止のため読み取り専用とし、「在庫を調整」リンクから在庫管理画面へ誘導する。
- サイド領域（Aside）: 公開ステータス、カテゴリー、ブランド、会員限定設定、更新日時・更新者情報を表示する。
- 未保存の変更が存在する間のみ、状況連動の保存バー（Contextual Save Bar）を表示する。
- プレビュー、保存、変更破棄、未保存時の離脱警告を提供する。プレビューはフォーム上の未保存データを使用し、別画面へ遷移せず編集画面内のダイアログまたはオーバーレイで表示する。商品名、カテゴリー、ブランド、有効なSKUが1件以上登録されているなど、下書き（draft）保存に必要な最小限のバリデーションを満たすまでプレビューボタンは無効化し、プレビューを閉じた後は元のフォーム内容と入力フォーカス位置を復元・維持する。
- 登録済みの既存商品には「複製」ボタンを提供し、新規登録フォームへ遷移した上で有効なSKU情報、画像設定、商品基本情報を初期入力する。なお、複製による画面遷移時点ではデータベースに変更を加え書き込まず、商品コードおよびSKUコードは未入力状態とし、初期在庫数は0とする。
- SKU設定では、新規追加、価格および購入上限数の変更、無効化、条件付き削除の操作ができる。新規追加するSKUに限り、登録時に初期在庫数を入力できる。商品コードやSKUコードがシステム制約等により変更不可となった場合は、読み取り専用表示に切り替え、変更できない理由を明記する。
- 下書き（draft）状態の商品に限り、危険操作領域（Danger Zone）に削除ボタンを配置し、削除の可否および削除対象の確認ダイアログを表示する。
- 状態変更アクションは、定義されたステートマシン（State Machine）に厳密に従う。draftからは「公開」、publishedからは「非公開」または「販売終了」、unpublishedからは「再公開」または「販売終了」の操作を受け付け、discontinued（販売終了）となった商品は読み取り専用として復元用アクションは表示しない。ステータス変更はフォーム入力の保存とは独立した操作とし、未保存の変更がある状態でステータス変更を試みた場合は、先に保存または変更の破棄を行うようユーザーに要求する。

### カテゴリー・ブランド管理

- カテゴリー管理では、一覧表示、新規追加、編集、表示順の並べ替え、有効/無効の切り替えを提供する。ブランド管理では、一覧表示、新規追加、編集、有効/無効の切り替えを提供する。新規作成時はステータスを有効（active）固定とし、カテゴリーは一覧の末尾へ追加する（既存0件時は表示順10、既存がある場合は最大値+10を自動採番）。通常情報の編集とステータス変更は別操作として分離する。
- カテゴリーの並べ替えモードでは、フィルターやページネーションを一時的に解除して全カテゴリーを表示し、ドラッグ＆ドロップおよび上下移動ボタンによる順序変更を提供する。並べ替え結果の保存時には、送信された `orderedIds` がシステム内の全カテゴリーIDと過不足なく一致することを検証し、`sortOrder` を10刻みで再採番して保存する。ブランドは名称の五十音・アルファベット順固定とし、並べ替えモードは提供しない。
- 公開中の商品から参照されているカテゴリーやブランドであっても、無効化ボタン自体を非活性（disabled）にはせず、実行時に参照中の対象商品件数と無効化するための手順・解消方法を明記したエラーメッセージを表示する。

## 13. 在庫管理

- SKUコード、商品名、現在の在庫数、在庫ステータス、最終更新日時を表示する。在庫ステータスは、0を「在庫切れ」、1〜5を「低在庫」、6以上を通常表示とする。
- 在庫調整時は、調整数量と調整理由を入力させ、変更前後の数量差分を確認ダイアログに明示して実行させる。

## 14. ユーザー管理

- 管理者（admin）権限を持つユーザーのみが利用できる。
- メールアドレス、権限ロール（Role）、会員ランク（Rank）、ステータス（Status）による検索・絞り込みを提供する。
- 変更可能な範囲として、会員ランクは顧客（customer）ロール内での変更、権限ロールはオペレーター（operator）と管理者（admin）間での昇格・降格、ステータスは有効（active）と停止（suspended）の間でのみ変更を許可する。また、システム内に管理者が不在になることを防ぐため「最後の管理者アカウントの権限変更・停止」および「自身のアカウントの権限変更・停止」を禁止し、該当操作時は保護エラーを表示する。退会済み（withdrawn）ステータスおよび一般顧客（customer）ロールは読み取り専用とする。フェーズ1（Phase 1）では変更理由の入力は求めない。
- 詳細な監査ログ（Audit Log）の閲覧機能は、フェーズ2（Phase 2）以降で提供する。

## 14.1 管理者向け一覧画面の固定条件

| リソース | 検索対象 | 絞り込みフィルター | 並べ替え（ソート） |
|---|---|---|---|
| 商品 | 商品名、商品コード、SKU | 状態、カテゴリー、ブランド、会員ランク、在庫有無 | 更新日、商品名、最小価格 |
| カテゴリー | 名称 | 有効（active） | 表示順、名称 |
| ブランド | 名称 | 有効（active） | 名称、更新日 |
| 在庫 | 商品名、SKU | 低在庫（1〜5）、在庫0、在庫あり（1以上）、有効（active） | 在庫昇順、更新日 |
| 注文 | 注文番号、顧客メールアドレス | 状態、注文日 | 新しい順、古い順、合計金額 |
| ユーザー | メールアドレス、表示名 | ロール（Role）、ランク（Rank）、ステータス（Status） | 登録日、更新日 |
| レビュー | 商品名、投稿者名 | 状態、評価 | 新着順、評価が高い順、評価が低い順 |

カテゴリーおよびブランドのフィルターは、複数選択された場合に同一ファセット（同一分類軸）内ではOR条件として処理します。一括操作（Bulk Action）は、現在表示されているページ内で選択された最大50件のみを対象とし、検索結果全件の一括選択は提供しません。対象データごとに独立したトランザクションで処理を行い、処理成功・失敗の件数および結果を個別に表示します。

## 15. テスト制御（Test Control）

- シードデータの選択、データベースリセット、仮想クロック（Clock）の固定/解除、決済遅延時間（Payment Delay）の擬似設定、システムバージョン表示機能を提供する。
- 実行前には必ず確認ダイアログを表示する。
- 自由入力による任意のデータ直接編集、インポート/エクスポート機能、任意のシステム障害（Fault）注入機能は提供しない。

## 16. 画像管理

- GitHub管理のアセットカタログ（Asset Catalog）から有効（active）な画像を検索・選択する。ローカルファイルからの直接アップロード機能や、外部画像URLの直接入力機能は提供しない。
- 既存商品に関連付けられている廃止（inactive）アセットは「廃止済み」と明示して維持できるが、一度関連付けを解除した後は再選択できない。
- 商品1件に対して関連付けられる画像は最大3枚までとする。1枚目に登録された画像が自動的にメイン画像（Primary）となり、メイン画像を解除した場合は先頭の画像が自動的に新たなメイン画像として再割り当てされる。メイン画像の設定、関連付け解除、表示順序の変更、代替テキスト（Alt Text）の入力は必須とする。
- 廃止されたinactiveアセットは新規登録時の候補一覧には表示しないが、すでに商品へ関連付けられている場合は「現在は選択対象外」と明記した上で継続表示する。
- 画像の読み込みに失敗した場合は、プレースホルダー画像と代替テキストを表示する。
- 画像の並べ替えUIとして、ドラッグ＆ドロップ操作および上下移動ボタンを提供する。
- 新しい画像を追加する手順として、「GitHubリポジトリへ画像ファイルを追加して再デプロイしてください」という管理者向けのヘルプ案内を表示する。

## 実装基盤

- フォーム管理には React Hook Form、スキーマバリデーションには Zod を使用する。
- 共通のストアフロント（Storefront）UIは、React NativeコンポーネントとStyleSheetによるスタイリングを基本とする。
- 管理者向けテーブルやWeb固有のレイアウトは `.web.tsx` と CSS Modules を使用し、テーブルはセマンティックなHTML（`<table>` 等）で実装する。
- ダイアログ、ポップオーバー、コンボボックスなどの複雑なWeb向けウィジェットは React Aria Components の利用に限定し、車輪の再発明となる独自のヘッドレスUI実装は増やさない。
