# Issue #68 Metro 0.84.5 targeted resolution 実装計画

## 0. 依頼概要

- 対象Issue: #68 `security: validate targeted Metro 0.84.5 resolution for image-size vulnerabilities`
- 作業ブランチ: `security/metro-0.84.5-image-size-remediation`
- 背景: Issue #56 / PR #67 で、`image-size@1.2.1` が `metro@0.84.4` 経由で対象2 GHSAにaffectedであり、build / development pathで `Limited exposure` と確認した。
- 目的: Expo / React Native を変更せず、affected Metro pathに必要な最小限の `0.84.5` targeted resolution が安全に成立するかを実装と検証で確定する。
- 期待成果:
  - 成立する場合: current dependency graphから導出した最小のdependency差分でaffected `image-size` resolutionを除去し、Web / Native互換性を確認した状態で採用する。
  - 成立しない場合: candidate dependency差分を残さず、不成立理由と次の候補だけを記録して終了する。

## 1. ゴール / 完了条件

### ゴール

`@react-native/community-cli-plugin@0.86.2` から到達するaffected Metro family pathを実装開始時点のdependency graphで再確認し、対象2 GHSAにaffectedな `image-size` resolutionを除去するために必要な最小限のparent-scoped resolutionを `0.84.5` へ変更できるかを、dependency graphと実際のWeb / Native検証で判定する。

`metro@0.84.5` を採用すること自体をゴールにしない。また、最初から特定のoverride本数を決め打ちしない。baseline graphから必要なresolution setを確定し、採用条件をすべて満たした場合のみdependency変更を残す。

## 2. 現状理解と前提

### Current understanding

以下はlatest `main` とIssue #56 / PR #67のmerged調査結果、およびplan review時のlockfile確認で確認済みの事実である。

- latest `main` はPR #67を含む。
- `package.json` の主要versionは `expo@57.0.16`、`react-native@0.86.2`、`@expo/metro-runtime@57.0.13`。
- `package.json` は既に `pnpm.overrides` を使用し、特定parent配下だけを変更するparent-scoped overrideを複数運用している。
- Issue #56調査時点のaffected resolved `image-size` instanceは1件:
  - `image-size@1.2.1`
  - affected root pathの一つは `@react-native/community-cli-plugin@0.86.2 -> metro@0.84.4 -> image-size@1.2.1`。
- current lockfileでは `@react-native/community-cli-plugin@0.86.2` が `metro@0.84.4`、`metro-config@0.84.4`、`metro-core@0.84.4` を直接解決している。
- current lockfileでは `metro-config@0.84.4` 自体も `metro@0.84.4` を解決している。このため、direct `metro` edgeだけを変更しても別edgeから `metro@0.84.4` が残る可能性がある。
- current graphには別経路としてMetro family `0.84.5` が既に存在し、少なくとも `metro@0.84.5` / `metro-config@0.84.5` / `metro-core@0.84.5` がlockfileに存在する。
- `metro@0.84.5` はIssue #56調査時点で `image-size` dependencyを持たない。
- GHSA-5p2g-fcmc-qvqq / GHSA-w3rx-r6r6-pgpr のaffected rangeはIssue #56調査時点で `<=2.0.2`、patched versionなし。
- production runtime request-time parserは確認されず、affected call pathはMetro build / development pathにある。
- `scripts/validate-native-production-bundle.ts` はAutomation / Production Android Hermes bundleを `expo export --platform android` で生成し、production bundle guardを検証できる。
- `pnpm run build:web` はimage manifest validationを含むWeb exportを行う。
- `pnpm run verify` はformat / Markdown / spec / curriculum / lint / typecheck / image manifest / security static check / tests / Web build / spec buildをまとめて実行する。
- `.github/workflows/native-ci.yml` は `package.json` / `pnpm-lock.yaml` の変更をNative changeとして検知し、Native Static、Android Automation / Production build、Production Bundle Guard、Android Runtime / Maestro、Native iOS CIを起動する。
- `.github/workflows/native-ios-ci.yml` はmacOSでiOS Automation / Production-validation Release buildを行う。
- `native-ci / verify` はNative change時に上記Native gateの成功を要求する。

### Assumptions

- 実装開始時点でも対象GHSAにaffectedな `image-size` pathが残っていること。baseline再確認で既に解消済みならcandidate変更を追加せず、Issue #68の前提変化として記録して終了する。
- 必要なMetro family resolutionはpnpmのparent-scoped overrideで表現できること。baseline graphから必要性を説明できるselectorで成立しない場合、複雑なselectorや別方式を追加せず不採用とする。
- ローカル環境ではiOS Xcode buildを必須とせず、`expo export --platform ios` をpreflightとする。最終採用はPR上のNative iOS CIの実build成功で判定する。

### Non-goals

- Expo / React Nativeのversion変更。
- `@react-native/community-cli-plugin` 自体のupgrade。
- global `metro` / `metro-config` / `metro-core` override。
- direct `image-size` dependency追加。
- `image-size@2.0.2` の強制解決。
- broad `pnpm update` / `pnpm audit --fix` / `pnpm update --latest`。
- custom Metro configによる脆弱call path回避。
- custom Metro fork / patch-package。
- Alert dismiss。
- security scanner / CI設計の変更。
- Issue #68と無関係なdependency cleanup / refactor。

## 5. 変更方針

### Change strategy

1. latest `origin/main` とworking treeを確認しbaselineを固定する。
2. baselineのcurrent graph / GHSA statusを再確認し、affected Metro family edgeを列挙する。
3. affected `metro@0.84.4` をすべて除去するために必要な最小parent-scoped resolution setを編集前に決める。
4. そのresolution setだけを `package.json` に追加する。
5. pnpmのlockfile-only installでlockfileを正規再生成し、同じコマンドを再実行してdiffが安定することを確認する。
6. affected `image-size` instanceが0件であることを確認してからWeb / Native preflightへ進む。
7. ローカル品質ゲートを満たしたcandidateだけをPRへ反映し、Web CI / Mobile App CIを最終採用gateとして確認する。
8. すべての採用条件を満たした場合だけcandidate差分を残す。満たさない場合はcandidate差分を戻し、別方式へscopeを広げず不採用結果を記録する。
