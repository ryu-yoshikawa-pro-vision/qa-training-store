# Issue #68 Metro 0.84.5 targeted resolution 実装計画

## 0. 依頼概要

- 対象Issue: #68 `security: validate targeted Metro 0.84.5 resolution for image-size vulnerabilities`
- 作業ブランチ: `security/metro-0.84.5-image-size-remediation`
- 背景: Issue #56 / PR #67 で、`image-size@1.2.1` が `metro@0.84.4` 経由で対象2 GHSAにaffectedであり、build / development pathで `Limited exposure` と確認した。
- 目的: Expo / React Native を変更せず、affected parentに限定した `metro@0.84.5` targeted resolution が安全に成立するかを実装と検証で確定する。
- 期待成果:
  - 成立する場合: 最小のdependency差分でaffected `image-size` resolutionを除去し、Web / Native互換性を確認した状態で採用する。
  - 成立しない場合: candidate dependency差分を残さず、不成立理由と次の候補だけを記録して終了する。

## 1. ゴール / 完了条件

`metro@0.84.5` を採用すること自体をゴールにしない。採用条件をすべて満たした場合のみdependency変更を残す。

## 2. 現状理解と前提

### Current understanding

以下はlatest `main` とIssue #56 / PR #67のmerged調査結果で確認済みの事実である。

- latest `main` はPR #67を含む。
- `package.json` の主要versionは `expo@57.0.16`、`react-native@0.86.2`、`@expo/metro-runtime@57.0.13`。
- `package.json` は既に `pnpm.overrides` を使用し、特定parent配下だけを変更するparent-scoped overrideを複数運用している。
- Issue #56調査時点のaffected instanceは1件:
  - `@react-native/community-cli-plugin@0.86.2 -> metro@0.84.4 -> image-size@1.2.1`
- `metro@0.84.4` のcurrent parent constraintは `^0.84.3`。
- current graphには別経路として `@expo/metro@56.0.2 -> metro@0.84.5` が既に存在する。
- `metro@0.84.5` はIssue #56調査時点で `image-size` dependencyを持たない。
- GHSA-5p2g-fcmc-qvqq / GHSA-w3rx-r6r6-pgpr のaffected rangeはIssue #56調査時点で `<=2.0.2`、patched versionなし。
- production runtime request-time parserは確認されず、affected call pathはMetro build / development pathにある。
- `scripts/validate-native-production-bundle.ts` はAndroidのAutomation / Production Hermes bundleを `expo export --platform android` で生成し、production bundle guardを検証する。
- `pnpm run build:web` はimage manifest validationを含むWeb exportを行う。
- `pnpm run verify` はformat / Markdown / spec / curriculum / lint / typecheck / image manifest / security static check / tests / Web build / spec buildをまとめて実行する。

### Assumptions

- 実装開始時点でも上記affected pathが残っていること。baseline再確認で既に解消済みならcandidate変更を追加せず、Issue #68の前提変化として記録して終了する。
- `@react-native/community-cli-plugin@0.86.2>metro` はpnpmのparent-scoped overrideで直接限定できること。実際のlockfile regenerationで成立しなければ複雑な代替selectorを追加せず不採用とする。
- iOS native Xcode release buildは実行環境に依存するため、cross-platformで実施可能な `expo export --platform ios` を最低限のMetro production互換性validationとする。macOS / repository CIで既存のiOS release buildが実行可能なら追加で実施する。

### Non-goals

- Expo / React Nativeのversion変更。
- `@react-native/community-cli-plugin` 自体のupgrade。
- global `metro` override。
- direct `image-size` dependency追加。
- `image-size@2.0.2` の強制解決。
- broad `pnpm update` / `pnpm audit --fix` / `pnpm update --latest`。
- custom Metro configによる脆弱call path回避。
- custom Metro fork / patch-package。
- Alert dismiss。
- security scanner / CI設計の変更。
- Issue #68と無関係なdependency cleanup / refactor。

## 5. 変更方針

### Change strategy

1. latest `origin/main` とworking treeを確認しbaselineを固定する。
2. baselineのcurrent graph / GHSA statusを再確認する。
3. Repository既存方式に合わせ、affected parentにだけMetro 0.84.5を適用する。
4. pnpmでlockfileを正規再生成し、affected `image-size` pathが0件になることを最初に確認する。
5. dependency graphが期待どおりの場合だけWeb / Native compatibility validationへ進む。
6. すべての採用条件を満たした場合だけcandidate差分を残す。
7. 1つでも採用条件を満たさない場合はcandidate差分を戻し、別方式へscopeを広げず不採用結果を記録する。

### 実行タスク

- [ ] 1. branch freshness / baseline / Runを確定する。
  - `git status --short` がcleanであることを確認。
  - `git fetch origin`。
  - `git rev-parse HEAD` / `git rev-parse origin/main` / `git rev-list --left-right --count origin/main...HEAD`。
  - branchがbehindなら最新`origin/main`を安全に取り込み、その後のHEADをbaseline SHAとする。
  - latest mainを安全に取り込めない場合はBlocker。
  - Repository標準で新規Runを初期化する。

- [ ] 2. baselineのIssue #68前提を再確認する。
  - `pnpm install --frozen-lockfile --ignore-scripts`。
  - `pnpm why image-size`。
  - `pnpm list image-size --depth Infinity --json`。
  - `pnpm why metro`。
  - `pnpm view metro@0.84.4 dependencies --json` / `pnpm view metro@0.84.5 dependencies --json`。
  - 2件のGitHub Advisoryを再確認し、affected range / patched versionに変化がないか記録。
  - affected pathが既に消えている場合はcandidateを追加せず、Issue前提変化として終了する。

- [ ] 3. parent-scoped Metro overrideを追加する。
  - `package.json` の既存 `pnpm.overrides` に次の1件だけ追加する。

    ```json
    "@react-native/community-cli-plugin@0.86.2>metro": "0.84.5"
    ```

  - Expo / React Native / community-cli-plugin / image-size等、他versionは変更しない。
  - global `metro` overrideを追加しない。

- [ ] 4. lockfileをpnpmで正規更新し、dependency remediation成立性を先に確認する。
  - lockfileを手編集しない。
  - pnpm 9.10.0でlockfileを更新する。
  - 更新後 `pnpm install --frozen-lockfile --ignore-scripts` が成功することを確認。
  - `pnpm why image-size` / `pnpm list image-size --depth Infinity --json` で対象GHSA affected instanceが0件であることを確認。
  - `pnpm why metro` でaffected parentが`metro@0.84.5`へ解決されていることを確認。
  - `metro@0.84.4` / `image-size@1.2.1` が他pathに残る場合は、対象GHSAとの関係を確認する。affected resolutionが残る場合はcandidate不採用。
  - baselineとの差分を確認し、unrelated package version / integrity / dependency edge / importer / actual peer resolution / snapshot semanticsの変更があればcandidate不採用。

- [ ] 5. Web / asset compatibilityを検証する。
  - `pnpm run validate:image-manifest`。
  - production環境変数で `pnpm run build:web`。
  - `dist/index.html` が生成されることを確認。
  - Metro / asset resolver error、missing asset、manifest mismatchがないことを確認。

- [ ] 6. Android production bundle compatibilityを検証する。
  - `pnpm run validate:native-production-bundle`。
  - Automation / Production Android Hermes bundleの生成が成功することを確認。
  - Production bundle guardがPASSすることを確認。

- [ ] 7. iOS Metro production compatibilityを検証する。
  - production環境変数で `pnpm exec expo export --platform ios --output-dir output/issue-68-ios-production` を実行する。
  - Metro resolution / asset bundling errorなくiOS exportが完了することを確認。
  - macOS / existing CI entry pointで `pnpm run build:native:ios:release` が実行可能な場合は追加で実行する。
  - macOS native buildを実行できない環境では、未実施理由をRun Artifact / PRへ明記し、iOS Metro export結果と区別する。

- [ ] 8. Repository品質ゲートと回帰を確認する。
  - `pnpm run verify`。
  - Web bundle変更のruntime回帰として `pnpm run test:e2e:chromium`。
  - PR作成後、Repository CIのrequired checksを確認する。
  - dependency reviewがtargeted remediation自体を新規vulnerabilityとして拒否していないことを確認する。

- [ ] 9. 採用 / 不採用を確定し最終scopeを検証する。
  - 採用条件をすべて確認する。
  - 採用の場合:
    - `package.json` / `pnpm-lock.yaml` のtargeted差分を残す。
  - 不採用の場合:
    - candidateの`package.json` / `pnpm-lock.yaml`変更をbaselineへ戻す。
    - 別override / upgrade / fork等を追加しない。

  - `git diff --check`。

- [ ] 10. Run Artifactを最終化する。
  - PLAN / TASKS / REPORT / 必要なrun.jsonに採用 / 不採用結果を記録。

  - plan-onlyでは`docs/reports/`を追加しない。実装RunでもPRとRun Artifactで十分に結果を再確認できる場合は新規durable reportを作らない。

## 7. リスクと未解決論点

### Risks

- semver range上は`0.84.5`を許容しても、React Native / Metro間の実動作互換性が保証されるとは限らないため、Web / Android / iOS bundle実行で確認が必要。
- pnpm overrideでexpected Metroだけでなく別dependency pathまで変更すると、targeted remediationの範囲を超える。
- lockfile regenerationがmetadata以外のunrelated graphを動かす場合、そのまま採用するとscope creepになる。
- Web buildだけで判断するとNative Metro compatibilityを見落とす。
- Android validationだけでiOSを安全とみなすとplatform差を見落とす。
- iOS `expo export` はMetro bundle互換性の確認であり、Xcode native compile成功の完全な代替ではない。
- Dependabot AlertのFixed判定は通常merge後のdefault branch再評価になるため、PR branchでAlertがopenのままでもgraph検証と混同しない。

### Open questions

blocking open questionはない。

実装時に新たな互換性問題が出た場合は、同じRunで代替方式を試行せず、不採用理由として記録する。
