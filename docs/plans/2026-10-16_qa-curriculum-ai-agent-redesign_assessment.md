# 知識確認・実技・修了基準の設計

## 基本方針

知識、実際の操作、判断力のそれぞれに**異なる確認方法**を適用する。既存の`C01〜C12`と追加予定の`C13`に対するLevel 2を最終目標とする。クイズが高得点でも、実技の期待結果が誤っていれば合格しない。逆にPlaywrightが偶然PASSしていても、仕様・Assertion・実行証拠を説明できなければ合格しない。

既存の`scripts/training/check-completion.ts`は`validateSelfChecks()`でレッスン別Markdownの存在・非空を確認し、`semantic_understanding: "NOT_EVALUATED"`を返す。この契約は**意味を機械採点しないという事実**を正しく表している。受講者が自己採点した知識テストの結果や、講師レビューの記録とCompletion Receiptを混同しない。

## 1. 学習項目ごとの達成水準

[学習項目表](./2026-10-16_qa-curriculum-ai-agent-redesign_learning-map.md)に記載した「説明」「適用」「判断」を以下のように評価する。

| 到達 | Level 2で必要な能力 | 知識クイズ | 実技の要否 |
| --- | --- | --- | --- |
| 説明 | 概念の役割・制約を他の概念と区別し、理由を説明できる | 選択肢から正しい意味・誤りの理由を選べる | その項目に実際の操作を要求しない限り不要 |
| 適用 | 指定した条件に対し仕様・手順・技法を用いて正しい結果を導く | 具体的な事例・コード・データの結果を選べる | `training/`の演習・CSV等で実際に適用できる |
| 判断 | 正本・実行証拠・範囲・コストの制約から妥当な採否を説明する | 一意の根拠がある場面で適切な判断を選べる | 複数解がある題材では採用/却下と理由を成果物に記載する |

Level 1は教材・例・ヒントをなぞって達成、Level 3は代替案とトレードオフを比較した改善提案ができる段階。**C01〜C13のLevel 2を満たすために、Level 3の抽象化や全Skillの理解を要求しない**。

## 2. 確認クイズの合格基準

- 対象：17レッスンすべてにクイズを設ける。Native選択（P1-07/P2-06）は選択者だけ対象。
- 実施：説明と該当する演習を行ってから回答する。**初回回答は本人が行い、AIに解答そのものを作らせない**。教材と正式仕様は参照してよい。質問文で引用した仕様は特定revisionのもの。
- 記録：問題ID、初回の選択肢、正誤、誤った項目ID、解答との照合、復習先、再確認結果を既存の`self-check/<Lesson ID>.md`へ記す。新しい受講者DBは作らない。
- レッスン別の初回到達目安：**正答率80%以上**。これは教育設計上の初期基準であり、実測データから導いた数値ではない。数が少ないレッスンでは`ceil(問題数×0.8)`問以上とする。
- **学習上の必須項目は未理解のまま通過させない**。80%以上でも誤答した必須項目があれば該当説明を復習し、**異なる条件の別問または短い理由説明**で正しく確認できるまでその項目は未達成とする。間違えた同じ選択肢を単純暗記して採点し直さない。
- 初回80%未満なら復習と再確認を行う。初回結果は消さず、最終到達と別に残す。環境や利用時間の制約による未受験はFAILと捏造せず未実施とする。
- すべての必須学習項目で理解確認が済んだ時に知識確認は完了。**正答率だけでは修了不可**。実技成果物の判定へ進む。

80%という数値は設計上の案であり、初回試行で問題の難易度が不適切だった場合は、評価基準を恣意的に甘くするのでなく問題文・選択肢・解説・前提教材を検証して見直す。変更した時点の問題と正答を履歴で追えるようにする。

### 問題ごとの合否判定

**正答のみを採点し、個々の選択肢の説明文の丸暗記は求めない**。ただし受講者が実技・判断系の誤答をした場合には、誤答の理由を自分で説明できる状態を再確認する。選択肢が2つ以上正しく解釈できる問題は作問不備として採点から除外し、修正後の問題で確認する。

## 3. 実技・判断の評価

各実技演習は、以下の観点を本人または講師が成果物から確認する。**該当する観点をすべて満たすことがLevel 2の条件**であり、平均点で重大な不足を隠さない。

| 観点 | Level 2として必要な条件 | 根拠 |
| --- | --- | --- |
| 仕様と期待結果 | 対象のBR/ACに合致し、仕様と観測・仮説を混同していない | `docs/spec/`、Workbook |
| リスクとテスト設計 | Risk→Condition→TC→Assertionが一貫し、除外した条件に理由がある | 既存4 CSV、受講者説明 |
| 実装・再現性 | 許可された場所の本人作成/採用コードで、Reset、Locator、意味あるAssertionが成立する | `training/playwright/`、差分、実行証拠 |
| 実行・失敗分析 | 対象Runの成功・失敗・未実行、原因仮説、修復後Runを区別する | Receipt、Trace、ScreenShot、ログ |
| 安全性・変更範囲 | 不要な製品・正式CI・秘密情報への変更なし。変更差分を説明できる | `git diff`、Training Copy |
| PR・CI（Part 2） | 対象SHAに紐付く実際のRun/Check/Artifactで検証し、権限・品質ゲートを説明できる | GitHub PR、Training CI |
| AI成果物の採否（C13） | 具体的な作業依頼、実際に使ったSkillまたは使わなかった理由、提案された内容、本人による採用/修正/却下と根拠がある | 対象成果物、self-check、実行ログ・差分 |

各レッスンの実技採点は[Scenario Shop演習・テスト対象設計](./2026-10-16_qa-curriculum-ai-agent-redesign_target.md)のE1〜E6で実施する。レッスンのすべてで新しいE2E specを作らせない。

C13に関しては、次の**不合格条件**が明白である。
- AIを使っていないのに、実行したと記録した。
- AIに生成させた期待結果の正本照合・採否判断がなく、本人が意味を説明できない。
- AIが「PASS」と答えただけで、対象Run/Receiptが未確認。
- 許可していない製品コード・正式回帰・Secretへの変更を本人が確認せず採用した。
- 診断・保守の初回と改善後を同じEvidenceで済ませた。

AIのモデル名が変わった、AI案が最初から正しかった、全22 Skillを呼び出さなかった、という理由だけでは不合格にしない。

## 4. 各段階の修了判定

| 段階 | 知識確認 | 実技・成果物 | 共通課程の修了基準 |
| --- | --- | --- | --- |
| 各レッスン | 対応項目の確認クイズを受験し、誤答した必須項目を再確認した | 該当Lessonの演習・自己確認・理由説明が完了 | 当該レッスンの学習項目に未達成がない |
| Part 1共通 | P1-01〜P1-06・P1-08・P1-09で知識確認済み | E1/E2の設計、E1の実装と実行、E3の診断、E4の保守、C13のAI利用の説明 | 現行`C01〜C07+C09〜C10`＋`C13`のLevel 2 |
| Part 2最終共通 | P2-01〜P2-05・P2-07・P2-08で知識確認済み | Part 1成果物を使ったPR、対象SHAのTraining CI、総合品質判断、C13の追加評価 | 現行`C01〜C07+C09〜C12`＋`C13`のLevel 2 |
| Native選択 | P1-07・P2-06のクイズ（選択者のみ） | Android実行等の選択経路に必要な成果物 | `C08`を別に確認。iOS Runtimeを要求しない |

**「クイズのみPASS」「Completion ReceiptのみPASS」「自己確認Markdownの存在のみ」「baselineのみPASS」はいずれも修了の十分条件ではない**。

既存の`check-completion.ts`が確認できるものは提出物・ID・Evidence/Receiptの整合性であり、クイズと実技の意味的な正誤判定ではない。既存Receiptの`semantic_understanding: "NOT_EVALUATED"`を、クイズを追加しただけで`PASS`等に書き換えない。修了の最終判断は、公開された基準に基づいて受講者自身の自己評価または講師の確認記録で行う。講師の非公開情報を合否条件にしない。

## 5. 受講者が何を記録するか

既存`handoff-root/self-check/P1-03.md`などに、次の形式で記録できればよい。新しい専用アプリ・データベース・機械学習採点は必要ない。

```md
## 知識確認
- 対象クイズ: P1-03
- 問題IDと初回回答: P1-03-Q01=C, P1-03-Q02=A, ...
- 初回正答率: 5/6
- 誤答と復習: P1-03-Q03 / P1-03-K03 / 「状態遷移」の節を復習
- 再確認: 異なる状態条件を用いた問題に回答し、前後状態と理由を説明済み
- 知識確認: 完了（未達があれば未完了）

## 実技と判断
- 対象: TC-CART-101
- 仕様と採用理由: ...
- AIの依頼と提案: ...
- 採用・修正・却下と根拠: ...
- 実行・差分の証拠: ...
- 実技判定: Level 2 / 未達と理由
```

上記の回答例（`5/6`など）は**書式例**であり実績ではない。AIとの全会話、内部推論、APIキーやSecret、受講者個人のプライベート情報は記録しない。判定が難しい場合は講師の補足確認を許すが、公開ルーブリックにない基準を後出ししない。

## 6. 不合格・未実施・環境障害の区別

| 状態 | 例 | 次の対応 |
| --- | --- | --- |
| 知識未達 | 複数の選択肢を区別できない、期待結果を誤解 | 該当する学習項目・仕様へ戻り、別条件で再確認する |
| 実技未達 | Assertionが弱い、Root Causeを証拠で示せない | 対象TC・Run・コードを確認し、改善後の別実行 |
| 未実施 | クイズ未回答、E2E未実行 | 未実施として記録し、必要な課題を実行 |
| 環境障害 | OpenCodeの認証/無料枠、ブラウザ不可、権限不足、CI未準備 | `BLOCKED`と記録。課題の理解不足と混同しない |

AI利用料金・Codespaces料金・個別のモデル仕様は変化し得るため、環境が用意できない場合に「利用したことにする」記録は認めない。

## 7. 採点・テストの受入条件

Codex実装時の検証は以下をすべて満たす。

1. 全17レッスンに学習項目、説明への参照、確認クイズ、正答・解説、復習先、実技または実技不要の理由が揃う。
2. 共通/選択を区別し、**共通58項目が選択Nativeの前提なしに評価可能**。
3. 正答の根拠・誤答の理由・前提条件に論理的な矛盾がない。仕様・金額・数量・CIのSHAなど重要な問題は独立に検算・検証する。
4. 正解が複数、正解がゼロ、問題中で正解を漏らす、学習前に必要知識を参照できない問題は採用しない。
5. 各自己確認で初回結果、誤答、復習、再確認、実技の合否を追える。ただし環境・個人情報の記録を必要以上に強制しない。
6. 既存Completion Receiptの出力・意味・Training Copyの隔離・正式製品のCIに回帰がない。
7. 改訂後の受講者導線をP1→P2で通し、**知識確認だけで実技へ進めなくなる誤判定**や、自己採点の合格を機械的な実行証拠へすり替える設計がない。
8. 問題数や80%基準を修正する必要が判明した場合は理由・変更前後・検証結果をPlanへ戻して説明する。検証失敗を隠すために基準を緩めない。

## 未実証事項

このPlanは**採点基準の設計**であって、問題・選択肢の難易度が適切であることを実受講者で検証した結果ではない。正式な教材を使った試行で、誤解しやすい問題、解説不足、必要時間を確認し、同じ基準のまま改善できるものは問題側を改善する。実測前の完了率や合格率を記載しない。
