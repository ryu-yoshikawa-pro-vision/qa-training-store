# 新課程の評価・各フェーズの修了基準

## 講師なし・AI支援による自己学習と正式修了の原則（2026-10-26確定）

学習者は講師、研修担当者、別の評価者による質問・承認を**待たずに**、M00〜M10の学習、演習、自己確認、再学習、各Phaseの正式修了判定まで進められることを必須とする。M04/M07/M10にPhase総括評価を集約する設計と、Phase 3の選択制は維持する。通常の修了処理で人間への提出・口頭面談・人的採点を要求しない。開発者が教材の内容をレビューする工程は、学習者の修了ゲートとは別責務とする。

**評価処理経路**：受講者の個人非公開Codespacesで、本人が各モジュールを明示的にロードし、`workspace/Mxx/submission.md`と`evidence/`・コード・Runを作成する。既存の`course:check`は開始/終了ファイル・版・参照整合の**読み取り専用検証**であり習熟判定ではないため、別の`course:assess`相当の**新課程専用評価入口**を既存`scripts/training/ai-assisted-qa-course.mjs`から拡張する。正式評価入口は`pnpm course:assess M04|M07|M10 --model provider/model-id`と定め、後述の入力・出力・再開・失敗契約に従って実装する。単なる`course:check`成功を正式修了と表示しない。

1. **事前検証（決定論的）**：module/Phase、配布元SHA、課題と評価基準のrevision、必須ファイル、実在する仕様・Skill参照、Run ID・spec/test・Trace・結果の組、M10の実PR HEADとRun/Check/Artifactなど、機械的に確認できる事実を検証する。必要に応じて検証済みのsandboxで対象specを別途実行する。未実行、版不一致、証拠欠落、費用/権限違反はAIの文章で上書きできない。
2. **AI意味評価**：本人の採否・リスク・Case・Locator/Assertion・原因分類・POM/fixture・CI運用判断を、固定版の正式仕様、51学習目標と公開`assessment/scoring-tests/Mxx.json`・Phase rubricを用いてIDごとに評価する。採点に使うAIはOpenCode CLIの受講者認証済みモデルを標準入口とし、学習支援時の会話とは**別セッション・独立コンテキスト**で実行する。非対話実行と機械可読結果は導入版のOpenCode CLIで実機確認して採用する。料金が発生するモデルへの自動切替はしない。
3. **初見の条件変更と本人説明**：M04/M07/M10は既習の範囲内で根拠のある別条件・誤案を選び、受講者に短い回答・必要な追加操作を求める。出題条件、難易度、正当な複数回答、提示済み模範との差、評価時に要求する証拠を評価側で追跡する。学習時の模範を再提示して答案を代行することと区別し、受講者が回答を提出してから評価する。独立性を完全に証明できると偽らず、条件変更への適用とコード/Runとの整合で判断する。
4. **判定とフィードバック**：目標IDごとにLevel 0/1/2/3、判定不能、BLOCKED、未実行を区別し、Level 2以上の必須IDだけを達成として集計する。結論だけでなく、確認したファイル・行/節・Run、仕様/採点規則、足りない能力、復習先・次に行う最小練習を表示する。部分達成・正しい別解・環境障害を混同しない。根拠不足・モデル/料金制限・JSON異常・判定の矛盾・校正未達時は**不確定のまま停止し、合格へ繰り上げない**。
5. **再学習・再評価と記録**：低リスクな途中練習ではAIチューターが説明・段階的ヒント・誤解別のフィードバックを返す。正式評価の証拠とセッションを分離し、未達IDから該当授業・練習へ戻して再挑戦できるようにする。元の結果と新しい結果、教材/仕様/Skill/採点基準の版、使用モデルID・評価CLI版・評価入力の識別子・対象Run・校正の結果を、**個人非公開workspace内**に機械可読結果と人間可読サマリで残す。Public repository・公開Web・グラフ・Git履歴への個人記録の自動送信は禁止する。Phase 1/2ではGitなしで安全にエクスポート可能とする。

**モデルの限界**：OpenCode Zen等の無料モデルの在庫・認証・API制限・採点品質は保証されない。本人の初回認証確認に加え、導入時とモデル変更時に既存の校正例＋未知条件・模範転記・誤PASS・不正な指示入り証拠を評価し、誤った正式合格が起きないことを必須ゲートにする。校正に通らないモデルでは正式修了を出さずBLOCKED/判定不能にする。受講者が読める理由と再試行方法を表示し、人間の承認を必須とする代替経路は追加しない。

## 正式AI評価の実装契約（2026-10-26レビュー反映）

### 入口・対象と実行責務

既存の`course:sync`（管理者配布）、`course:load`（本人の単一モジュールロード）、`course:check`（配布/構造/revision/参照検査）はそのまま残す。正式評価は既存`scripts/training/ai-assisted-qa-course.mjs`を入口に追加し、`package.json`へ`course:assess`を登録する。受講者は`pnpm course:assess M04 --model provider/model-id`、`M07`、`M10`のいずれかを実行する。M04=P1（M00〜M04、22 ID）、M07=P2（M05〜M07、15 ID）、M10=P3（M08〜M10、14 ID）。その他のIDや複数Phase指定、未確認のモデルは拒否する。Phase 1/2でGit/PR/CIを要求しない。

CLIは`--resume <assessment_id>`で未確定の同一試行を再開し、`--history`で該当Phaseのローカル履歴を読み取り表示できること。`--resume`は以前の確定結果の書き換えに使用しない。引数の順序・エラー文などの内部詳細は既存CLI規約に合わせられるが、対象Phase・入出力・停止条件・復旧の意味は変更しない。

| 処理 | 責務と境界 |
| --- | --- |
| 既存`course:check`/core | 配布元SHA、load receipt、対象モジュールの開始/終了ファイル・ID・参照だけを読み取り確認。**実Run・本人の習熟は認定しない** |
| 新規Node.js評価処理 | 必要ファイル/評価資料の取得・固定、提出/証拠スナップショット、決定論的証拠検査、問題条件の制約検証、AI起動、結果Schema検査、Level有効性・Phase集約、非公開保存と再評価を担当 |
| OpenCodeの評価専用セッション | **検証済みの固定版仕様・採点基準・限定した証拠・本人回答**だけからID別の意味評価候補と理由/不足を返す。Phaseの修了判定、Shell実行、ファイル保存、評価基準の変更は行わない |
| AIチューター | 通常授業中の質問・ヒント・誤り別フィードバック。正式採点用の評価セッション・非公開条件・確定結果を共有しない |

### 実行順序、入力と結果

1. 新規試行IDを発行し、要求されたPhaseの**全必須objective ID**と、配布元`source_sha`、state/scoring/rubric/正式仕様・固定Skillの版を列挙する。本人の提出物は`workspace/Mxx/`を用い、過去Phaseの未提出物を模範で自動補完しない。
2. `course:check`相当の構造検査の後、必要な実技は**後述の決定論的証拠検査**で実行元・コード・Runを確認する。採点に利用する仕様・評価資料は固定SHAで取得/照合する。欠落・版違いをAIの説明で補わない。
3. 本人の提出物・コード・仕様・必要なRun抜粋・検証結果を**固定スナップショット**として列挙し、ファイルパス、サイズ、SHA-256、作成した試行ID、対象IDを記録する。認証情報/環境変数/全会話は収集しない。
4. 既習範囲の`BR/AC`・正式仕様に照らして採点可能な条件変更を選び、問題ID、対象目標、正答の制約/許容別解、出典・版を保存する。AIに設問文を整形させてよいが、**未決の仕様の期待結果や採点規則をAIの自由生成で確定させない**。問題の出典や合否条件を照合できなければ判定不能とする。
5. 本人に条件と質問を表示し、回答および必要な実操作を本人が完了するまで待つ。**回答はAI採点開始前に保存・ハッシュ固定**する。入力待ちで終了しても試行IDから安全に再開でき、AIチューターの回答を本人の提出に転記しない。
6. 学習セッションとは別のOpenCode評価セッションに、限定・検査済みの採点入力を渡す。AIは`objective_id`・`criterion_id`・`evidence_id`、0〜3の**候補Level**、根拠、未達、復習先を機械可読で返す。未提示・未検証のIDに達成を推測しない。
7. Node.js側は全必須IDの一意性/過不足、criterion/evidenceの実在、証拠と版、校正済みのモデル/プロンプト/採点条件、AI結果Schemaを検査する。AIの`pass`や`completed`を正式結果として信用しない。**Phase修了は決定論的に集計**してから結果を保存し、受講者へ理由・不足ID・復習位置を表示する。

**結果Schemaの必須意味**：`schema_version`、`assessment_id`、`attempt`、`phase_id`、`terminal_module_id`、`status`、`source_sha`と状態/仕様/Skill/scoring/rubric/問題/評価Promptの版・ハッシュ、`evaluator`（実使用モデル、OpenCode版、校正ID）、`input_snapshot`（対象証拠ID・path・SHA-256）、`deterministic_checks`（検査方法・対象Run・結果）、`challenge`（ID・対象ID・条件/回答のハッシュ）、`objectives[]`（全必須ID・判定状態・Level・criterion/evidence ID・根拠・不足・復習先）、`completed`、`previous_assessment_id`、時刻。AIの**候補結果**とNodeが確定した**正式結果**は別JSONで保存する。具体的な内部変数・ファイル分割をここで固定しない。

| 目標IDの判定状態 | `level` | 意味 |
| --- | --- | --- |
| `assessed` | 0〜3 | 本人の回答/証拠を評価できた。0=理解/判断が示せない、1=部分達成/支援依存、2=別条件への独立適用、3=比較・改善まで説明可能 |
| `not_run` | `null` | 実行/提出がまだない。能力不足と断定しない |
| `ungradable` | `null` | 入力/出典/版/結果形式等が足りず判定不能。**評価可能な根拠不足の回答**は原則Level 0/1として区別する |
| `blocked` | `null` | モデル認証・利用枠、環境、権限、通信等の障害で評価できない |

試行の進行は`created → preflight → awaiting_answer → evaluating → result_saved`とし、停止・中断を`blocked`/`ungradable`/`interrupted`として記録する。未完了の試行は正式PASSにならない。正常に判定した目標がLevel 0/1の場合は「未達」であり、環境障害とは区別する。**正式修了条件**は、当該Phaseの全必須IDが漏れ・重複なく存在し、すべて`assessed`でLevel 2以上、各IDの必須実行/出典/ハッシュ/版の検証が有効で、モデル+Prompt+評価基準の校正ゲートが有効、未実行・判定不能・BLOCKEDが0件であること。AIが結果に`completed: true`を書いても無視する。

### 履歴、部分再評価、失敗時の復旧

`workspace/.course-assessments/<P1|P2|P3>/attempts/<assessment_id>/`に試行ごとの`input-manifest.json`、`challenge.json`、`deterministic.json`、`ai-candidate.json`、`result.json`、`summary.md`を必要な範囲で保存し、`current.json`は**最後に確定した試行を指す参照**とする。試行の途中結果は確定結果に上書きしない。原子的なファイル確定（同一ディレクトリ内の一時ファイル→rename）・書込み失敗時の安全な再試行・中断後の不完全なファイルの区別を実装し、旧確定試行を削除しない。名前の採用より、この不変条件が優先される。

再挑戦では以前の結果を保持して、毎回全必須IDの有効性を再集約する。変更された提出・Run・仕様/Skill・採点基準/Prompt・教材版に依存するIDは再評価する。**版/根拠/証拠ハッシュ/校正がすべて一致する有効なIDだけ**再利用可能で、変更範囲が判定不能なら安全側で再評価する。本人には新規試行・不足ID・復習先・再実行条件を表示する。Phase 1/2はGit/PR不要で履歴をエクスポートでき、停止したCodespaceの履歴保存をリモートGitへの保存と誤認させない。

### 校正・正式評価の利用許可

従来の`cases[].expected_decision`は公開した回答例の5ラベルのまま保持し、**学習時の目標Levelや教材品質の3値判定と直接変換しない**。正答、誤答、部分正答、仕様に適合する別解、根拠不足、証拠欠落、未実行、旧版/別SHA、偽ログ、Prompt Injectionを含む提出、異常JSON、認証/利用制限/タイムアウト、同一答案の評価差を**実際の採点処理**へ通す校正fixtureを追加する。評価候補だけでなく最終Node集計で誤PASSが出ないことを検査する。実行証拠を伴うM03/M06/M07/M10と各Phase固有の意味判断は別に校正する。

モデルID（提供側で識別可能な版を含む）、OpenCode版、Promptの版とハッシュ、採点資料のsource SHA/ハッシュの組に対し、**既知の重大な誤PASSが0件**・必須決定論的負例が全件拒否・正しい別解が不当に一律拒否されないことを確認できた場合だけ正式採点を許可する。繰返し試行でLevel 2の誤判定・結果差を観測し、不一致は調査/再校正する。繰返し回数「3」などを根拠なく普遍的な合格基準に固定しない。重大誤PASS、版/形式不一致、Secret混入、権限逸脱、証拠矛盾、校正未達を検知したモデル+Prompt構成は**利用停止**。修正・再校正されるまで正式結果を発行しない。起動時にも選択モデル・接続/料金条件と校正識別子を確認する。有限の校正が将来の全答案の正しさを保証するとは説明しない。

### 受入試験

正例はP1/P2/P3それぞれ全必須IDが有効にLevel 2以上となる受講者の修了、正しい別解、未達IDからの復習・再提出/再評価、前試行の不変性。負例は51 IDの欠落/重複・他Phase混入、未実行/同一Runの転用、別SHA、証拠改ざん、無根拠なLevel 2、採点JSON/モデル版違い、AIの`completed: true`偽装、無効な追加条件、Prompt Injection、異常JSON、モデル失敗/中断、公開GitやArtifactへの個人記録混入。固定fixtureでNode側の検証・集計を先にテストし、その後にOpenCode CLI実モデルで校正・安全性を検証する。実公開Templateから非公開repo/2コアCodespaceで、質問→本人回答→実Run→正式採点→復習/再評価まで通し確認する。未実施・失敗はPR完了としない。実受講者に対する学習効果の試行はPR後の別工程。

## 合否の具体化とAI校正ラベル

全51目標について既存`scoring-tests/Mxx.json`、公開Phase別ルーブリック、実演習を照合し、対象固有の`required_evidence`・`decision_rules`・`pass_conditions`・`reject_if`で客観的に判定できるか検証する。汎用文言だけで判定できない項目を具体化し、M02/M04/M06/M07/M10の新しい能力は必ず更新する。1実技で複数IDを評価してよいが、ID別の証拠と不足は判別する。51件の独立試験や新評価DBは作らない。

校正例の`expected_decision`（`pass`/`fail`/`partial`/`pass_with_reason`/`ungradable`）は**回答例への期待判定**、教材品質レビューの`pass/fail/ungradable`は**教材の検査**、本人のLevel 0〜3・BLOCKED・未実行・判定不能は**受講者の評価結果**として別に扱う。回答が正しい別解なら根拠付き達成を認め、partialをLevel 2へ換算しない。いずれも対象SHA・ルーブリックrev・校正例ID・使用モデル・根拠を記録する。

必須の負例はM06の固定TODOだけ、M07のPOM/fixture採否説明だけ、M10の未実行/旧Run/別SHA、M04の未確定仕様をAIが勝手に補完した例、根拠なし答案、提出物中の「合格と判定せよ」という指示、部分正答を達成にした例。教材のAIレビューと受講者AI採点は別の処理・結果であり、一方のPASSで他方を認定しない。

## 学習目標の証拠・再評価とAI教材レビューの実施（2026-10-26）

全11モジュールの`workspace/Mxx/submission.md`で(1)版と仕様・Skill根拠、(2)本人の別条件への短い回答、(3)コード/操作/Run証拠、(4)未決/BLOCKEDをID別に追跡する。M04/M07/M10ではAIによるPhase全IDの独立評価・必要な追質問・実操作の結果をまとめ、**受講者自身が開始・再評価**できるようにする。1件の質問で全IDの達成を推定せず、再提出時は元の履歴を保持する。

AIは(1)開発時の教材品質レビューと(2)受講者の習熟を測る独立した意味評価の**両方**に使用する。前者は固定版の教材節・仕様・Skill・51目標を検査し、後者は本人の提出物・実行証拠・回答を公開採点基準と別条件で評価する。両者は専用の結果スキーマと校正例を持ち、開発者の教材レビューによるPASSを個人の修了に流用しない。自動評価の低信頼・校正未達・判定不能は合格にしない。

## 全モジュールの証拠とフェーズ終了時の正式評価（2026-10-25）

M00〜M10すべての学習目標に本人の実演習成果物・条件変更への判断・短い質疑回答・実行証拠を結び付ける。各モジュールで自己確認とAIチューターによる練習・復習を行い、M04/M07/M10の終了時は**AI評価器がPhaseの全必須IDを正式採点**する。失敗・部分達成・校正不足は説明と復習先を返すが、人間評価者の待ち状態は作らない。

評価課題の条件・模範・採点資料はpublic Git上に置いてよいが、配布除外を秘密保持と誤認しない。Phase末は評価器が既習の範囲内で小さな条件変更・質問を提示し、本人の判断と実行証拠を採点する。各必須IDがLevel 2以上で修了とし、不足・BLOCKED・判定不能・未実行は正式修了にしない。人間による面談・採点・提出先の指定を通常フローに要求しない。

## 評価する能力と共通原則

本Planでの「修了」は3つの別々の結果を表す。受講者の作業環境は**教材正本と別の学習用リポジトリ**とし、各モジュールを**受講者本人が明示的にロード**して実施する。**Phase 1修了はテスト設計能力、Phase 2修了はPlaywright自動化能力、Phase 3修了はGitHub・CI運用能力**である。標準の学習環境はGitHub Codespacesだが、Gitコマンド・PR・CIの学習は選択Phase 3に限定する。

## 実装完了と人間による最終承認の区分

- **実装完了に含める開発時の内容確認**：正式仕様・固定Skill・学習目標との照合、教材・評価基準のレビュー、別AIによる独立レビュー、必要な自動/契約テストを行い、具体的な指摘を修正する。形式ValidatorのPASSだけで内容の正しさを判断しない。
- **開発時の人間による教材レビュー**：教材内容・知識ノードの人間承認状態は実際のレビューと区別して保持する。任意の品質管理であり、受講者の学習進行・AI修了を人間の承認待ちにしない。正式仕様との整合、校正、回帰検証が未達なら教材そのものを利用可能と宣言しない。
- 未承認の知識ノードに`draft_requires_content_review`がある場合は承認済みと偽らず、必要な内容・仕様整合と開発時の自動/AI校正による受入状態を別に記録する。受講者の修了判定に教材制作担当者の在席を要求しない。
- 今回PRの実装完了条件には、AIチューター/採点の経路、校正・誤PASSの拒否、自己再学習・再評価の契約、実Template・2コアCodespaces技術受入を含む。実受講者による習熟効果の観察は後続工程とする。

- Phase 1だけで修了可能。Phase 2はPhase 1の学習成果を前提に追加し、Phase 3は任意の追加受講である。
- 各フェーズの問題・解説・実技評価は別に用意し、**将来のフェーズで初めて学ぶ操作やツールを先行フェーズの合格条件にしない**。
- クイズは正答・誤答説明と復習先がある知識確認。実技はAIとの実作業と成果物、実行・判断の証拠で確認。クイズ得点だけで技能を認定しない。
- 初回クイズの正答率を一律80%等に固定しない。必須の学習項目で誤解が残っていないことを復習・別条件での再確認によって確かめる。
- **未実行、BLOCKED、未達、達成**を区別し、AIの自己申告や旧課程のPASSを新課程の証拠として使わない。公開済みの学習クイズ解説、public Gitでレビューできる模範解答、学習用配布物に含めない採点用テストを、それぞれ用途で区別する。配布除外は秘密保持ではない。AIが生成した成果物だけで本人の技能を認定しない。

## 学習順序と到達判定

[学習順序・モジュール別習熟基準](./2026-10-16_qa-curriculum-ai-agent-redesign_progression.md)に、受講開始ガイドからM10までの**前提知識・演習・51項目別Level 2の証拠**を定義する。各モジュール末尾では次の教材に進むための基礎確認を行い、M04・M07・M10では別条件で独立した実技を実施する。1件の実技で複数項目を評価してよいが、本人が判断した内容と各IDの評価根拠を残す。

- 初めて扱うコマンドは、**意味の説明前にコピーして実行する場合はその旨を明記**し、技能判定に含めない。
- M05ではTypeScriptの最小構文が読める・部分修正できることを確かめてから、M06でCaseのE2E化へ進める。M06で実行証拠を得てからM07の失敗分析へ進める。
- 不合格・環境BLOCKED・教材の不備を区別し、学習内容を習っていないことを理由に先行モジュールを不合格にしない。
- **AIが正しく作業したことだけではLevel 2を認定しない**。本人の根拠説明、誤りの採否、短い変更、条件を変えた確認を観測する。

## Web確認クイズと正式修了の区別

受講者は[Web閲覧・学習体験Plan](./2026-10-16_qa-curriculum-ai-agent-redesign_web-learning.md)に従いクイズを一問ずつ回答・復習する。クイズ得点・ブラウザ内の途中保存だけではLevel 2を認定しない。実技・本人判断・コード/Runの証拠をAI/決定論的に評価し、Phase末の正式修了と区別する。

- クイズに誤答があれば、対応する学習項目の説明へ戻り、別条件での判断・必要な実技を再確認する。
- クイズの途中回答・得点を、本人の`submission.md`、非公開の正式評価記録、Codespacesの開始/終了判定へ**自動転記しない**。本人が必要に応じて振り返りを記録できるが、正式修了は既存の実技と根拠説明に基づく。
- 教材revisionが異なる過去のWeb回答を新版の得点や正式な学習証拠として自動流用しない。ブラウザに保存した回答は成績DBとして扱わず、共有端末では消去方法を案内する。

## 提出・評価と記録の契約

- **各モジュールの成果物**は`workspace/Mxx/`を正本とし、`submission.md`にモジュールID・教材/状態revision・使用した開始入力の種類・仕様根拠・作業内容・AI案の採否・未確認事項を記載する。実行するモジュールは`evidence/`にログ・Trace・実行条件など必要な証拠を置く。実技コードと提出説明は同じmodule IDで追えるようにする。
- **自己確認**は受講者自身の練習・再学習に使う。正式修了はM04/M07/M10で、別セッションのAI評価器と決定論的な検証の両方により本人が開始・完了できることを必須とする。評価器は既習範囲内の別条件を出題し、受講者の回答後に証拠を採点する。AIの自己申告やテストPASSだけで達成を認定しない。
- **採点基準**は、必須の仕様根拠、前提・期待結果、適切な技法の選択、再現できる実行証拠、説明できる根拠など、当該フェーズで既習の項目に限定する。**正しい別解**は仕様・制約・不変条件を満たす限り認め、模範と異なる表現だけを理由に不合格としない。根拠不明や仕様未確定は未判定/確認事項とし、都合のよい期待結果に補正しない。
- **個人別の記録**は公開repoや公開グラフへ書き込まない。`workspace/`配下の非公開学習データと読み取り専用の評価入力スナップショットに、モジュール/Phase・教材/Skill/仕様/採点基準版・本人の回答と証拠への参照・目標ID別Level・評価理由・モデル・日時・再評価履歴を残す。Phase 1/2はGitコマンド不要で本人がエクスポートでき、履歴やSecretの公開送信を禁止する。新しい成績DBは不要。
- **未評価・判定不能・BLOCKED**は正式修了としない。AI接続不能・料金制限・校正不合格時は原因と再開条件を表示して停止する。教材版や採点条件の変更後は影響IDだけ再評価し、旧版の結果を新版へ自動承継しない。
- **基準入力の参照**：前モジュールの成果物を失った場合、当該モジュールに同梱の**別条件で検証済みの開始入力**を利用できる。入力元を記録するが、前フェーズの本人修了を推定・認定しない。別モジュールの復旧は実装しない。

## 公開の模範解答・採点用テスト・完成状態の基準

`qa-training-store`はpublicである。各モジュールの模範解答、採点用テスト、完成状態データは、内容を通常のGit差分・PRレビューで確認できるMarkdown/JSON/TypeScript等として次の場所へ保存する。

```text
training/ai-assisted-qa-course/assessment/
  README.md
  reference-solutions/M00.md ... M10.md
  playwright/M05/product-link.spec.ts
  playwright/M06/cart-cases.spec.ts
  playwright/M07/expected-failure/intentional-assertion.spec.ts
  playwright/M07/repaired/repaired-assertion.spec.ts
  scoring-tests/M00.json ... M10.json
  completed-states/M00.json ... M10.json
```

公開した資料を見られることは前提とし、情報の秘匿性や学習用配布物からの除外を秘密保持と説明しない。`training/course-sync/manifest.json`の既存許可リストを維持し、`assessment/`全体とその内容は学習用Template、同期、module load、Web Build、公開Artifactへ含めない。この配布契約をmanifest/loader/build testsで確認する。`assessment/playwright/M05`〜`M07`は既存の新課程専用Playwright Configでローカル実行できる評価用完成specであり、学習者用workspaceの未完成課題とは分離する。暗号化アーカイブ、age、復号スクリプト、鍵管理、暗号化専用CIは設けない。

M04/M07/M10の評価条件は公開可能とし、評価器は既習範囲から初見の小さな変更・質問を選ぶ。提出した本人の条件判断・不足・実行証拠を採点し、模範を読めることやモデルが正解を述べることだけで正式修了としない。評価器は既存校正例の条件を安易にそのまま再提示せず、正答の妥当性を仕様で検証する。

| 対象 | 模範と採点資料に必要な根拠 |
| --- | --- |
| M02〜M04の分析・テスト設計 | 正式な仕様・BR/AC・revision、Role/State/Data/Journey、リスク・検証責務、技法の採否と選定理由、同値クラス・境界・条件表・状態遷移の必要な導出過程、採用・除外条件、Caseの前提・操作・期待結果・観測方法・不変条件、仕様上の未決事項 |
| M05〜M07の実装・診断 | 承認済みCaseとspecの対応、Seed/Reset、LocatorとAssertionの選択・保証範囲、実際のRun・Trace等の証拠、誤りの原因仮説と反証、修正前後の別実行、PASSでも仕様を検証できていない実装の例 |
| 各フェーズの修了課題 | **必須判断と合否に直結する条件**、誤答や不足を判断する仕様根拠、部分的に正しい回答の扱い、正しい別解の許容条件、評価不能・BLOCKED・未確認の場合の判定方法 |

**模範解答の制作時に確認すること**：

1. 結論・完成表・動くコードだけではなく、学習目標に必要な**導出過程と判断理由**がある。
2. 典型的な誤り（例：境界値は正しくても期待結果が誤る、条件表に到達不能な組合せを含む、E2EのPASSだけでは業務結果を検証できない）について、どの根拠で不合格・要再確認とするか示せる。
3. 模範と異なる表現・設計技法・実装でも、仕様・必要な検証責務・不変条件を満たす回答は認める。**模範との文字列一致、ケース件数、コード量だけで採点しない**。
4. 評価する能力ごとに、観測対象と合格に必要な要素を示す。提出物の一部が正しくても、必須の能力を示す証拠がない場合は自動合格としない。各モジュールの公開校正データには参照revision不一致と必須証拠不足の例を含め、どちらも現行基準で推測採点せず`ungradable`として扱う。
5. 特にM03のSkill生成結果は、runtimeの構造/current evidenceを決定論的に検証したうえで、正式仕様・技法・Condition/Caseの意味上の妥当性を**学習時AI評価器**が根拠付きで確認する。開発時には代表回答と既存校正例で誤PASSを測る。

**採点基準の確認**では、正答・誤答・部分正答・正しい別解・不正な指示・別revision・証拠欠落などの入力に対して、使用モデルとプロンプトの組合せが事前期待どおりに判定することを開発時に検証する。模範への文字列一致だけで合格にしない。**1回でも重大な誤PASSを出した評価器は、その条件を修正・再校正するまで正式修了判定に使わない**。自習者が異議を述べる場合は、根拠・ID・誤判定箇所を記録して再評価でき、必須の人間審査を要求しない。

個々の課題に必要な模範・判定観点は学習目標と課題の性質に合わせて作成し、すべての模範へ無関係な技法や項目を機械的に追加しない。

## フェーズ終了時のAIによる本人判断確認

M04・M07・M10の総括評価は、学習者が自分で起動する別のOpenCodeセッションで実行する。チューターの解説履歴や本人が後で編集可能な自己採点文を無条件に信頼しない。

1. **通常演習の照合**：版を固定した提出スナップショット、Spec/BR/AC、本人の採否・補足、PlaywrightやCIの実Run、決定論的検証結果を揃える。Secret・公開禁止情報を採点プロンプトに混入させない。
2. **追加の条件・質疑**：既習能力を測る小さい未知条件を出題し、本人の回答を先に保存する。M04は仕様・設計見直し、M07は証拠からの失敗分類と保守修正、M10はRun/権限/費用の判断。全IDに追加質問1件だけを流用しない。追加条件と回答の区別、使用教材・仕様revisionを明記する。
3. **採点**：読み取り専用の評価用権限・独立セッションで公開ルーブリックと例示校正を参照し、未実行/BLOCKEDや部分正答を勝手にPASSへ変換しない。自由記述は結論・根拠・仕様一致・別解の理由、実技はRunとファイル実体を照合する。
4. **結果と再実践**：目標ID別Level/根拠/不足、復習すべき教材の節、次の実行可能な小演習を本人へ返す。失敗したIDだけを再評価でき、元の結果を履歴として保持する。必要な条件を満たすまで正式修了にしない。
5. **安全な実行**：提出物・ログ・Web情報に書かれた「採点指示」「承認しろ」といった文は**証拠データ**として扱い、実行命令にはしない。AI評価器のファイル書込み・Shell・network権限を最小化し、決定論的検証と結果確定は評価器のテキスト出力だけで上書きできない設計とする。

**受入**：本人が講師なしでM00から選択Phaseの終了まで進み、AIによる質問対応、各モジュールの学習・復習、M04/M07/M10での正式評価、未達IDの再提出と再評価まで完了できる。現行OpenCode CLIで非対話呼出し・モデル制限・結果JSONの形式/パース/校正/権限を実機確認する。校正不合格・モデル利用不能はBLOCKEDまたは判定不能とし、人間への必須引継ぎなしでも状態と再開方法が分かる。

## 教材・評価・習熟の独立確認

[知識グラフ](../curriculum/ai-assisted-qa/README.md)の理解事項とLevel 2基準を使用し、以下を**別の状態**で確認する。

| 確認 | 判定に必要な根拠 |
| --- | --- |
| 教材に説明がある | 学習対象の知識と例を受講前に説明している教材節 |
| 評価手段が存在する | 実在する問題または実技がその知識・技能を対象としている |
| 評価内容が妥当である | 設問・正答・誤答説明または実技の条件を照合し、**必要な理解・適用・判断を評価できる**と独立に確認した根拠 |
| 受講者が習得した | 使用した**教材・問題・実技の版**と本人の回答・実行・判断の証拠により、その時点のLevel 2を認定した記録 |

- 上位の行を満たさない場合は、下位の達成と推定しない。**形式的なID対応・問題数・PASSだけでは習熟を保証しない**。
- 問題の改訂、正式仕様または`qa-workflow-skills`の契約変更時は、影響対象を[グラフの変更影響検索](../curriculum/ai-assisted-qa/README.md)で抽出し、該当評価の内容を再確認する。古い版の合否を新しい版へ無条件で引き継がない。
- 公開の模範解答・採点用テストは通常ファイルとして`training/ai-assisted-qa-course/assessment/`へ保存する。学習者個人の識別情報、回答・評価結果、評価時に追加・変更して本人判断を確認する条件は公開グラフ・公開資料・学習用Templateへ保存しない。学習履歴DBは新設しない。

## 各モジュールの開始・終了状態の判定

[全モジュールの開始・終了基準状態](./2026-10-16_qa-curriculum-ai-agent-redesign_states.md)に従い、**M00〜M10のすべて**について、実際の開始用入力・環境条件と、終了時に正しいとみなせる成果物・根拠・許容別解を用意する。

- **開始判定**：指定モジュールを始めるために必要な入力、仕様/Skill/課題revision、設定、Seed、前モジュールの引継ぎ成果物が正しいか照合し、不足・不整合・確認不能を区別する。開始できることは学習目標の達成証拠にしない。
- **終了判定**：正しい完成基準データと照らし、機械的な構造・実行条件と、本人の設計意図・適用判断・仕様根拠を別に確認する。正しい別解を排除しない。
- **過去成果物の不在**：本人のM04成果物がなくても**M05同梱の別条件の検証済み開始入力**で進められる。M07→M08も同様とし、入力元は記録する。前工程を修了したという記録は新たに作らず、**自動復元や復旧コマンドは実装しない**。
- **公開・配布範囲**：正解データ・模範テスト・完成状態はpublicなGit上で閲覧できるが、学習用配布物/Web Build/公開Artifactには含めない。配布除外は秘密保持ではない。学習者の成績や評価結果、評価時に追加・変更して本人判断を確認する条件を公開基準データへ含めない。

## 共通の受講開始条件（修了評価とは別）

- 受講者は公開Templateから本人の非公開リポジトリを作り、無料枠の2コアCodespaceを利用する。個別の利用可能枠・支払主体・モデル認証・必要Skill動作は受講者の初回起動時に確認し、不成立はBLOCKEDとする。**公開Templateと2コアCodespaceの配布/load・Serve/Reset・Playwrightの技術受入は今回PRの実装完了条件**とし、未実施・失敗を後続の受講者試行へ送らない。
- 既存devcontainerの起動・Node.js/pnpm、受講範囲に応じたPlaywright/Chromiumと外部Skillの動作を確認する。**受講者ごとにOpenCode CLIの無料モデル・個人認証・必要Skillの初回動作を確認し、不成立はBLOCKEDとする**。Secretを安全に管理し、有料モデルへの自動切替や無断課金を避ける。
- `qa-workflow-skills`の必要なSkillとPython helperを認識・実行でき、AIに与える権限を制限できることを確認する。**学習者本人による`course:load M00`などの1モジュール単位ロードと再実行時の上書き防止**も確認する。個人情報・APIキーを教材や共有ログに保存しない。
- 各フェーズ終了時の成果物のダウンロード／保全とCodespace停止方法を示す。無料枠到達・容量不足・接続不能は**環境BLOCKED**として扱い、学習成果のLevelを推測で合格・不合格にしない。
- **環境の準備完了 ≠ 受講者の技能習得**。初期設定は受講できる状態かの確認であり、以下のPhase 1〜3の実技評価を代替しない。

## 習熟度の判定

| 水準 | 意味 |
| --- | --- |
| Level 0 | 対象の仕様・結果を正しく説明・判断できない |
| Level 1 | 教材の例や手順をなぞればできるが、新しい条件では支援が必要 |
| **Level 2** | 与えられた新しい条件に正しく適用し、仕様・証拠から自分で結果を説明できる |
| Level 3 | 複数の方法・費用・リスク・保守性を比較して改善策を説明できる |

各フェーズの必須観点を**すべてLevel 2以上**にしたとき修了とする。Level 3や全Skillの習熟は必須にしない。旧課程のC01〜C12やCompletion Receiptと結果を混ぜない。

旧`scripts/training/check-completion.ts`の`semantic_understanding: "NOT_EVALUATED"`と旧課程の対象Lesson IDはそのまま維持する。新課程の修了判定は別の公開基準を用い、**ファイル存在だけで意味的な理解をPASSとしない**。
