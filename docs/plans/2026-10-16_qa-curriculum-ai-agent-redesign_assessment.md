# 新課程の評価・各フェーズの修了基準

## 評価する能力と共通原則

本Planでの「修了」は3つの別々の結果を表す。受講者の作業環境は**教材正本と別の学習用リポジトリ**とし、各モジュールを**受講者本人が明示的にロード**して実施する。**Phase 1修了はテスト設計能力、Phase 2修了はPlaywright自動化能力、Phase 3修了はGitHub・CI運用能力**である。標準の学習環境はGitHub Codespacesだが、Gitコマンド・PR・CIの学習は選択Phase 3に限定する。

- Phase 1だけで修了可能。Phase 2はPhase 1の学習成果を前提に追加し、Phase 3は任意の追加受講である。
- 各フェーズの問題・解説・実技評価は別に用意し、**将来のフェーズで初めて学ぶ操作やツールを先行フェーズの合格条件にしない**。
- クイズは正答・誤答説明と復習先がある知識確認。実技はAIとの実作業と成果物、実行・判断の証拠で確認。クイズ得点だけで技能を認定しない。
- 初回クイズの正答率を一律80%等に固定しない。必須の学習項目で誤解が残っていないことを復習・別条件での再確認によって確かめる。
- **未実行、BLOCKED、未達、達成**を区別し、AIの自己申告や旧課程のPASSを新課程の証拠として使わない。公開済みの学習クイズ解説と、**公開・同期しない修了課題の模範解答**を区別する。AIが生成した成果物だけで本人の技能を認定しない。

## 学習順序と到達判定

[学習順序・モジュール別習熟基準](./2026-10-16_qa-curriculum-ai-agent-redesign_progression.md)に、受講開始ガイドからM10までの**前提知識・演習・51項目別Level 2の証拠**を定義する。各モジュール末尾では次の教材に進むための基礎確認を行い、M04・M07・M10では別条件で独立した実技を実施する。1件の実技で複数項目を評価してよいが、本人が判断した内容と各IDの評価根拠を残す。

- 初めて扱うコマンドは、**意味の説明前にコピーして実行する場合はその旨を明記**し、技能判定に含めない。
- M05ではTypeScriptの最小構文が読める・部分修正できることを確かめてから、M06でCaseのE2E化へ進める。M06で実行証拠を得てからM07の失敗分析へ進める。
- 不合格・環境BLOCKED・教材の不備を区別し、学習内容を習っていないことを理由に先行モジュールを不合格にしない。
- **AIが正しく作業したことだけではLevel 2を認定しない**。本人の根拠説明、誤りの採否、短い変更、条件を変えた確認を観測する。

## 提出・評価と記録の契約

- **各モジュールの成果物**は`workspace/Mxx/`を正本とし、`submission.md`にモジュールID・教材/状態revision・使用した開始入力の種類・仕様根拠・作業内容・AI案の採否・未確認事項を記載する。実行するモジュールは`evidence/`にログ・Trace・実行条件など必要な証拠を置く。実技コードと提出説明は同じmodule IDで追えるようにする。
- **自己確認**は受講者の復習・次モジュールへの進行判断に使う。**フェーズの正式な修了判定**は評価担当者（講師または指定レビュー担当者）が受講者の提出物と非公開の模範・公開ルーブリックを照合して行う。**M04・M07・M10では短い未提示条件への本人判断も直接確認する**。AIの自動評価は参考意見であり、最終判定を代替しない。
- **採点基準**は、必須の仕様根拠、前提・期待結果、適切な技法の選択、再現できる実行証拠、説明できる根拠など、当該フェーズで既習の項目に限定する。**正しい別解**は仕様・制約・不変条件を満たす限り認め、模範と異なる表現だけを理由に不合格としない。根拠不明や仕様未確定は未判定/確認事項とし、都合のよい期待結果に補正しない。
- **記録**は公開リポジトリや公開知識グラフへ保存しない。評価担当者がアクセス制限された提出・評価保存先に、受講者の提出物、モジュール/フェーズ、参照した教材・問題・基準状態のrevision、確認した各学習IDのLevel、判定根拠、判定日時をまとめる。新しい成績DBや学習用Webアプリは作らない。
- **未評価とBLOCKED**は正式修了としない。担当者が不在であれば受講者は学習・自己確認を進められるが、正式な修了判定は保留とする。教材の版が更新された場合、改訂差分の影響を判定して必要な項目だけ再評価し、過去の達成を新版へ自動移行しない。
- **基準入力の参照**：前モジュールの成果物を失った場合、当該モジュールに同梱の**別条件で検証済みの開始入力**を利用できる。入力元を記録するが、前フェーズの本人修了を推定・認定しない。別モジュールの復旧は実装しない。

## 修了時に本人の判断を直接確認する手順

M04・M07・M10の正式な修了判定では、**受講者の提出済み実技を評価したうえで、評価担当者が短い未提示条件を追加し、本人が判断する場面を直接確認する**。新しい試験システム・独立したモジュール・大量の追加問題は作らない。

1. **通常の実技**：AI・教材・公式ドキュメントの参照を許可し、仕様根拠・生成物の採否・実行証拠を確認する。この時点では提出文をAIが書いた可能性だけで不合格にしない。
2. **本人確認**：評価担当者が、提出済みの課題に関連する**未提示の小さな条件変更または誤りを1件**示す。受講者は**その問いへの新しい回答をAIに生成させず**、既存の仕様・コード・ログを見ながら、自分の言葉で判断、根拠、追加で確認する点を説明する。口頭・その場のテキスト回答のいずれでもよい。**暗記・手書きコーディング・全工程のAI禁止**は求めない。
3. **フェーズ別の問い**：M04は追加されたBR/AC条件を受けてCaseと期待結果の見直し範囲を判断する。M07は誤ったAssertionまたはRunの断片を見て原因仮説と独立した再検証方法を説明する。M10は対象PR HEADと別SHAの成功Runを示し、それを合格証拠にできるか判断する。
4. **判定**：評価担当者は、結論だけでなく**仕様・コード・実行証拠との対応、誤案を退ける理由、不明点の扱い**を既存Level 2で評価する。妥当な別解は許容し、矛盾や根拠不足は追加確認または未達とする。回答が成立しない場合は、通常実技のPASSだけで正式修了にしない。
5. **記録**：新しい問いの条件、回答の要点、参照した版、Level 2の判定根拠、評価担当者を、既存の非公開評価記録へ追記する。本人の回答や評価記録を公開グラフ・Git履歴へ載せない。受講者の言語能力や回答の流暢さより**判断内容**を評価する。

**受入検証**：提出物が正しくても、未知条件への本人判断が誤っている例を正式修了から除外できる。M04・M07・M10の通常課題で測らない新しい能力や未学習知識を突然要求しない。M01〜M03・M05〜M06・M08〜M09の通常の進捗確認に同じ面談を機械的に追加しない。

## 教材・評価・習熟の独立確認

[知識グラフ](../curriculum/ai-assisted-qa/README.md)の理解事項とLevel 2基準を使用し、以下を**別の状態**で確認する。

| 確認 | 判定に必要な根拠 |
| --- | --- |
| 教材に説明がある | 学習対象の知識と例を受講前に説明している教材節 |
| 評価手段が存在する | 実在する問題または実技がその知識・技能を対象としている |
| 評価内容が妥当である | 設問・正答・誤答説明または実技の条件を照合し、**必要な理解・適用・判断を評価できる**と独立に確認した根拠 |
| 受講者が習得した | 使用した**教材・問題・実技の版**と本人の回答・実行・判断の証拠により、その時点のLevel 2を認定した記録 |

- 上位の行を満たさない場合は、下位の達成と推定しない。**形式的なID対応・問題数・PASSだけでは習熟を保証しない**。
- 問題の改訂、正式仕様または`qa-workflow-skills`の契約変更時は、影響対象を[グラフの変更影響検索](../curriculum/ai-assisted-qa/README.md)で抽出し、該当評価の内容を再確認する。古い版の合否を新しい版へ無条件で引き継がない。
- 受講者の本人識別情報、回答・評価結果、非公開の採点用テストは**公開グラフや公開Templateへ保存しない**。学習履歴DBは新設しない。

## 各モジュールの開始・終了状態の判定

[全モジュールの開始・終了基準状態](./2026-10-16_qa-curriculum-ai-agent-redesign_states.md)に従い、**M00〜M10のすべて**について、実際の開始用入力・環境条件と、終了時に正しいとみなせる成果物・根拠・許容別解を用意する。

- **開始判定**：指定モジュールを始めるために必要な入力、仕様/Skill/課題revision、設定、Seed、前モジュールの引継ぎ成果物が正しいか照合し、不足・不整合・確認不能を区別する。開始できることは学習目標の達成証拠にしない。
- **終了判定**：正しい完成基準データと照らし、機械的な構造・実行条件と、本人の設計意図・適用判断・仕様根拠を別に確認する。正しい別解を排除しない。
- **過去成果物の不在**：本人のM04成果物がなくても**M05同梱の別条件の検証済み開始入力**で進められる。M07→M08も同様とし、入力元は記録する。前工程を修了したという記録は新たに作らず、**自動復元や復旧コマンドは実装しない**。
- **情報保護**：正解データ・模範テストは非公開、公開の配布物には必要な条件と未完成課題だけを含める。学習者の成績や評価結果を公開基準データへ含めない。

## 共通の受講開始条件（修了評価とは別）

- **学習用Templateから作成した個人リポジトリ**で本人の無料枠を利用する2コアCodespaceを作成できることを確認する。現在のリポジトリは2コア固定設定ではない。所有者・支払主体、残りコア時間・ストレージ、課金停止条件を確認し、**無料利用が成立しなければ開始をBLOCKEDにする**。
- 既存devcontainerの起動・Node.js/pnpm、受講範囲に応じたPlaywright/Chromiumと外部Skillの動作を確認する。**OpenCode Zen無料モデルは利用確認済みとして採用し、モデルの利用可否・認証可否の再検証は要求しない**。Secretを安全に管理し、有料モデルへの自動切替や無断課金を避ける。
- `qa-workflow-skills`の必要なSkillとPython helperを認識・実行でき、AIに与える権限を制限できることを確認する。**学習者本人による`course:load M00`などの1モジュール単位ロードと再実行時の上書き防止**も確認する。個人情報・APIキーを教材や共有ログに保存しない。
- 各フェーズ終了時の成果物のダウンロード／保全とCodespace停止方法を示す。無料枠到達・容量不足・接続不能は**環境BLOCKED**として扱い、学習成果のLevelを推測で合格・不合格にしない。
- **環境の準備完了 ≠ 受講者の技能習得**。初期設定は受講できる状態かの確認であり、以下のPhase 1〜3の実技評価を代替しない。

## 習熟度の判定

| 水準 | 意味 |
| --- | --- |
| Level 0 | 対象の仕様・結果を正しく説明・判断できない |
| Level 1 | 教材の例や手順をなぞればできるが、新しい条件では支援が必要 |
| **Level 2** | 与えられた新しい条件に正しく適用し、仕様・証拠から自分で結果を説明できる |
| Level 3 | 複数の方法・費用・リスク・保守性を比較して改善策を説明できる |

各フェーズの必須観点を**すべてLevel 2以上**にしたとき修了とする。Level 3や全Skillの習熟は必須にしない。旧課程のC01〜C12やCompletion Receiptと結果を混ぜない。

## Phase 1の修了：AIエージェントを使ったテスト分析・設計

### 評価対象（M00〜M04）

| 観点 | Level 2の合格条件 | 主な証拠 |
| --- | --- | --- |
| AIの基本操作 | CodespacesでOpenCode CLIと必要なSkillを使い、手順例を経験したうえで本人が目的・資料・作業範囲・完了条件を指定できる | 実際の依頼内容、結果、本人による確認 |
| 安全・証拠 | 読取りとファイル変更を区別し、Secretを扱わず、AIの推測・未実行の成功宣言を見抜ける | ローカルの変更前後比較、採否理由 |
| 仕様とリスク | BR/ACと観測を区別し、Role/State/Data、リスク・優先度を根拠付けられる | 初見条件の仕様参照、Risk/Condition |
| テスト設計 | 適切な技法から条件・ケース・前提・期待結果を導ける | CaseとBR/ACの対応 |
| AI案のレビュー | 不足・重複・誤った期待結果を検出し、自動化候補の採否と理由を説明できる | 本人が確定させた設計、AI案の採否 |

**総合演習（M04終了時）**：**非公開の模範解答を受講者リポジトリへ同期しない状態で**、Scenario Shopの未演習の仕様条件を配布し、OpenCode/Skillを使いながら分析・設計・自動化候補の判断を行う。教材に載っている完成例の転記では合格しない。AIから正しい提案が出た場合は根拠を示した採用を認め、無理に誤りを捏造させない。

**必要な環境**：個人の学習用リポジトリのCodespace、モジュール単位でロードした教材・仕様資料・成果物保存先、利用可能な無料モデルのAIエージェントと必要なSkill。**Gitコマンド、PR、Playwright、CI、実行中のScenario Shopは必須にしない**。製品の動作確認は参考にしてよいが、Phase 1では仕様に基づく分析・設計を判定する。

**修了の意味**：AIを活用して自動化に必要なテスト分析・設計成果物を作り、その妥当性を確認できる。Playwrightでの自動実装・実行は未認定。

### Phase 2への引継ぎ

確定したテストケース（識別子、仕様ID、前提状態、操作、期待結果）、選定理由、未確定事項を**学習者の`workspace/Mxx/`へMarkdown等でまとめ、Git操作なしでダウンロード**して保全・引継ぎできるようにする。**後続モジュールのロードで上書きしない**。GitHubのPRや旧Training Copyへの提出を前提としない。

## Phase 2の修了：Playwright構築・実装・実行・改善

### 評価対象（M05〜M07）

| 観点 | Level 2の合格条件 | 主な証拠 |
| --- | --- | --- |
| 自動化環境 | 同期済み学習用リポジトリのCodespacesでNode.js/pnpm/PlaywrightとScenario ShopのBuild/Serve/Seed/Resetを理解し、新課程用Config・テスト対象・実行コマンド・結果先を設定して実行できる | `package.json`、Config、Codespaces内の実行記録。devcontainer全体の再構築は不要 |
| コード理解 | **Node.js/pnpmの実行経路、TypeScriptの変数・配列・オブジェクト・関数・型・import/export・async/await**、Locator/Action/Assertion、待機と期待結果を理解し、短いコードを説明・部分修正できる | コード読解、本人の採否と変更前後 |
| テストの実装 | Phase 1のCaseから仕様に適合するPlaywright specを作り、Resetと独立性を確保する | 受講者spec、Seed/Reset、意味あるAssertion |
| 実行結果 | ローカルで対象テストを実行し、PASS/FAIL/BLOCKEDとRun・Trace等の証拠を対応付けられる | 実行コマンド、ログ、Report/Trace |
| 診断と保守 | Test/Product/Environment/Flakyの可能性を区別し、必要なら最小修正・別Runで検証できる | 初回と修正後の異なる証拠、差分、理由 |

**総合演習（M07終了時）**：**学習者がロードした未完成課題から**Phase 1の承認済みケースに対応するE2Eを構築・実行し、さらに未演習の条件または故意に不適切なテストspecの診断・修正を行う。テストの不具合を直すために製品本体を変更しない。

**必要な環境**：同じ**学習用リポジトリ**のCodespaceに導入済みのNode.js/pnpm/Playwright/Chromium、Build/Serve可能なScenario Shop、テスト対象と許可されたAIエージェント。**Git/PR/GitHub Actions/CI操作は不要**。Git CLIを使った差分確認は許可するが、必須にはしない。

**修了の意味**：Codespaces内で再現性のあるWeb自動化を構築・実装・実行・改善できる。GitHub/CI運用は未認定。環境が利用できない場合はその実行部分をBLOCKEDとし、架空の成功証拠で合格させない。

### Phase 3への引継ぎ

Phase 2でCodespaces内で動作確認したspec、環境設定、依存関係、Reset手順、実行コマンド、結果・未確認事項を**Git操作なしで保全**して引き継ぐ。**テストケース自体を再作成させない**。

## Phase 3の修了：GitHub・CIによる継続実行（選択）

### 評価対象（M08〜M10）

| 観点 | Level 2の合格条件 | 主な証拠 |
| --- | --- | --- |
| Git/GitHub | 許可された作業コピーでbranch、commit、PRを作り、AI変更を差分からレビューできる | Git差分、PR、本人の採否理由 |
| CI構築 | Phase 2のテストをCI用に起動し、依存導入・Build/Serve/Test・Artifactを適切に構成できる | 新課程用workflow、Run |
| 実行証拠 | 対象PR/commit SHAとRun/Check/Artifactが一致することを確認できる | GitHub Actionsの実際の結果 |
| 失敗調査 | CI環境差・対象のテスト不備・実行未完了を切り分け、必要な対応を示せる | 失敗ログ・変更内容・再実行 |
| 安全性・運用 | 権限・Secret・正式CIとの境界を守り、品質ゲートと未確認事項を説明できる | workflowレビュー・最終評価 |

**総合演習（M10終了時）**：Phase 2で成功したPlaywright specを**同じ受講者個人の学習用リポジトリでGit管理し**、新課程専用のCIから実行して証拠を確認する。新たなテストケースの再実装を修了条件としない。既存CIの成功を、新しい対象SHAの成功として流用しない。

**必要な環境**：受講者本人の書込可能な**学習用GitHubリポジトリ**と標準GitHub-hosted Runner・workflow権限等。**公開リポジトリでの標準Runnerの無料利用**を第一候補とし、private/larger runnerでの課金・公開内容の安全性を確認する。使えない場合はBLOCKEDとするが、Phase 2修了を取り消さない。

**修了の意味**：自動テストをGitHub/CIへ組み込んで検証・調査・管理できる。

## クイズと再確認

[クイズ仕様](./2026-10-16_qa-curriculum-ai-agent-redesign_quizzes.md)で各学習項目に問題または実技評価の根拠を付ける。初回回答、正誤、誤答した学習項目、復習、**条件を変えた再確認**をフェーズ別に記録する。問題の曖昧さや誤った解説は受講者の不合格とせず問題を修正する。

回答・評価記録は受講者のローカル作業コピー／指定提出先に保存し、教材・公開PR・旧`self-check/P1-xx.md`へ混入させない。APIキーや個人情報、AIの内部推論、AIとの全会話は保存を要求しない。

## 既存課程との境界と実装検証

旧`scripts/training/check-completion.ts`の`semantic_understanding: "NOT_EVALUATED"`と旧課程の対象Lesson IDはそのまま維持する。新課程の修了判定は別の公開基準を用い、**ファイル存在だけで意味的な理解をPASSとしない**。

受入検証：**全11モジュールの開始・終了基準データ**を作成し、引継ぎID・revision、過去成果物欠落時の参照可能性、開始状態とLevel 2判定の分離を確認する。受講開始ガイドからM00をロードでき、M05でNode.js/pnpm/TypeScriptを順序立てて学習できること、51学習項目すべての具体的判定根拠があることを検証する。学習用リポジトリの新規2コアCodespaceで本人による1モジュールロード、成果物の上書き防止、Phase 1・2の初期導入、`qa-workflow-skills`とPlaywright実行、成果物保全を検証する。**OpenCode Zen無料モデルの利用可否・認証可否を再検証する工程は置かない**。Phase 1の修了判定にPlaywright・Git/PR/CI関連の必須証拠がないこと、Phase 2にGit/PR/CI関連がないこと、Phase 3を選択しない場合に旧・新のテストが失敗しないこと。各フェーズで[知識グラフ完成仕様](./2026-10-16_qa-curriculum-ai-agent-redesign_knowledge-graph.md)に沿い、全学習目標・理解事項・教材・クイズ・実技・修了条件の対応、評価内容の妥当性、仕様・Skill変更時の追跡まで確認する。
