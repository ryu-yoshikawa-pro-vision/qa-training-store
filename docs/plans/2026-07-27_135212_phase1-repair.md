# QA学習用ECアプリ Phase 1 修正計画

## 0. 依頼概要

- 依頼内容: 既存レイヤー、Use Case、Repository、Transaction Runner、Seed、Test API、37 Route を維持し、Phase 1 の既知不具合と検証不足を最小差分で修正する。
- 背景: Typecheck 停止、時刻源の混在、Reset 後の古い DB 参照、本番成果物への Test API 混入、Logout 導線不足、検証 script/a11y/画像/UI の不整合がある。
- 期待成果: Git/GitHub 操作や Deploy を行わず、指定された CI・Unit・Integration・Repository・Component・Contract・E2E・a11y 検証を通せる Phase 1 実装。

## 1. ゴール / 完了条件

- ゴール: 依頼文の作業順序を維持し、Phase 1 の全完了条件を実装と実測検証で満たす。
- 完了条件（DoD）:
  - CSS side-effect import を型解決し、strict TypeScript 設定を弱めず Typecheck を通す。
  - browser runtime で生成した単一の変更可能 Clock を TestControlService と全対象 Use Case が共有する。
  - Test Control UI の Reset 成功後だけ reload し、Test API reset の戻り値と fixture 制御を維持する。
  - automation/local のみ Test API・Test Control・テスト環境 badge を許可し、production build/deploy job を分離する。
  - customer と staff/admin が共通 Logout UI を利用でき、失敗・二重送信・保護 Route をテストする。
  - package scripts、a11y smoke、4商品画像、Seed version 11、Home Hero、CSS variable、顧客向け文言を整合させる。
  - 指定検証を順番に実行し、未実行・失敗を PASS と記載しない。

## 2. 現状理解と前提

### Current understanding

#### Entry points

- Runtime: `app/_layout.tsx` → `AppRuntimeProvider` → `src/bootstrap/browser-runtime.web.ts`
- Services: `src/application/create-application-services.ts`
- Test control: `src/test-controls/test-control-service.ts` / `test-api.web.ts` / `app/admin/test-control.tsx`
- Build/CI: `app.config.ts` / `package.json` / `.github/workflows/ci.yml`
- UI: storefront/admin shell、profile、home、auth、review-user pages、`global.css`
- Image/Seed: `config/product-image-assets.json` → prepare/generate/validate scripts → generated/public manifest → default dataset

#### Main flow

- browser bootstrap は TestControlService の DB を ApplicationServices へ渡すが、ApplicationServices 内で別の `SystemClock` を生成している。
- Catalog/Cart/Admin/Review は `app_settings` を個別参照し、Auth/Account は注入 Clock、Checkout は両方を参照するため、固定時刻が一貫しない。
- Reset は DB を close/delete/reseed して TestControlService の DB を差し替えるが、既存 ApplicationServices は古い DB を保持する。
- Test API allowlist と automation-admin guard はすでに `automation/local` 限定だが、CI は同一 job の automation `dist` を production にも使い、test-mode badge は常時表示している。
- Profile に独自 Logout はあるが、共通化・header/sidebar 導線・失敗表示・Home 遷移が不足している。
- 画像 manifest は config と実ファイルから決定的に生成・検証される。対象4商品は `asset-shirt-front` を流用している。

#### Key abstractions

- `Clock` / `TestClock`、`TestControlService`
- `createApplicationServices` と各 Use Case dependency
- `ScenarioShopDatabase`、Dexie repositories、transaction runner
- `AppRuntimeProvider` と `RouteGuard`
- `isTestApiBuild` allowlist
- `ProductImage` / generated manifest / seed validation

#### Existing tests

- Unit: domain logic/password。Runtime Clock unit は未追加。
- Integration: 各 Use Case、Seed/TestControl、Auth logout DB/session 削除。
- Repository contract: catalog/cart/repository。
- Component: auth/account、catalog、review/test-control等。Shell、共通 Logout、Reset reload は不足。
- Contract: Test API allowlist、image manifest、transactions。production install boundary と追加画像の強い検証は不足。
- E2E: 必須12、mobile、cross-role、browser smoke。Logout/a11y/新画像/Home Hero は不足。fixture は Test API reset → metadata → reload を制御し、console error を収集する。

#### Safe change surface

- Clock port/implementation、Use Case dependency と factory wiring
- TestControlService の Clock 同期、Test Control UI の reload
- build-kind の純粋 allowlist、app config default、CI job topology
- 共通 Logout component と既存 shell/profile への配置
- package scripts/Playwright spec、既存 image pipeline への asset 追加
- Home Hero markup/CSS と顧客向け表示文言
- 既存テストへの局所追加

#### Unknowns

- `node_modules` が未導入で、初回 Typecheck は依存型を解決できなかった。frozen install 後に依頼記載の CSS import error を再現確認する。
- a11y smoke の実違反は実行時に確定する。critical/serious を除外せず、対象 UI を局所修正する。
- 全browser E2Eの可否は Playwright browser install と実行環境に依存する。

### Assumptions

- 画像は外部 URL を使わず、統一した商品カタログ用画像を4点生成し、既存 sharp pipeline で 720×720 WebP 化する。
- CSS variable は検索で確認した実使用分（依頼明示の2件を含む）だけを `:root` に追加する。
- `tokens.ts` は `StatusTone` の import 元なので維持する。
- CI の Cloudflare secret 有無は boolean output で job 条件へ渡し、secret 値自体は出力しない。

### Non-goals

- 依頼文「2.2 対象外」の全項目。
- Backend/API、DB/認証/決済方式、Route/Router、状態管理、UI library、全画面 redesign の変更。
- Git/GitHub 操作、PR更新、Cloudflare Deploy、file delete/rename/move。
- moderate/minor a11y 違反の全件解消、複雑な bundle parser、design token generator。

## 5. 変更方針

- Change strategy:
  - Pure logic: RuntimeClock、build-kind allowlist/config resolution、DTO/manifest expectations は副作用から分離して unit/contract test する。
  - Side-effect boundary: Dexie reset、localStorage session、`window.location.reload()`、画像生成、dependency/browser install、CI deploy action の境界を明示してテストする。
  - Internal changes: Clock injection、build/job/script/Seed metadata、テスト基盤。
  - Consumer-facing changes: Logout導線、Hero画像、商品画像、顧客向け日本語、test badge 非表示。
  - 既存 architecture と public Route を維持し、fallback/skip/型無効化で失敗を隠さない。
- 実行タスク:
  - [x] 1. frozen install 後に CSS declaration を追加し Typecheck を通す。
  - [x] 2. `RuntimeClock` と共通 injection/synchronization を実装し、direct time source を除く。
  - [x] 3. UI Reset 成功後 reload を追加し、Test API reset を変えない。
  - [x] 4. app config、badge/guard、CI validate/preview/production を分離する。
  - [x] 5. 共通 Logout component を storefront/profile/admin へ配置する。
  - [x] 6. aggregate scripts、axe dependency、a11y smoke と CI step を追加する。
  - [x] 7. 4商品画像を生成/変換し、manifest/Seed/version 11 を更新する。
  - [x] 8. Home Hero、CSS variable、顧客向け文言を局所修正する。
  - [x] 9. Unit/Integration/Component/Contract/E2E の不足を追加する。
  - [x] 10. 指定順に全検証し、bounded repair を行う。

## 6. 検証方法

- Validation plan:
  - Dependency: `pnpm install`、`pnpm install --frozen-lockfile`
  - Static: format、format:check、lint、typecheck、image manifest generate/validate、security check
  - Tests: unit、integration、repository、component、contracts
  - Build: automation/local `build:web`、production environment `build:web`
  - Browser: Playwright Chromium install、required E2E、a11y
  - Optional: mobile、cross-role、Firefox、WebKit
  - Targeted searches: `src/application` の direct `new Date().toISOString()` と `app_settings.get("test-control")` が0件、追加assetの参照整合、未定義CSS variableが0件。
- 成功判定:
  - 各コマンド exit code 0。
  - a11y critical/serious 0、console error 0。
  - production build kind で Test API/Test Control/test badge が利用不可。
  - Reset UI reload と Test API fixture の非reload制御がともにテストで確認できる。

## 7. リスクと未解決論点

- Risks:
  - Clock dependency 追加は全 Use Case constructor test fixture へ波及する。Typecheck で漏れを機械的に検出する。
  - Reset 中の DB 差替えは ApplicationServices 再構築を行わず、成功後 reload のみに限定する。
  - Production bundle の文字列検査は minifier/tree-shakingへ過度に依存するため、runtime install boundary と route/badge gating を優先する。
  - a11y 修正は代表画面の critical/serious のみに限定し、全画面 redesign へ拡張しない。
  - generated image/manifest は script 出力に限定し、hash/file名/config を同時に整合させる。
- Open questions: なし。
