  - Reset の DB 更新を一つの Exclusive Transaction にまとめ、rollback と FK 整合性を検証する。

  - Production向けModule解決でTest Control／Harnessをimportしない構造とBundle Guardを追加する。
  - 複数Variationを未選択で開始し、未選択時の追加を無効にする。

## 2. 現状理解と前提

- Current understanding:
  - Branch は `feature/01_phase2-first-half-native-foundation`、PR #8 のHEADは `7f7e48e`、作業ツリーは開始時点でclean。
  - `native-test-control-bridge.tsx` は `parsed.path === "test-control/reset"` を比較しており、正式URLの `hostname=test-control`、`path=reset` 契約と一致しない。
  - `PHASE_ONE_SCENARIOS` はWebの全Scenarioであり、Native Reset／Seedの入力検証へ直接使われている。
  - Native Guest Cart repository は `published`、Inactive、在庫を確認するが `required_rank IS NULL` をMutation側で確認していない。
  - Native Runtime は `NativeGuestCatalogUseCases`／`NativeGuestCartUseCases` を生成しており、既存 `CatalogUseCases`／`CartUseCases` と業務入口が二重化している。
  - Reset service は `clearNativeCustomerData` と `seedNativeDataset` を別々に呼び出している。
  - Harness は work 成功直後にPASSを通知し、その後にCleanupしている。
  - Native Product Detail は複数Variationでも在庫のあるVariantを自動選択している。
  - `.github/workflows/native-ci.yml` と `native-ios-ci.yml` は存在しない。
- Assumptions:
  - EAS Cloud Build／Workflow／Submit、GitHubへのCommit／Push／PR更新は実行しない。
  - `android/`／`ios/`は生成・Commitしない。Windows上でAndroid SDKまたはmacOS/Xcodeがない場合の実Native成功判定は行わない。
  - Native前半の業務対象はGuest Storefront／Cartであり、後半の会員購入・決済・注文・Review・Admin UIは追加しない。
- Non-goals:
  - Phase 2後半のRepository／Table／UIを先行実装しない。
  - 独自Cross-store Transaction、Journal、Saga、Global Mutation Queueを追加しない。
  - PR本文をGitHub上で更新・レビューThreadをResolveしない。
