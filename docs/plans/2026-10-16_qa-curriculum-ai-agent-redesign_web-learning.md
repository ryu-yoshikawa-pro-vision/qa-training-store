# 新課程のWeb閲覧・確認クイズ・受講者の学習体験

## Webの改善確定事項（2026-10-25）

受講トップ→環境準備→全仕様一覧→学習目標→教材→公開演習・コード/ログ例→ルーブリック→クイズ→解説・復習をサイト内で辿れるようにする。教材とクイズの外観・前後移動・閲覧済み状態・自己確認チェックリストを統一し、ブラウザの版付き`localStorage`を利用する。成績DB、ログイン、端末間同期は追加しない。スマートフォン・タブレットは閲覧・回答・簡単な自己確認まで保証し、実技はPCのCodespacesを使う。

Web最新版とCodespaces教材revisionが違う場合、管理者が版を揃えるまで演習をBLOCKEDとする。自動同期・上書きは禁止する。生SHAの受講者向け表示は廃止して内部検証を維持する。正確な表・SVG・必要な実画面・生成した模式図を組み合わせ、想像図を実UIの証拠にしない。公開許可リストと個人情報・評価用完成資料の除外を守る。

## 目的と対象

新課程M00〜M10の教材を、GitHubやCodespacesの起動前でも**公開Webページから閲覧**できるようにする。各モジュールの確認クイズは、**1問ずつ回答し、全問終了後に結果と解説を確認**できる形式とする。

**Webで表示する教材本文は今後新規制作する`docs/curriculum/ai-assisted-qa/modules/Mxx/README.md`等のMarkdownを正本とし、確認クイズ・正答・公開解説は今後新規制作する`docs/curriculum/ai-assisted-qa/quizzes/Mxx.json`を唯一の正本とする。**現存する旧課程`docs/curriculum/test-automation/`のMarkdown・104問を新課程の教材として利用・一括変換しない。公開Webは新規教材の閲覧・練習の入口とする。**現存する`docs/curriculum/ai-assisted-qa/README.md`は知識グラフの管理用説明であり、受講者の入口には使わない。** 受講者用の`start-here.md`を新たに作り、Webの新課程トップへ対応付ける。管理用READMEは既存参照とともに維持し、受講者向けナビゲーションからは外す。**Webクイズの点数は知識確認の参考であり、Level 2・フェーズの正式修了を自動判定しない**。実技、提出物、本人の根拠判断、評価者の確認は[評価Plan](./2026-10-16_qa-curriculum-ai-agent-redesign_assessment.md)に従う。

旧課程の`/docs/curriculum/`とその公開ページは維持する。新課程は独立した`/docs/curriculum/ai-assisted-qa/`配下に公開し、旧課程のURLや本文を置き換えない。**既存の公開カリキュラム入口からも新課程の入口を発見できるリンクを追加**し、受講者が直接URLを知らなくても到達できるようにする。旧課程Markdown本文を改変せず、生成ページ共通のヘッダー等の最小変更で実現する。

## 受講者が辿る導線

1. **入口（Web）**：新課程の目的、対象者、準備物、3フェーズ（Phase 3は選択）、M00〜M10の構成、Web閲覧とCodespaces実技の違い、費用・Secretへの注意を確認する。教材の閲覧と学習用クイズはGitHubログイン不要とする。実技開始時には本人のGitHubアカウントとCodespacesが必要なことを案内する。
2. **モジュール一覧（Web）**：フェーズ別に順序・学習目標・前提・実技の有無を示す。選択したモジュールの本文へ移動でき、先行モジュールや次のモジュールへ戻れる。Phase 1のみ／Phase 1＋2／Phase 3まで、受講範囲に合う終了地点と修了の意味を示す。
3. **モジュール本文（Web）**：最初に「何を学ぶか・前提・到達条件・必要な準備」を提示し、用語・手順・根拠付き完成例→誘導演習→本人の実技→確認クイズ→復習先の順に読める。正式仕様へのリンクはWeb版を優先し、必要なコード・Seed・Skillの参照も辿れるようにする。画面は目次・パンくず相当の戻り導線・前後のモジュール・現在地を示す。
4. **実技への移動**：Web上には受講者本人による`pnpm course:load Mxx`、Codespacesでの実行方法、作業フォルダ、提出物、戻る先を案内する。**WebボタンでCodespaces操作・課題ロード・AI実行を自動化しない**。教材本文はWebでも読めるが、Phase 1・2の実技は配布済みの学習用リポジトリで行う。公開Webの最新版と受講者の教材revisionが異なる場合に取り違えないよう、教材の版・参照先を表示し、受講中の教材を自動更新しない。
5. **確認クイズ（Web）**：各モジュールの本文から対応するクイズへ進み、結果を確認した後は間違えた学習項目の説明へ戻れる。次のモジュールへ進む操作は本人が行い、クイズの終了によって次の課題を自動ロードしない。
6. **フェーズ終了**：Web上に振り返りと正式な修了評価の案内を置く。M04/M07/M10の総合演習・公開評価資料・評価担当者による正式判定を、Webクイズの点数で代替しない。基本評価条件は公開してよい。評価時は追加の条件変更・質疑で本人判断を確認する。Phase 3未受講でもPhase 1・2の導線が完結する。

## クイズ画面と操作の契約

- **開始**：モジュールID・題名・問題数・取り組み方を確認して「開始する」。問題順は対応JSONの`questions`配列順とし、今回の範囲でランダム出題・制限時間・問題バンクを追加しない。
- **1問ずつ**：画面に`第n問／全N問`、設問・必要な条件・A〜Dの四択を1問だけ表示する。選択して「次へ」で進む。最初以外は「前へ」で戻って回答を変更できる。未回答で次へ進む／結果を確定する操作は防止し、何をすべきか分かるメッセージを表示する。
- **正答の表示時点**：途中では正答・得点・選択肢の解説を表示しない。最後の問題で全問回答を確認してから「結果を確認」を実行する。回答の変更は結果確定まで可能とする。
- **結果**：全問回答後に正答数／問題数、正答率、回答内容と正誤、問題ID・学習項目ID、正答、各選択肢の意味と正誤理由、根拠・復習先を確認できる。誤答だけを確認できる導線と、対象の教材節へ戻るリンクを用意する。誤答後は復習先から**別条件で再確認**できる手順を案内する。
- **再挑戦**：「最初からやり直す」を本人が選んだときだけ、そのモジュールの回答・結果をリセットする。他モジュールの状態と実技成果物は変更しない。復習・再挑戦で元の採点結果を正式修了に読み替えない。
- **中断・再開**：同じブラウザ・端末でページを再表示しても、そのモジュールの選択済み回答と現在位置を復元できるようにする。ブラウザ標準の`localStorage`にモジュールID・**ビルド時に対応クイズJSONのUTF-8バイト列から算出したSHA-256**・問題ID別の選択肢・進行位置・結果確定状態のみ保存する。**問題ID集合の一致のみでは版の一致と認めない**。公開の採点サーバーへ送信しない。保存が利用できない場合も回答・結果表示は成立させ、再開できない旨を案内する。版が異なれば古い回答を新版の結果へ自動流用せず、再開始を案内する。共用端末では保存データの削除方法を案内する。
- **アクセシビリティ**：ラジオボタンと関連付けた設問、キーボード操作、明確なフォーカス、現在問数・エラー・結果の読み上げ、画面幅に応じた配置、適切なコントラストを満たす。回答操作はポインタ限定にしない。通信断でも読み込み済みの問題の操作はでき、保存できなかった場合に架空の保存完了を表示しない。
- **異常時**：問題ゼロ件、問題/解答の不一致、同一ID、A〜D欠損、正答が0件または複数、復習リンク欠損を含む不正な教材はビルド時に拒否する。公開済みページで必要なデータ取得に失敗したときはエラーと再読み込み手段を示し、0点や全問不正解として扱わない。

## データ・公開・実装方針

- **一次情報（今後制作）**：[クイズPlan](./2026-10-16_qa-curriculum-ai-agent-redesign_quizzes.md)に従い、教材本文は`docs/curriculum/ai-assisted-qa/modules/Mxx/README.md`等のMarkdown、問題・A〜Dの選択肢・正答・全選択肢の意味と理由・根拠・復習先は`docs/curriculum/ai-assisted-qa/quizzes/Mxx.json`に新規作成する。**クイズJSONを唯一の問題正本**として静的クイズ画面を生成する。正答や解説の手編集Markdownを別に設けない。新課程のモジュール学習項目・教材節との関係は[知識グラフ完成仕様](./2026-10-16_qa-curriculum-ai-agent-redesign_knowledge-graph.md)と照合する。
- **既存基盤のみ再利用**：`scripts/docs/build-docs.ts`、`scripts/spec/markdown.ts`、`build:web`が公開中の旧課程`/docs/curriculum/`を生成している。**再利用対象は静的HTMLの生成・リンク解決・公開経路であり、旧課程の教材本文・クイズ・修了評価ではない。**そこに**新課程の独立URL群**と確認クイズ用の最小限のHTML/CSS/ブラウザJavaScriptを追加する。旧ナビゲーション・ビルド・公開Smokeを壊さない。新規Webアプリ、React画面の全面複製、CMS、認証、サーバーAPI、成績DB、学習管理サービス、外部の問題表示サービスは作らない。
- **公開データの範囲**：公開クイズの正答・解説と修了課題の模範解答・採点用テストはpublicなGit上で閲覧できる。模範・採点資料・完成状態は公開Webページ、Web Build、配布物へ含めない。この配布除外は秘密保持ではない。Web上ではクイズ結果確定後に解説を表示する。個人の提出物・評価結果・Secretは公開ビルドへ入れず、静的ページに認証情報・個人情報を埋め込まない。
- **URLの例**：入口`/docs/curriculum/ai-assisted-qa/`、モジュール`/docs/curriculum/ai-assisted-qa/modules/M03/`（最終的な静的HTMLの表記に合わせる）、確認クイズ`/docs/curriculum/ai-assisted-qa/quizzes/M03.html`。旧課程`/docs/curriculum/`とURLを衝突させない。
- **配布の扱い**：既存の管理者用許可リスト同期はMarkdown教材・未完成実技を配布する責務のままとし、Web閲覧は正本の公開ビルドが担当する。学習用Templateには教材MarkdownとクイズJSONを配布し、**Web画面が利用できない場合はJSONから生成した閲覧用Markdown（必要な場合）を読める**ようにする。生成Markdownは編集用の正本にせず、Codespacesの実技にWeb UIを必須としない。

## 実装手順と受入条件

1. 既存`scripts/docs/build-docs.ts`の旧課程生成・静的URL・仕様リンク・画像処理・公開Smokeを確認する。**新規制作する新課程用の教材・問題・公開解説**を入力として、新課程の教材ページとナビゲーションを追加する。**存在しないM00〜M10の実教材を完成として表示しない**。教材が揃ったモジュールから、前提・学習範囲・必要な実技が見えるようにする。
2. **新課程のモジュール別JSONを作り、そのデータ構造・A〜Dと正答・問題ID/学習目標ID・復習先・根拠を検証**して静的クイズ画面を生成する。公開学習用のクイズJSONのみ使い、`assessment/`配下の模範・採点・完成状態資料を読み込まない。破損・不足・複数正答・リンク切れ・問題ゼロ件をビルドで拒否する。JSONの内容ハッシュが変わった場合に旧回答を復元しないことも検証する。
3. 1問表示→回答→次/前→全問回答→結果→問題別解説→復習→再挑戦と、中断・再開／revision相違／保存不可の経路をブラウザで検証する。誤答しても「クイズ失敗＝正式修了不可」と機械判定しない。
4. ここでは全モジュール分の画面・リンク・案内を自動テスト、静的検証、コード/教材レビューで検証する。**実際のGit/プログラミング未経験者が講師の補足なしで辿れるかという実地試行は、全11モジュールと関連機能の実装完了後に行う**。その試行の実施・成功を全量制作や実装完了の条件にしない。
5. Desktopとスマートフォン幅、キーボード、画面リーダーでの基本導線、公開URL直アクセス、ビルドとデプロイ後のページ表示、旧課程の非回帰を確認する。クイズJSONの文字列・URLをDOMへ出力するときは`textContent`等の安全な方法を使用し、教材本文や問題文から任意のScriptを実行させない。`assessment/`配下の公開評価資料をWeb Bundle・公開Artifactから除外する契約をテストする。
6. **実装完了判定**：新課程11モジュールをWebで閲覧でき、対応する全クイズが一問ずつの回答・結果・復習まで動作し、ブラウザ再開・不正データ拒否を含む自動/契約/E2Eテスト、静的検証、ビルド、CIが通過すること。公開正本と学習者向け配布の境界、既存の旧課程Web、学習用同期/ロード、3フェーズの学習・修了評価を維持し、正式仕様との整合を確認する。代表教材は開発時のコード/教材レビューと自動検証を通過してから全量制作へ展開する。実際の受講者による導線試行は実装完了後の独立工程とする。

## 実装完了後の実地検証

全11モジュールと関連機能の実装完了後、実際の未経験受講者に、公開入口からPhase選択、教材閲覧、各クイズの回答・最終結果・解説・復習、Codespaces実技開始、成果物の保全/再開までを講師の補足なしで試してもらう。受講者が各画面と次の行動を見つけ、誤答時に根拠のある復習先へ戻れ、意図しない自動ロードやログイン要求に遭遇しないことを期待結果とする。迷子・説明不足・未学習の前提を記録する。

実装時のブラウザE2E、アクセシビリティ、公開URL、ビルド/CI検証は引き続き必須である。実地試行の未実施・不合格は実装工程のBLOCKED理由にせず、運用開始判断へ記録する。実地試行で実装要件に対する欠陥を発見した場合は、別の実装修正として扱い、関係する開発検証を再実行する。

## 除外すること

Web上でのPlaywright実行、Skillのリモート実行、CodespacesやGitHubリポジトリの自動作成、クイズのサーバー採点、アカウント別成績管理、講師向け成績ダッシュボード、受講者の正式修了の自動認定、旧課程の画面改修は本件に含めない。
