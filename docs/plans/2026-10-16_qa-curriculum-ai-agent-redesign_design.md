# 新規AI協働QAカリキュラム：学習目的と全体設計

## 卒業像

手動テスト経験がありプログラミング未経験でも受講できることを前提に、**初めて与えられたScenario Shopの機能・状態**について、正式仕様を読み、リスク・テスト条件を整理し、AIエージェントと協働してテストを設計・自動化・実行・改善し、変更の安全性とCI結果を自分で判断できる人材を育成する。

実装に使用する主な道具はOpenCode、`qa-workflow-skills`、Playwright、Git、GitHub Actions。目的はこれらのツールの操作方法を暗記することではなく、**道具を使って妥当なQA成果物を作り、検証できること**。AIモデルの名前や全Skillの網羅的な習熟、JavaScriptのすべての文法理解は卒業条件にしない。

## 卒業時の能力と評価の証拠

| 能力 | 到達条件 | 評価に必要な証拠 |
| --- | --- | --- |
| 仕様の理解 | BR/ACと画面の観測、既存コード、AIの推論を区別できる | 根拠の参照先、仕様違反・未確定の区別 |
| テスト分析 | リスク・条件・状態・優先順位と選定理由を説明できる | Scenario Shopの新しい条件を使った分析成果物 |
| テスト設計 | 適切な技法・期待結果・テスト層を選び、AIの案を検証できる | テストケース、仕様との対応、AI提案の採否理由 |
| Web自動化 | Locator、Assertion、Seed/Resetの意味を理解したPlaywrightテストを実行できる | 受講者が確認したコード差分、実行結果 |
| 失敗と保守 | 失敗の証拠から原因仮説を区別し、最小変更・再実行まで完了できる | 異なる実行のログ・Trace・差分、原因の説明 |
| 変更管理 | AIの変更を安全に確認し、PRとCIの対象commitを追跡できる | Git差分、PRレビュー、Run/Check/Artifact |
| AIの安全な利用 | 許可範囲とSecretを扱い、AIの自己申告を証拠の代わりにしない | 許可した操作・生成内容・未実行事項の記録 |

これらのうち用語・基本的な理解はクイズ、適用・判断と技能は実技で評価する。**すべての能力に知識と実技の両方が必要とは限らない**。詳細は[学習項目と理解水準](./2026-10-16_qa-curriculum-ai-agent-redesign_learning-map.md)、[評価基準](./2026-10-16_qa-curriculum-ai-agent-redesign_assessment.md)。

## 新課程の構成案

既存17レッスンを継承しない。以下の**M00〜M10の11モジュールは初期構成**である。学習項目と評価の棚卸しにより統合・分割できるが、後述の卒業能力を削らない。

| ID | モジュール | 必ず理解・実行すること | 主な評価 |
| --- | --- | --- | --- |
| M00 | 学習環境とAIの安全な利用 | 開発用コピー、OpenCode、Skillの利用経路、作業範囲、Secretと差分の扱い | 安全操作・環境の確認（環境障害は未達としない） |
| M01 | QAとテスト自動化の基礎 | 仕様、テスト階層、QA工程、自動化の価値と限界、人間とAIの分担 | 知識クイズ・判断課題 |
| M02 | 仕様とリスクの分析 | BR/AC、Role/State/Data、Seed、リスク・優先度、AI分析の検証 | 分析成果物・レビュー |
| M03 | テスト設計 | 同値分割、境界値、条件組合せ、状態遷移、ケースと期待結果 | 知識・事例クイズ、ケース設計 |
| M04 | テスト設計レビュー・自動化選定 | 欠落・重複・根拠不明のAI案、テスト層・費用・自動化適否 | AI生成案の採否理由 |
| M05 | Playwrightと最小TypeScript | `test`、`page`、`async/await`、Locator・Action・Assertion・待機 | コード読解・修正 |
| M06 | 自動テスト実装と実行 | Seed/Reset、テストの独立性、AIコードの差分、実行と証拠 | Web E2E実技 |
| M07 | 失敗分析と保守 | 失敗の帰属、Trace、再現、最小修正、Locator/Helper/POMの選択 | 診断・再実行と差分 |
| M08 | Git・GitHubとレビュー | 差分、branch、commit、PR、AIレビュー指摘の検証 | 受講者作業コピー上の変更・レビュー |
| M09 | GitHub Actionsと品質ゲート | Trigger、Job、実行範囲、Run/Check/Artifact、失敗時の調査 | 新課程専用のCI実習 |
| M10 | 総合演習 | 未演習の仕様条件を理解し、AI協働で分析→設計→Web自動化→実行→PR/CIへ通す | 最終実技・判断と知識の統合評価 |

**選択課程**：Native/Maestroは必要な前提を終えた受講者が別に選択できるものとする。共通11モジュールと同じ採点へ混ぜず、`optional/native/`にまとめる。Nativeを選ばなくても共通課程を卒業できる。iOS Runtimeは現在の保証範囲外であり必修化しない。

### 順序を選ぶ理由

- M00で作業の許可範囲・差分確認を学び、M02からAIによる分析を始める。学習者によるAIファイル編集はM00での安全操作を確認してから許可する。
- M02〜M04で「正しい期待結果」を確定してからM05〜M06の実装へ進む。コード先行で仕様を後付けしない。
- M06〜M07でテストの成功だけでなく、失敗・修復・変更の影響を経験する。
- M08〜M09で同じ受講者作成コードをGit・PR・CIへつなぐ。新たな題材を二重に実装させない。
- M10は前章で見た完成答案の再提出にしない。**未演習の条件**に対して転用できるかで修了を判断する。

## モジュール内に必ず備えるもの

各モジュールを「タイトルとハンズオン」だけで終わらせない。

1. 対象者・前提学習と、学習後にできる行動。
2. 習得する知識の一覧と、**説明・適用・判断の必要水準**。
3. 用語の説明・Scenario Shopからの具体例・誤りやすい点。
4. 問題IDと到達目標IDが対応した**選択式の確認クイズ**。解答後に参照する正答、全選択肢の説明、復習先。
5. 適用・判断・技能の確認が必要な項目には、受講者自身の**実技演習**。
6. 何を提出・確認すれば修了かを示す評価基準。未達時の復習・再確認方法。
7. 次のモジュールへの引継ぎ（ファイル/ID/必要な知識）。環境障害で進めない場合の扱い。

**知識の確認だけではQA工程を遂行できたことにはならない**。逆に説明を覚える必要がない実技を、無理に選択式だけで合否判定しない。

## 既存資産との関係

- 製品正本：`docs/spec/` と製品コード、Seed。新旧課程から参照してよい。教材都合で仕様を改変しない。
- 旧課程：`docs/curriculum/test-automation/`、`scripts/validate-curriculum.ts`、`scripts/training/check-completion.ts` は現行のまま維持する。
- 新課程：新しい到達目標・評価の正本は `ai-assisted-qa/` に置く。必要な検証は旧課程のvalidatorに足さず、別の軽量な検証として実装する。
- 実技：製品の`e2e/web/`や既存の`training/playwright/exercises/`を受講者の書き込み場所にしない。必要な場合だけ `training/ai-assisted-qa-course/`へ分け、既存helperを安全に参照する。
- Skill：`qa-workflow-skills` は依存する実在revisionを固定して検証する。単に`SKILL.md`をコピーしただけでSkillが動くとは扱わない。

## 未確定でよいものとCodexの責務

モジュール数は初期案。クイズの**必要問題数と合格率は、学習項目と問題の難易度を確定した後に決める**。実際の無料モデルの利用可否、動作するSkillの範囲、受講時間、最終演習が未演習として成立するかは実装・試行で検証する。

Codexには、この設計のもとで新課程の本文・問題と正答・実技と確認方法を実装させる。旧課程の修正、PR #198の変更、旧rubricへのC13追加は依頼しない。
