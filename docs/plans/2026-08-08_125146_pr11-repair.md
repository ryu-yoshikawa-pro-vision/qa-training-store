# PR #11 修正計画

## Goal

PR #11 の既存CIトポロジを維持したまま、Native変更検出の不足、Android Build Evidenceの重複保存、Runtime JobのJava暗黙依存、Contract TestとRun Artifactの不整合を修正する。

## Current understanding

- `.github/workflows/native-ci.yml` の `detect` は Native Static が参照する EAS設定・検証スクリプトを一部含んでいない。
- Android Buildは正式な `native-android-apk-${{ github.run_id }}` Artifactを保存した後、常にEvidenceへAPK本体をコピーしている。
- Android BuildはGradleログ全文を常にEvidenceへコピーしている。
- `android-runtime` はMaestro CLIを実行するが、Java 17のsetupがない。
- `tests/contracts/native-ci-workflow.test.ts` には、RuntimeのJava未setupを正とする契約と、`jobBlock("android-runtime")` による範囲過剰取得がある。
- `tests/contracts/ci-workflow.test.ts` のFormat/Markdown順序に対するテスト名が実装順序と逆である。
- 指定Current Run `20260808-111001-JST` には、無効なYAML検証コマンド、Sanitizer証跡不足、REPORTのPROJECT_CONTEXT記述矛盾、タスク分類の不整合が残っている。

## Assumptions

- Native変更検出には、明確にNative Jobの入力となる限定されたAndroid project path（`android/app/build.gradle`、`android/app/proguard-rules.pro`、`android/app/src/main/**`、`android/build.gradle`、`android/settings.gradle`、`android/gradle.properties`、`android/gradle/wrapper/**`、`android/gradlew`）、`scripts/validate-image-manifest.ts`、`public/images/products/**`、`public/images/placeholder.svg` も追加する。生成物を含む `android/**` や `public/images/**` は追加しない。
- Android Build Evidenceの成功判定は既存の `job.status` を使い、成功時はAPK metadataとGradle末尾200行、失敗時は存在するAPK本体とGradle全文を保存する。
- RuntimeのJava setupはAndroid Buildと同じTemurin 17を使用する。
- Current Runの `REPORT.md` はappend-onlyとし、既存記録を削除・改変せず訂正を末尾へ追記する。

## Non-goals

- CI topologyの再設計、Composite/Reusable Workflow化、Self-hosted runner導入。
- Application/Native production code、Maestro Flow、iOS Workflowの変更。
- Actions version更新、SHA pinning、Playwright cache導入。
- Branch作成、checkout/switch、merge/rebase、add/commit/push、PR更新、Remote CI実行。
- 過去Run Artifactの一括修正。

## Impacted areas

- Native変更検出の入力境界。
- Android Build ArtifactとEvidenceの保存境界、および失敗時診断保持。
- Android Runtimeの再現可能なJava実行環境。
- Workflow Contract Testの回帰防止契約。
- Current Runの作業履歴・検証証跡・Progress整合。

## Change strategy

1. Native Jobが直接・間接に検証する入力だけを `detect` のpathへ追加し、Contract Testで重要Pathを固定する。
2. Android Build Evidenceを成功／失敗で分岐し、正式APK Artifactは維持する。成功時APK本体をEvidenceへコピーせず、APK metadataのみを残す。Gradleログは成功時末尾200行、失敗時全文とする。
3. `android-runtime` にTemurin Java 17 setupを追加し、Node/pnpm/Gradle Buildを追加しない。Contract Testを反映する。
4. 軽微なContract Test名、RuntimeのJob block境界、計画書typoを修正する。
5. Current RunのTASKS/PLAN/run.jsonを今回の修正へ更新し、REPORTへ事実ベースの追記を行う。Workflow LevelはRepository規約を根拠にstandardを維持する。
6. focused/full Contract、markdown lint、lint、typecheck、format、可能ならverifyを実行し、最後にCurrent RunへSanitizer Write/Checkの正確なコマンドと結果を記録する。

## Risks

- Native detect pathを広げすぎると最適化効果を損なうため、Repository全体のglobは追加しない。
- 成功時ログ縮小で既存Evidence契約を壊さないよう、現行ContractとRuntime側の方針を確認する。
- WindowsのCRLFによりformat/既存Maestro契約が失敗する可能性があるため、失敗時はbaseline・実行条件・focused結果を記録する。
- Run ArtifactをSanitizerの前に更新すると、最終証跡自身が未サニタイズになるため、最終Write/Checkを完了直前に実行する。
