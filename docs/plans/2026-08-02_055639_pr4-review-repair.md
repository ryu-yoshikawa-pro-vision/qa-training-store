## 2. 現状理解と前提

- Current understanding:
  - Resetは`resetScenario`のtry内でDB reset、Notice操作、reloadを一括処理し、`ConfirmDialog`のConfirm後は即時closeするため、非同期中のConfirm無効化がない。
  - Product Previewの既存Variant Form値に`isActive`を正しく含めず、公開Issueは画像だけを判定し、Presentationが`messageKey`を直接表示している。
  - Flow Iは既存Processing URLへ直接移動する1テストで、既存Cross-roleも長い単一テストと簡略化されたFlow Jである。
  - Cartの`adjustedItemCount`は完全除外を含み、Reset Noticeの推奨Account/Route payloadはComponentで未表示である。
  - Homeのrole CTAがPrimary、Categoryが0件を除外せず、Guideに内部Property名が残っている。
  - Shipment表示、Last Active Adminエラー、Login後`getActive`のcatchがそれぞれ指摘どおり未分離である。
- Assumptions:
  - 既存のApplication Error Dictionary、Scenario Metadata、Test API、DTOの公開形状を優先し、新しい状態管理・Navigation Libraryは追加しない。
  - Route表示は既存Metadataの内部Pathのみを安全にLink化し、外部URL・不正Pathはテキスト表示または除外する。
  - 既存の長いCross-role lifecycle testはPhase 1契約を維持するため残し、新しい独立3テストを追加する。
- Non-goals:
  - 新機能、Seed契約の再設計、Shipment Domainへの状態追加、既存の全Dialogへの非同期管理導入。
  - テストの削除・Skip・弱体化、固定待機・無条件Retry、依存追加、Git操作。

## 5. 変更方針

- Change strategy:
  1. 11指摘を現行コード・既存テスト・直近Runと照合し、must_fix / already resolvedを確定する。
  2. 副作用境界と純粋表示変換を先に修正する（Reset、Preview、Shipment、Error、Cart、Notice）。
  3. Home/GuideとE2E構造を修正し、必要なUnit/Component/Integration/Repositoryテストを追加する。
  4. 差分に対する最小検証後、指定コマンドと4 viewport UI Reviewを実行する。
  5. Chrome Browser ClientのPlaywright-MCPで指定Flowを実動確認し、問題が出た場合のみ bounded repair iterationを行う。
- 実行タスク:
  - [ ] 1. 現行コード照合とRun初期化、findings triageを確定する
  - [ ] 2. Reset/Confirm、Preview、Error mapping、Shipment、Cart、Noticeを修正する

  - [ ] 4. Unit/Integration/Repository/Component/E2Eテストを追加・更新する

## 6. 検証方法

- Validation plan:
  - format、lint、typecheck、image manifest、security、unit、integration、repository、component、contracts、build。
  - Chromium list、Chromium E2E、a11y、mobile-boundary、cross-role、4 viewport UI Review。
  - Component: Reset連続Confirm/失敗/Notice保存失敗、Preview表示、Last Admin、Home/Guide、Checkout error。
  - Unit/Integration/Repository: Shipment mapping、Preview全SKU無効とDB不変、Cart集計、Checkout fallback。
