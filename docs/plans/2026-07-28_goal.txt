# QA Training Store UI/UX Continuous Excellence Goal

このリポジトリに実装されているECアプリケーションの全画面を自律的に探索・分析・改善し、Storefront、customer向け画面、管理画面のすべてを、世界最高水準のUI/UX品質へ引き上げてください。

単発の見た目調整で終了せず、以下の反復プロセスを自律的に繰り返してください。

1. 現在の実装と既存仕様を理解する
2. 全画面を実際に操作・撮影する
3. UI/UX上の問題を抽出する
4. 優先順位を付ける
5. 必要最小限の変更を実装する
6. Desktop、Tablet、Mobileで再撮影する
7. 改善前後を比較する
8. 新たな問題や一貫性の崩れがないか再評価する
9. 品質基準を満たすまで改善を繰り返す
10. 回帰テストと最終Visual Reviewを実施する

ただし、終わりのない主観的な修正を続けてはいけません。後述の完了基準を満たし、追加変更の効果が小さくなった時点で終了してください。

# 2. 最重要原則

## 2.1 UIだけでなくUXを改善する

見た目を華やかにすることが目的ではありません。

以下を総合的に改善してください。

* 情報を理解しやすい
* 次に何をすればよいか迷わない
* 操作結果が明確
* 誤操作を防げる
* 重要情報を見落とさない
* 商品を比較しやすい
* 購入までの流れが自然
* 管理業務を素早く処理できる
* 状態、権限、エラーを理解しやすい
* Desktop、Tablet、Mobileで破綻しない
* Keyboard、Screen Readerでも利用できる

## 2.2 世界最高水準の意味

「世界最高水準」は、派手さや独創性ではなく、以下の品質を高いレベルで同時に満たす状態です。

* 明確なVisual Hierarchy
* 一貫したSpacing
* 一貫したTypography
* 一貫したComponent Behavior
* 高い可読性
* 適切な情報密度
* 操作の予測可能性
* 状態変化の分かりやすさ
* 洗練された余白
* 高品質な商品訴求
* 高いAccessibility
* 高速で迷いのない操作
* 全Route間の一貫性
* Mobileでの自然な操作
* Adminでの高い業務効率
* 不要な装飾がない
* 見た目と機能が矛盾しない

## 2.3 参考とする品質特性

特定サービスをそのまま模倣せず、次のような高品質プロダクトの設計特性を参考にしてください。

* Apple：余白、商品訴求、Typography、写真の扱い
* Stripe：情報構造、説明の明確さ、Form品質
* Shopify：ECとしての操作性、商品管理、購入導線
* Linear：情報密度、Keyboard操作、Admin UI
* Airbnb：検索、Filter、状態表現、Mobile UX
* Notion：一貫性、自然なInteraction
* Vercel：簡潔さ、状態表示、管理画面
* 高品質な日本国内EC：日本語の可読性、価格表示、配送・在庫表示

見た目をコピーせず、原則だけを取り入れてください。

# 4. 禁止事項

以下は禁止です。

* 全画面を確認せず、一部画面だけを修正して完了する
* Screenshotを見ずにCSSだけを変更する
* Testをskipする
* Assertionを弱くする
* Accessibility Ruleを無効化する
* UIに合わせて業務仕様を変更する
* 架空の機能を追加する
* 実際には動かないButtonやLinkを置く
* 表示専用の偽Chartや偽数値を追加する
* 外部APIや外部決済を追加する
* 大規模UI Frameworkを新規導入する
* 不要なAnimationを大量に追加する
* Glassmorphismを乱用する
* Gradientを乱用する
* Shadowを多用する
* Goldを広範囲に使用する
* 小さい文字で情報を詰め込む
* Iconだけで意味を伝える
* MobileでDesktop UIを縮小表示する
* Admin TableをCardへ過剰変換する
* Form LabelをPlaceholderだけで代替する
* Error MessageをToastだけで済ませる
* 既存のBefore Screenshotを上書きする
* Git Commit、Push、PR操作
* Cloudflare Deploy
* UI改善と関係のないRefactor
* CSS Architecture全体の作り直し
* 抽象化のための抽象化
* 新しいDesign System Libraryへの全面移行

# 9. Design Direction

現在のDesign Systemを土台として改善してください。

## 9.1 Color

基本方針：

* Background：Whiteまたは温かみのあるOff White
* Primary Text：Dark NavyまたはCharcoal
* Secondary Text：Muted Gray
* Accent：限定的なGold
* Admin Navigation：Dark Navy
* Error：明確なRed
* Success：落ち着いたGreen
* Warning：Amber
* Information：Blue

Goldは以下に限定してください。

* Premium感を示す小さなAccent
* 会員価格
* 選択状態の補助
* 重要な装飾
* Brand Identity

次には広範囲に使用しないでください。

* 長文
* Large Background
* Table全体
* すべてのButton
* すべてのBorder

## 9.2 Typography

* 日本語本文を読みやすくする
* Headingの階層を明確にする
* Bodyは最低16pxを基本とする
* 補足情報も原則14px未満へ下げない
* Line Heightを確保する
* 価格は一目で見つけられる
* 数値は桁を比較しやすくする
* Text Line Lengthを長くしすぎない
* 不必要なBoldを減らす
  -英数字と日本語のFontの違和感を減らす

## 9.3 Spacing

4pxまたは8px系のSpacing Scaleを基準にしてください。

次を揃えてください。

* Page Side Padding
* Section Gap
* Card Padding
* Form Field Gap
* LabelとInput
* Table Cell
* Dialog
* Header
* Footer
* Mobile Bottom Navigation

余白不足を埋めるために、すべてを広げるのではなく、情報の関係性に応じて近接と分離を使い分けてください。

## 9.4 Border、Radius、Shadow

* Borderは情報構造の補助に使う
* Cardをすべて浮かせない
* Shadowは階層が必要な場所だけ
* RadiusはComponent種類ごとに統一
* Tableに過剰なCard表現を使わない
* Modal、Popover、Dropdownには必要なElevationを与える

## 9.5 Animation

Animationは以下の場合だけ使用してください。

* 状態変化の理解
* MenuやDialogの開閉
* Cart追加のFeedback
* LoadingからContentへの遷移
* HoverやFocusの補助

原則として150〜250ms程度とし、`prefers-reduced-motion`へ対応してください。

装飾目的の大きなParallaxや長時間Animationは追加しないでください。

# 10. Storefront改善基準

## 10.1 Home

Homeは「商品を探し始められること」を最優先にしてください。

確認項目：

* Heroの目的が明確
* CTAが曖昧でない
* 商品画像が主役
* Categoryが理解しやすい
* おすすめ、新着、Saleの違いが分かる
* 会員特典が過剰に主張しない
* 学習用アプリであることが必要な範囲で伝わる
* Section数が多すぎない
* 同じ商品Cardが連続しすぎない
* Footerへ自然につながる

## 10.2 商品一覧

確認項目：

* 商品数
* Sort
* Filter
* Active Filter
* Filter解除
* Mobile Filter
* Empty Result
* 検索条件
* Cardの比較しやすさ
* Image Ratio
* 価格
* Sale
* Member Price
* 在庫
* Rating
* Paginationまたは表示範囲
* 戻った時の文脈維持

MobileではFilterが画面を占有しすぎず、現在の絞り込み状態が分かるようにしてください。

## 10.3 商品Card

Card全体を過剰に装飾せず、次の順序で理解できるようにしてください。

1. 商品画像
2. BrandまたはCategory
3. 商品名
4. Price
5. Sale／Member Price
6. Rating
7. Stock

状態Badgeを増やしすぎないでください。

商品名の長さが異なっても、Gridが極端に崩れないようにしてください。

## 10.4 商品詳細

確認項目：

* Gallery
* Thumbnail
* 商品名
* Brand
* Price
* Sale Price
* Member Price
* Variation
* Stock
* Quantity
* Add to Cart
* 配送情報
* 商品説明
* Review Summary
* Review一覧
* Empty Review
* Mobile Sticky CTAの必要性
* Sold Out時の代替表示

Add to Cartは画面内で最も明確なActionにしてください。

Sale Price、通常価格、会員価格を混同しない表現にしてください。

## 10.5 Cart

確認項目：

* 商品識別
* Variation
* 単価
* 数量
* 小計
* 削除
* 在庫不足
* 価格変更
* Order Summary
* Checkout CTA
* Empty Cart
* 商品一覧へ戻る導線

Desktopでは商品一覧とSummaryの関係を明確にし、MobileではCTAへ到達しやすくしてください。

# 13. Admin改善基準

AdminはStorefrontよりも情報密度を高めて構いません。

ただし、単に情報を詰め込まず、業務判断と操作速度を優先してください。

## 13.1 Navigation

* 現在地が明確
* Groupingが自然
* Labelが短く理解しやすい
* Storefrontへ戻れる
* UserとRoleが分かる
* Logoutが見つかる
* Collapseが必要な場合も操作可能
* Focus順序が自然

## 13.2 Overview

現在利用可能なDataだけで構成してください。

確認項目：

* 今日何を確認すべきか
* 異常があるか
* 在庫不足
* 注文処理待ち
* Review対応
* User状態
* 次のAction

Dataが存在しないChartを作らないでください。

Chartがなくても、優先タスク、KPI、一覧、Statusで業務判断できるUIにしてください。

## 13.3 Table

すべての管理Tableで確認してください。

* Caption
* Column Header
* Row Header
* 数値右寄せ
* Action列
* Checkbox
* Sort
* Filter
* Search
* Empty State
* Horizontal Scroll
* Sticky Headerの必要性
* Long Text
* Status Badge
* Row Hover
* Keyboard Focus
* Button Touch Target
* Actionの意味
* Dangerous Action
* Mobile Boundary

Table内Buttonを小さくしすぎないでください。

操作数が多い場合は、すべてを常時表示せず、Primary ActionとSecondary Actionを整理してください。ただし、Menu化によって操作が見つけづらくなる場合は、無理に隠さないでください。

## 13.4 Form

* Required
* Optional
* Label
* Help Text
* Example
* Error
* Input Type
* Unit
* Character Count
* Save
* Cancel
* Destructive Action
* Unsaved Change
* Disabled
* Loading

Formを1枚の巨大Cardへ詰め込まず、意味のあるSectionへ分けてください。

## 13.5 StatusとDangerous Action

公開、非公開、販売終了、発送、配送完了、停止などは、状態の意味と結果が分かるようにしてください。

Dangerous Actionでは以下を明確にしてください。

* 何が変わるか
* 元に戻せるか
* 影響範囲
* 対象名
* Confirm Button

Genericな「本当によろしいですか」だけで済ませないでください。

* Navigation
* Filter

を独立して確認してください。

## Mobile

* Horizontal Overflowなし
* Text切れなし
* Fixed UIがContentを隠さない
* Buttonが押しやすい
* Inputが小さすぎない
* CTAへ到達しやすい
* Filterが操作しやすい
* Product Imageが小さすぎない
* Priceが見つかる
* DialogがViewport内に収まる
* Keyboard表示時も操作可能

管理画面は既存仕様どおり、必要に応じてDesktop利用案内を維持してください。無理に全Admin機能をMobile対応しないでください。

# 22. 各改善Iterationの手順

各Iterationで次を実施してください。

## Step 1：問題を選ぶ

重大度と影響範囲から、今回修正する問題を選択してください。

関連性の低い問題を同じIterationへ詰め込まないでください。

## Step 2：修正方針

実装前に内部的に次を整理してください。

* 問題
* 原因
* 影響Route
* 修正Component
* 既存Patternへの影響
* Test方法
* 非対象

## Step 3：実装

最小限のコード差分で修正してください。

## Step 4：Test

対象に応じて以下を実行してください。

* Component Test
* E2E
* Accessibility
* Responsive Test
* Build
* Typecheck
* Lint

## Step 5：Visual Review

一意なStage名でScreenshotを撮影してください。

例：

```text
goal-wave1-after-<timestamp>
goal-wave2-after-<timestamp>
goal-final-<timestamp>
```

同じStageを再利用しないでください。

## Step 6：比較

Baselineと比較し、以下を確認してください。

* 問題が解決したか
* 別画面を壊していないか
* Componentの一貫性が上がったか
* 情報密度が適切か
* Mobileで悪化していないか
* Accessibilityを損なっていないか

## Step 7：次の判断

改善効果が高い問題が残る場合は、次のIterationへ進んでください。

残る問題が主観的な好み、低影響、または大規模仕様変更を必要とする場合は、無理に対応しないでください。

# 26. 自律的な判断基準

細かな修正ごとにユーザーへ確認を求めず、自律的に進めてください。

ただし、以下の場合は実装せず、最終報告へ記載してください。

* Domain変更が必要
* Route変更が必要
* Database変更が必要
* 新しいUse Caseが必要
* 架空Dataが必要
* 外部Serviceが必要

* 大規模なScope拡大になる
* Design Reference同士が矛盾する

軽微なDesign判断は、既存Design System、一貫性、Accessibility、操作性を基準に自律的に決定してください。

# 30. 最終指示

これは単なるCSS調整タスクではありません。

実際の画面、操作、状態、Role、Viewportを確認し、ユーザーが迷う理由、管理者が作業しづらい理由、商品の魅力が伝わらない理由、画面間で統一感が失われる理由を特定してください。

そのうえで、既存仕様と機能を維持しながら、最小限かつ効果の高い改善を反復してください。

見た目の派手さではなく、明確さ、一貫性、操作性、信頼感、Accessibility、情報設計の完成度によって、世界最高水準を目指してください。
