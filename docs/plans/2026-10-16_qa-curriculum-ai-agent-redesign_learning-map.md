# 学習項目と到達目標の対応表

## 使い方と定義

この表は[カリキュラム設計](./2026-10-16_qa-curriculum-ai-agent-redesign_design.md)を、レッスン内の学習項目まで具体化した設計である。各行は、受講者が何を理解し、どの程度使える必要があるかを定義する。実装後は教材の説明、確認クイズ、演習、評価が**行ごとに追跡できる**ようにする。

- 「説明」：他の概念と区別し、自分の言葉で理由を説明できる。
- 「適用」：与えられたScenario Shopの条件で、該当する方法を使って正しい結果を導ける。
- 「判断」：根拠と制約を確認し、複数の選択肢から適切な方法を選び、採否の理由を示せる。
- 「共通」：全受講者が必要。「選択」：Native課程を履修した受講者のみ必要。「発展」：共通の合格要件に含めない。
- IDは学習項目との対応を記録する**教材内識別子**（例：`P1-03-K02`）。既存の`C01〜C13`、`TC-CART-`、`BR-/AC-`を変更・置換しない。質問IDもこのIDに紐付ける。

原則：**全行について最低1つの評価手段を用意する**。知識・判断を確認クイズで評価し、技能・判断の実行を伴う行は実技の合格観点でも評価する。説明だけの項目をむやみに実行テスト化しない。1問で複数の行を測る場合、各行に必要な判断が問題内で本当に求められていることを確認する。

## 学習項目と評価の確認方法

Codexが教材を実装するときは、次の欄を持つ**対応表を1つ**維持する。表の媒体は既存Markdownのままでよい。別DBやグラフは作らない。

| 欄 | 必須の意味 |
| --- | --- |
| 項目ID / レッスン | 上の行を一意に参照する |
| 到達水準 | 説明・適用・判断のいずれか。行によって必要なら両方 |
| 教材の該当節 | 学ぶための説明・コード・実例へのリンク |
| クイズID | 確認する知識と、その正答・解説の所在 |
| 演習・成果物 | 適用・判断能力を測る場合、対象の演習とTC/Receipt等 |
| 修了の判定 | 知識確認の結果、実技の観点、C01〜C13との関連 |
| 共通/選択/発展 | 共通の修了要件に混入させないための分類 |

**設計上の制約**：
- 題材のSKU/Seed値を教材のために複製しない。回答の根拠は正式仕様・本来のSSOTへ戻す。
- 1つのクイズ問題だけで実践技能やAIへの指示能力を習得したとは認定しない。
- 選択Nativeの学習項目を共通修了へ追加しない。
- 総合演習では前章の成果物を再利用し、新しい独立した完成テスト一式を要求しない。
