# 新課程の教材同期・モジュール単位ロード設計

## 目的と責務

**教材の正本は公開の`qa-training-store`に維持する。** 受講者がCodespacesで課題を進めるための**別の公開学習用リポジトリ**を用意し、配布対象だけを同期する。受講者自身がモジュールIDを指定して、そのモジュールの課題を作業領域へロードする。

処理の責務を分ける。

| 処理 | 実行者 | 入力 | 出力 | してはいけないこと |
| --- | --- | --- | --- | --- |
| **教材の同期** | 教材管理者 | `qa-training-store`の確定commit、配布許可リスト | 学習用リポジトリの教材・環境・ロードスクリプト | 無差別な全リポジトリ複製、解答・Secret・正式workflowの配布、無断push |
| **モジュールのロード** | **学習者本人** | 学習用リポジトリ内の配布済み教材、`M00`〜`M10`の1 ID | **指定した1モジュール**の作業フォルダ | 他モジュールの自動ロード、学習者の編集・過去成果物の上書き、同期先リポジトリの更新 |
| **課題の評価** | 学習者・講師等 | 学習者の成果物、公開評価基準、必要なら非公開評価資料 | フェーズ別の実技・知識・判断の判定 | AI自己申告だけの合格判定、配布物にある完成例の転記を技能と認定 |

### リポジトリ構成（実装案）

```text
qa-training-store/                                  # 公開・教材とScenario Shopの正本
  docs/curriculum/ai-assisted-qa/                    # 教材、学習用クイズ・解説
  training/ai-assisted-qa-course/                    # 課題素材・未完成spec
  training/course-sync/manifest.json                 # 配布対象を明示する許可リスト
  scripts/training/sync-ai-assisted-qa.ts            # 管理者用同期スクリプト

学習用リポジトリ/                                   # 新設予定・公開Template
  .devcontainer/                                     # Codespaces用
  course/modules/M00/ ... M10/                       # 配布済み教材（ロード前でも参照可能）
  course/manifest.json                               # 配布元commit・モジュール資産一覧
  scripts/load-module.ts                             # 学習者が実行するロードスクリプト
  runtime/ など                                      # Scenario Shopの実行に必要な配布物
  workspace/M00/ ...                                 # 学習者による作業成果（都度ロード）

非公開の評価資料保存先/                              # 保存手段は別途確定
  Phase 1/2/3 の修了課題用模範解答・必要な評価用テスト
```

非公開保存先は**今回のPlanでは新しいGitHubリポジトリの作成を必須としない**。アクセス制限された既存の保存先でもよい。ただし、非公開の修了解答・評価用テストを`qa-training-store`や学習用リポジトリの公開commit・branch・履歴へ投入しない。

## 知識グラフとの境界

教材・理解事項・Skillの変更影響は[基準グラフ](../curriculum/ai-assisted-qa/README.md)で管理する。グラフは**学習用Templateへの配布許可リストではない**。`training/course-sync/manifest.json`が実際の同期範囲を決定する。

**基準グラフ全件や運用用CLIは学習者へ自動同期しない。** 必要な教材・モジュール向けの参照情報だけを管理者が許可リストへ明示する。Skillの正本は別リポジトリ`ryu-yoshikawa-pro-vision/qa-workflow-skills/skills/`であり、ローダーが公開元の別Skillを自動収集しない。非公開修了解答や評価用テストをグラフ・配布物へ含めない。

## 管理者による教材同期

実装予定のコマンド例：

```sh
pnpm course:sync --source-sha <40文字の確定SHA> --target ../ai-assisted-qa-learner
```

- `training/course-sync/manifest.json`を**配布許可リスト**の正本とする。共通の実行環境・依存ファイル、各モジュールの教材・課題・必要な仕様断片、ロード用スクリプトとその補助ファイルを**必要な範囲で明示**する。ファイル対応先とモジュール帰属を追える構造にする。配布元のcommit SHAを記録する。
- 同期処理は**実在する固定SHAの内容**を対象とし、意図しない未commit変更を混ぜない。存在しないファイル・意図しない配布範囲・禁止パス・シンボリックリンクによる領域逸脱を検出した場合は停止する。
- 許可リストに載せないもの：修了課題の解答・模範コード・非公開評価用テスト、旧教材の完成済み回答や不要な完成spec、`.env`、認証情報、`.git/`、開発用の不要なworkflow、ビルド成果物、`node_modules/`、元リポジトリのPlan全文。
- クイズは学習時に解説を参照できる教材として扱う。一方、**実技・修了課題の完成解答は配布しない**。学習用クイズの正答が公開されていることと、修了課題の答えを学習者から隠すことを混同しない。公開正答へのリンクを残す場合、AIが参照する可能性も明示する。
- 同期先への変更は管理者が差分を確認して適用する。**スクリプトはcommit・push・公開設定変更を自動で行わない**。同期先に存在する学習者の`workspace/`・提出物を削除・上書きしない。公開Templateの更新は管理者が行い、既存の受講者個人リポジトリへ自動同期しない。
- 正本に重複する教材を手で保守しない。`training/course-sync/`には設定・契約テスト等を置き、配布物はスクリプトで生成する。全面クローンや旧`prepare-training-copy.ts`の結果をそのまま公開しない。

## 学習者によるモジュール単位ロード

実装予定のコマンド例：

```sh
pnpm course:load M03
```

1. 初回のM00ロードには**モジュールとは別の受講開始ガイド**を用意し、ターミナルやpnpmの意味をまだ知らない受講者でも、画面上の位置を確認してコマンドをコピー・実行できるようにする。これは修了評価ではない。学習者は自分の学習用リポジトリの**2コアCodespace**で実行する。IDは`M00`〜`M10`のうち**1つだけ**を受け付け、フェーズ全体の一括ロード・自動進行は行わない。
2. ローダーは配布済みの`course/manifest.json`から**指定IDのファイルだけ**を読み、`workspace/M03/`など所定の作業場所に課題文、入力資料、未完成ファイル、テンプレートを準備する。共通ランタイムは起動環境の一部として別管理し、モジュールごとにコピーし直さない。
3. **以前のモジュールの成果物は維持**する。M03が必要とするM02の成果物は明示的な参照で読み取る。未作成なら必要な前提を示すが、M02を勝手にロードしたり、模範成果物で穴埋めしたりしない。
4. 同じモジュールを再ロードしたとき、既存の編集済みファイルを**上書き・削除しない**。未変更のファイルはそのままにし、差分があれば停止して学習者へ知らせる。復元を行う場合も、明示操作とバックアップを必要とする。
5. 配布版のsource SHA、モジュールID、ロード時刻（ローカルで得られる場合）、配置したファイル一覧を学習者側の記録へ残す。個人Secret・全AI会話・不要な認証情報は記録しない。
6. ローダーは自分のリポジトリ内の配布済みファイルだけを扱う。**Git認証・`clone`・APIアクセス・ネットワーク接続・PR作成・GitHub Actions実行をPhase 1/2のロード要件にしない**。
7. コマンドを手入力する操作は**学習者の意思決定**とし、AIエージェントが先回りして次のモジュールをロードすることを正式な導線・評価としない。

**注意：配布済みの`course/modules/`は、ロード前でも学習用リポジトリに存在する。ロードは作業開始と上書き防止の操作であり、AIから未ロード教材を秘密にするアクセス制御ではない。** 未ロード教材もAIが参照し得るため、隠す必要がある評価資料は**そもそも公開・配布しない**。

## Scenario Shopを別リポジトリから利用する

Phase 2を成立させるには、学習用リポジトリのCodespacesから**実際にScenario Shopを起動し、Seed/Resetを行ってPlaywrightを実行できること**が必要である。教材だけを同期しても不十分。

- `qa-training-store`にある製品・仕様・Seed/Resetを正本として維持する。配布先に入れる製品関連ファイルは**学習用ランタイムとして生成するコピー**であり、二重に開発・保守する正本にはしない。
- 同期許可リストへ、Build/Serve/Testに必要な依存・設定・静的ファイル・Seed/Resetの最小一式を含める。正本のcommit SHAから生成し、不要な本番workflow・正式回帰spec・模範実装を配布しない。**具体的なファイル一覧は実際のimportと起動経路を調べて確定**する。
- 元の`playwright.training.config.ts`をそのまま移植できるとは仮定しない。**8082のTraining用テストサーバー、8081の通常Web、6080のnoVNC**が別リポジトリでも成立するよう、新課程専用Configと起動コマンドで検証する。必要なPlaywright helperだけを配布可能な形で参照する。
- 既存devcontainerの必要部分を新リポジトリへ再利用するが、`package.json`・`pnpm-lock.yaml`・Playwright Configと実際の依存に不整合がないことを確認する。**2コアCodespaceで初回導入・アプリ起動・Reset・1本のE2Eを通す**まで検証する。失敗する場合は、同期済みと宣言しない。
- 公開Templateが元リポジトリのコードを含む以上、正式仕様・既存実装そのものは学習者とAIに見える。それでも**評価用の模範テストコード・完成した実技回答を入れない**ことで転記リスクを減らす。

## Phase 3の学習

Phase 1・2と同じ**学習者個人のリポジトリ**を継続利用する。ここで初めてbranch・commit・PR・GitHub Actionsを教材で扱い、Phase 2の成果物を対象とした専用CIを実行する。旧Training Copy生成処理は元リポジトリを丸ごと複製し、旧workflowを有効にするため、この同期・ロードには流用しない。新課程の実行範囲を明示した小さなworkflowと検証契約を用いる。

公開リポジトリであるため、受講者自身の実技・ログ・個人情報を公開commitへ入れる前に確認させる。Phase 1・2の`workspace/`は原則としてGit管理対象から除外し、Phase 3で提出対象としたコード・記録だけを意図的にcommitする手順を用意する。

## 必須の検証と未確定事項

| 検証 | 合格条件 |
| --- | --- |
| 同期対象の正しさ | manifestで許可したファイルだけを同期。禁止した解答・認証情報・正式workflow・正式回帰specを除外。配布元SHAを記録 |
| 同期の再実行 | 同じSHAなら同じ配布内容となり、同期先の受講者成果物を壊さない。意図せぬ差分・欠落は失敗 |
| モジュールID | M00〜M10の**1 IDだけ**を受け付ける。未知ID・複数ID・危険なパスは拒否 |
| ロードの再実行 | 同じIDを再ロードしても既存の編集・成果物を上書きせず、他モジュールへ影響しない |
| 学習者の操作 | **受講開始ガイドで**M00をロードするだけならGit・GitHub API・CIの操作を必要としない。M00前にターミナル・pnpmの知識を問わない。AIの自動進行を要求しない |
| 解答の混入防止 | 完成済み実技spec・修了課題の模範解答が公開学習用リポジトリの配布物・履歴に存在しない |
| Phase 1の実施 | ロードした仕様・Skillから分析・設計を行い、完成例の転記なしに独立修了できる |
| Phase 2の実施 | **学習用リポジトリ単体**の2コアCodespaceでSetup→Build/Serve→Seed/Reset→Playwright→結果確認できる |
| Phase 3の実施 | 学習用リポジトリの明示したコードだけをPR/CIで実行し、旧・正式workflowを発火させない |
| 無料運用 | 2コア・無料AIモデル・公開標準Runnerで条件を確認。超過・利用不能はBLOCKEDにし自動課金しない |

**未確定**：新しい学習用リポジトリの実際の名称・作成、Runtime同期のファイル一覧、出力先の最終命名、非公開評価資料の保存先、外部Skillの配布・実行と2コアCodespacesでの学習経路、Codespaces無料枠内での完走。**OpenCode Zen無料モデルの利用可否・認証可否は確認済みであり、再検証対象ではない。**残る検証事項については設計の完成条件を変えず、実際の依存経路と動作証拠で充足させる。

**このPlanの完成条件には、教材の同期・ロードスクリプト、学習用リポジトリとScenario Shopの動作確認まで含める。** 今回のPlan更新では、新規GitHubリポジトリの作成、教材同期・ロードの実装と実行、学習用リポジトリへのpush、mergeは行わない。
