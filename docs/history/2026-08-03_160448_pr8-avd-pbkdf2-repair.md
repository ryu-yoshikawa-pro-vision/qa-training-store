# PR #8 AVD永続化・PBKDF2契約修正履歴

## 対象

- Head: `50411a63e643000a024d929b8869b240936ef56e`
- Native CI Run: `30787501472`
- Android失敗Job: `Android Build / Emulator / Maestro`、Step `Start Android Emulator with KVM`

## 原因確認

SDK導入、Release APK生成、Bundle確認までは成功していた。AVD作成時に保存先を明示していなかったため、`avdmanager create avd`がCustom hardware profile入力待ちとなり、180秒後に終了コード124で停止していた。`avdmanager`の`-p`はAVD保存先を指定し、Emulatorは`ANDROID_AVD_HOME`を優先してAVDを探索するため、作成と起動のPathを同一に固定した。

参照した公式資料:

- [avdmanager command-line tool](https://developer.android.com/tools/avdmanager)
- [Android Studio command-line variables](https://developer.android.com/tools/variables)

## 実装

- `.github/workflows/native-ci.yml`
  - `ANDROID_AVD_HOME=$RUNNER_TEMP/android-avd`を作成、export、`GITHUB_ENV`へ保存。
  - `avdmanager -p`、API 34／`google_apis;x86_64`、固定device profileを使用。
  - AVD filesと`emulator -list-avds`の完全一致をEmulator起動前に検査。
  - Emulator PIDを保存し、ADB／boot／package service待機中に早期終了を検知。
  - SDK／ABI、`sys.boot_completed`、package／process、dumpsys、logcat、APK、Maestro、Contract SignalのEvidenceを失敗時も回収。
- `src/test-controls/native-contract-harness.native.ts`
  - Application DB不変確認とPBKDF2確認をCleanup前に実行し、全Cleanup成功後だけ成功Signalを通知。
  - `checks.passwordHashing`を追加。
- `src/test-controls/native-contract-harness-runner.native.ts`
  - seed userの`password_hash`を読み、`NativePbkdf2PasswordHasher`で固定password、誤password、Unicode passwordの正誤を検証。
  - password／hash値をログへ出さない。
- `tests/contracts/native-ci-workflow.test.ts`、`tests/contracts/native-contract-harness.test.ts`、`tests/unit/native-contract-harness.test.ts`、`tests/component/native/native-password-hasher.test.ts`
  - Path、処理順序、PID／boot、Signal、PBKDF2の契約を固定。
