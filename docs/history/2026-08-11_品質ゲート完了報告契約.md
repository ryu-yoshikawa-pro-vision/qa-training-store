# 品質ゲート完了報告契約

日付: 2026-08-11

## 変更理由

CIの`expo-doctor`がExpo SDKのpatch version不整合で失敗した。今回の修正を契機に、品質ゲートを省略した完了報告や、直接範囲外に見えるFailureの未調査を防ぐ運用をLiving Documentationへ追記した。

## 現行契約

- 完了報告前に、リポジトリで定義された全品質ゲートとテストを実行する。通常のローカル入口は`pnpm run verify`であり、変更パスに応じたCI専用・追加ゲートも実行対象とする。
- いずれかのゲートが失敗した場合は、Baseline、差分、共有依存、CI／テスト契約、環境を調査する。現在の変更が原因である、または正しい検証に必要なら、作業範囲を最小限拡張して修正する。
- 真に無関係、環境依存、unsafe、または要件判断が必要なFailureだけを保留できる。その場合も、根拠、未実行検証、残差、次の対応者・アクションをRun Artifactとユーザー向け報告へ残し、未実行をPASS扱いしない。

## 今回の適用

Expo SDK 57の7件のpatch mismatchと`expo-constants` overrideを更新し、lockfileを再生成した。更新後の`expo-doctor`依存チェックは17/17 PASSとなった。Windowsのローカル未追跡`.npmrc`がnpm warningをstderrへ出すため、通常実行ではdoctorがそのwarningをFailureとして扱うが、CI checkoutには当該ignored fileが含まれない。`npm_config_loglevel=error`を設定したCI相当実行でdoctor全17チェックPASSを確認し、環境固有warningとしてRun Artifactへ記録する。
